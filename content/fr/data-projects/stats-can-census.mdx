# Exploiter les données du recensement 🇨🇦

Bienvenue dans ce nouveau projet ! Nous allons explorer l'immense quantité d'informations du recensement canadien fournies par Statistique Canada. Pour traiter ces données, nous utiliserons la librairie Simple Data Analysis (SDA), que j'ai créée ([donnez-lui une étoile ⭐](https://github.com/nshiab/simple-data-analysis)).

Pour chaque région métropolitaine, nous créerons une carte montrant les aires où le revenu des ménages est inférieur ou supérieur à la médiane. La carte de Montréal ci-dessous montre le résultat que nous obtiendrons ensemble.

![Une carte de Montréal montrant comment le revenu médian des ménages varie entre les aires de diffusion.](/assets/stats-can-census/montreal-final-map.png)

Dans ce projet concret, je vous montrerai des techniques avancées pour traiter de grands ensembles de données avec TypeScript. Les données du recensement de 2021 pèsent environ 30 Go, mais il vous faudra environ 70 Go d'espace libre sur votre disque dur. C'est le moment de faire du ménage ! 🧹

## Quelle est la question ?

Pour ne pas perdre le fil, définissons la question à laquelle nous voulons répondre :
- Pour chaque région métropolitaine canadienne, quelles aires de diffusion ont un revenu des ménages supérieur ou inférieur à la médiane ?

Voici comment le recensement définit les régions métropolitaines :

> Une région métropolitaine de recensement (RMR) est formée d'une ou de plusieurs municipalités adjacentes centrées sur un centre de population (appelé le noyau). Une RMR doit compter au moins 100 000 habitants, dont au moins 50 000 vivent dans le noyau.

Et voici la définition des aires de diffusion :

> Une aire de diffusion (AD) est une petite unité géographique relativement stable dont la population moyenne est de 400 à 700 personnes. C'est la plus petite région géographique normalisée pour laquelle toutes les données du recensement sont diffusées. Les AD couvrent tout le territoire canadien.

Passons au code !

Pour tout configurer, utilisons [setup-data-project](https://github.com/nshiab/setup-data-project), comme dans les leçons précédentes.

Créez un nouveau dossier, ouvrez-le dans VS Code et exécutez : `deno -A jsr:@nshiab/setup-data-project`

Quand le programme vous le demande, utilisez la barre d'espace pour sélectionner `simple-data-analysis`, puis appuyez sur `Entrée`. Plot est installé automatiquement avec SDA.

## Téléchargement des données

Pour télécharger les données du recensement avec le plus de détails possible, rendez-vous sur cette [page de Statistique Canada](https://www12.statcan.gc.ca/census-recensement/2021/dp-pd/prof/details/download-telecharger.cfm?Lang=E).

Ouvrez le premier volet *Comprehensive download file*, puis cliquez sur le bouton *CSV* de *Canada, provinces, territories, census divisions (CDs), census subdivisions (CSDs), and dissemination areas (DAs)*.

Si vous ne le trouvez pas, voici le [lien direct](https://www12.statcan.gc.ca/census-recensement/2021/dp-pd/prof/details/download-telecharger/comp/GetFile.cfm?Lang=E&FILETYPE=CSV&GEONO=006). Vous téléchargerez un fichier ZIP de 2,25 Go.

![Une capture d'écran du site de Statistique Canada pour télécharger les données du recensement.](/assets/stats-can-census/stats-can-census-download.png)

Puisque nous voulons travailler sur les régions métropolitaines, il nous faut aussi leur nom pour chaque aire de diffusion.

Statistique Canada fournit cette information dans le [Fichier des attributs géographiques de 2021](https://www150.statcan.gc.ca/n1/pub/92-151-g/92-151-g2021001-eng.htm). Téléchargez-le à partir de ce [lien direct de Statistique Canada](https://www12.statcan.gc.ca/census-recensement/2021/geo/aip-pia/attribute-attribs/files-fichiers/2021_92-151_X.zip). Il s'agit d'un fichier ZIP de 9,8 Mo nommé `2021_92-151_X.zip`.

![Une capture d'écran du site de Statistique Canada pour télécharger les noms des régions métropolitaines.](/assets/stats-can-census/stats-can-names-download.png)

Enfin, pour créer une carte, nous avons besoin des frontières géospatiales des aires de diffusion. Vous les trouverez [ici](https://www12.statcan.gc.ca/census-recensement/2021/geo/sip-pis/boundary-limites/index2021-eng.cfm?year=21).

Ouvrez le volet *Statistical boundaries* et sélectionnez *Dissemination areas*. Dans la section *Format*, choisissez *Shapefile*, puis cliquez sur *Continue* au bas de la page.

Si vous ne le trouvez pas, voici le [lien direct](https://www12.statcan.gc.ca/census-recensement/2021/geo/sip-pis/boundary-limites/files-fichiers/lda_000b21a_e.zip) pour télécharger le fichier. Il pèse environ 197 Mo.

![Une capture d'écran du site de Statistique Canada pour télécharger les frontières des aires de diffusion.](/assets/stats-can-census/stats-can-boundaries-download.png)

Déplacez tous ces fichiers dans le dossier `data` de votre projet et décompressez tout, sauf les frontières géospatiales du fichier `lda_000b21a_e.zip` !

Pour décompresser les fichiers, ouvrez votre dossier en dehors de VS Code, par exemple dans Finder ou l'Explorateur de fichiers. Vous pourriez avoir besoin d'un logiciel comme WinZip ou 7-Zip. Une fois les fichiers décompressés, supprimez les deux fichiers `.zip` d'origine de votre projet et du dossier Téléchargements, sans oublier de vider la corbeille ! 🗑️ L'espace disque est précieux avec les grands ensembles de données.

Surprise ! Vous avez maintenant plus de 27 Go de données à traiter. 😅

## Les données du recensement

### Charger seulement ce dont nous avons besoin

En décompressant les données du recensement, nous avons obtenu un dossier contenant plusieurs fichiers. Les données se trouvent dans ceux dont le nom contient `_data_`.

Essayons de charger les 1 000 premières lignes du premier fichier, qui couvre les provinces de l'Atlantique. Ces fichiers sont très volumineux. Nous utiliserons donc l'option `limit` pour explorer un échantillon.

```ts showLineNumbers filename="main.ts"
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB();

await sdb
  .newTable("census")
  .loadData(
    "sda/data/98-401-X2021006_eng_CSV/98-401-X2021006_English_CSV_data_Atlantic.csv",
    { limit: 1000 },
  ).log();

await sdb.close();
```

Hum... Il y a un problème. Cette erreur signifie que les données n'utilisent pas l'encodage `UTF-8`, devenu la norme aujourd'hui.

![Une capture d'écran de VS Code montrant une erreur de caractères Unicode invalides.](/assets/stats-can-census/encoding-error.png)

J'ai demandé à Statistique Canada quel encodage était utilisé. On m'a répondu qu'il s'agissait de [`Windows-1252`](https://en.wikipedia.org/wiki/Windows-1252). Heureusement, SDA offre une option `encoding`. Nous pouvons utiliser `cp1252` pour désigner cet encodage, et SDA convertira automatiquement les données en `UTF-8` en arrière-plan.

Mettez votre code à jour avec l'exemple ci-dessous et enregistrez le fichier (`COMMAND` + `S` sur Mac ou `CTRL` + `S` sur Windows). Les 1 000 premières lignes devraient maintenant apparaître.

```ts showLineNumbers filename="main.ts" {9}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB();

await sdb
  .newTable("census")
  .loadData(
    "sda/data/98-401-X2021006_eng_CSV/98-401-X2021006_English_CSV_data_Atlantic.csv",
    { limit: 1000, encoding: "cp1252" },
  ).log();

await sdb.close();
```

Génial, ça fonctionne ! 🥳

![Une capture d'écran de VS Code montrant les données des provinces de l'Atlantique.](/assets/stats-can-census/atlantic-data.png)
<Callout type="info" emoji="💡">
    Si le tableau s'affiche bizarrement dans votre terminal, c'est parce qu'il est plus large que celui-ci. Faites un clic droit dans le terminal et cherchez `Toggle size with content width`. J'utilise aussi souvent le raccourci `OPTION` + `Z` sur Mac ou `ALT` + `Z` sur PC.
</Callout>

Notre table contient beaucoup de colonnes, mais nous n'en avons besoin que de quatre dans le fichier CSV :

- `GEO_LEVEL` : le type de région géographique représentée par la ligne.
- `CHARACTERISTIC_ID` : la variable du recensement représentée par la ligne.
- `DGUID` : l'identifiant géographique unique que nous utiliserons pour joindre les données.
- `C1_COUNT_TOTAL` : la valeur de la variable du recensement.

Nous pouvons utiliser l'option `columns` pour ne charger que ces quatre colonnes. Notre table reste ainsi ciblée et nous évitons de conserver des colonnes inutiles en mémoire. Avec des fichiers `UTF-8`, choisir les colonnes à l'avance peut aussi accélérer considérablement le chargement. Ici, SDA doit quand même convertir les données de `Windows-1252` en `UTF-8`, ce qui prend la majeure partie du temps de traitement.

```ts showLineNumbers filename="main.ts" {12}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB();

await sdb
  .newTable("census")
  .loadData(
    "sda/data/98-401-X2021006_eng_CSV/98-401-X2021006_English_CSV_data_Atlantic.csv",
    {
      limit: 1000,
      encoding: "cp1252",
      columns: ["GEO_LEVEL", "CHARACTERISTIC_ID", "DGUID", "C1_COUNT_TOTAL"],
    },
  ).log();

await sdb.close();
```

![Une capture d'écran de VS Code montrant les quatre colonnes du recensement.](/assets/stats-can-census/census-columns.png)

La colonne `GEO_LEVEL` affiche actuellement des lignes pour le pays. C'est parce que le fichier téléchargé contient *le Canada, les provinces, les territoires, les divisions de recensement, les subdivisions de recensement et les aires de diffusion*, alors que nous n'avons besoin que des aires de diffusion.

Nous pouvons utiliser l'option `conditions` pour ne garder que les lignes des aires de diffusion. Avec des fichiers `UTF-8`, filtrer pendant le chargement peut améliorer considérablement les performances. La conversion de l'encodage limite cet avantage ici, mais passer `columns` et `conditions` à `loadData` reste pratique : nous obtenons exactement les données voulues sans ajouter d'étapes de sélection et de filtrage par la suite.

```ts showLineNumbers filename="main.ts" {13}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB();

await sdb
  .newTable("census")
  .loadData(
    "sda/data/98-401-X2021006_eng_CSV/98-401-X2021006_English_CSV_data_Atlantic.csv",
    {
      limit: 1000,
      encoding: "cp1252",
      columns: ["GEO_LEVEL", "CHARACTERISTIC_ID", "DGUID", "C1_COUNT_TOTAL"],
      conditions: `GEO_LEVEL = 'Dissemination area'`,
    },
  ).log();

await sdb.close();
```

![Une capture d'écran de VS Code montrant seulement les lignes des aires de diffusion.](/assets/stats-can-census/census-condition.png)

Nous pouvons maintenant retirer l'option `limit` et charger toutes les données du fichier CSV de l'Atlantique. Avant cela, utilisons la méthode `cache`.

Au premier lancement, `cache` exécute le code que nous lui passons et enregistre la table obtenue dans un nouveau dossier `.sda-cache`. Aux lancements suivants, si le code n'a pas changé, SDA charge le résultat directement depuis le cache au lieu de relire le fichier d'origine, de convertir son encodage, de sélectionner ses colonnes et de filtrer ses lignes. C'est beaucoup plus rapide.

```ts showLineNumbers filename="main.ts" {6-15}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB({ cacheVerbose: true });

const census = sdb.newTable("census");
await census.cache(() => {
  census.loadData(
    "sda/data/98-401-X2021006_eng_CSV/98-401-X2021006_English_CSV_data_Atlantic.csv",
    {
      encoding: "cp1252",
      columns: ["GEO_LEVEL", "CHARACTERISTIC_ID", "DGUID", "C1_COUNT_TOTAL"],
      conditions: `GEO_LEVEL = 'Dissemination area'`,
    },
  );
});
await census.log();

await sdb.close();
```

Sur mon ordinateur, ce premier chargement a pris environ une minute et créé le dossier `.sda-cache`. Pas mal pour près de 12 millions de lignes ! 👏

![Une capture d'écran de VS Code montrant le premier chargement et le nouveau dossier de cache.](/assets/stats-can-census/atlantic-cache-first-run.png)

Enregistrez `main.ts` de nouveau sans modifier le code à l'intérieur de `cache` (`COMMAND` + `S` sur Mac ou `CTRL` + `S` sur Windows). SDA chargera les données directement depuis `.sda-cache`. Sur mon ordinateur, cela n'a pris que 69 millisecondes, soit environ 910 fois plus rapide. Voilà toute la beauté du cache ! ⚡

![Une capture d'écran de VS Code chargeant les données du recensement depuis le cache.](/assets/stats-can-census/atlantic-cache-hit.png)

### Filtrer les variables du recensement

Rafraîchissons-nous la mémoire. Notre question est la suivante :
- Pour chaque région métropolitaine canadienne, quelles aires de diffusion ont un revenu des ménages supérieur ou inférieur à la médiane ?

Pour trouver la variable du revenu total des ménages, ouvrez `98-401-X2021006_English_meta.txt` dans le dossier des données du recensement. Ce fichier répertorie toutes les variables et indique que `CHARACTERISTIC_ID` vaut `243` pour `Median total income of household in 2020 ($)`.

Dans la capture d'écran ci-dessous, j'ai utilisé la recherche pour le trouver rapidement (`COMMAND` + `F` sur Mac ou `CTRL` + `F` sur Windows).

![Une capture d'écran de VS Code montrant le code de la variable du revenu total.](/assets/stats-can-census/income-code.png)

Nous pouvons utiliser `keepValues` pour ne sélectionner que les lignes où `CHARACTERISTIC_ID` vaut `243`.

⚠️ Ajoutez bien `keepValues` après la méthode `cache`, comme ci-dessous. Si vous modifiez le code à l'intérieur de `cache`, SDA réexécutera tout le bloc et rechargera les données d'origine. Une fois les 152 millions de lignes chargées depuis le cache, SDA les réduit très vite à environ 57 000 lignes. Nous n'avons donc pas besoin de mettre cette étape en cache.

```ts showLineNumbers filename="main.ts" {16-18}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB({ cacheVerbose: true });

const census = sdb.newTable("census");
await census.cache(() => {
  census.loadData(
    "sda/data/98-401-X2021006_eng_CSV/98-401-X2021006_English_CSV_data_*.csv",
    {
      encoding: "cp1252",
      columns: ["GEO_LEVEL", "CHARACTERISTIC_ID", "DGUID", "C1_COUNT_TOTAL"],
      conditions: `GEO_LEVEL = 'Dissemination area'`,
    },
  );
});
await census
  .keepValues({ CHARACTERISTIC_ID: 243 })
  .log();

await sdb.close();
```

![Une capture d'écran de VS Code montrant les données filtrées.](/assets/stats-can-census/cleaning-filtering.png)

Ça se présente bien ! Nous avons le revenu médian pour chaque aire de diffusion. Il nous reste à ajouter le nom des régions métropolitaines.

### Les régions métropolitaines

Pour obtenir le nom des régions métropolitaines, nous utiliserons le [Fichier des attributs géographiques de 2021](https://www150.statcan.gc.ca/n1/pub/92-151-g/92-151-g2021001-eng.htm) téléchargé plus tôt, enregistré sous `2021_92-151_X.csv`. Ce jeu de données contient beaucoup de colonnes, mais j'ai parcouru la documentation pour vous. Il ne nous en faut que deux :

- `DADGUID_ADIDUGD`, un identifiant correspondant à celui des aires de diffusion dans les données du recensement
- `CMANAME_RMRNOM`, le nom de la région métropolitaine correspondante

Ce fichier utilise aussi l'encodage `Windows-1252`. Nous reprendrons donc les options `encoding`, `columns` et `conditions` pour ne charger que les données nécessaires. La condition conserve les régions métropolitaines, tandis que `removeDuplicates` produit des lignes uniques pour les prochaines étapes. Avec `renameColumns`, l'identifiant des aires de diffusion s'appelle `DGUID` dans la table `census`, qui contient les données du recensement, comme dans la table `names`, qui contient le nom des régions métropolitaines.

Nous mettrons aussi cette étape en cache. Le premier lancement prend quelques secondes, mais les suivants sont presque instantanés.

```ts showLineNumbers filename="main.ts" {20-32}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB({ cacheVerbose: true });

const census = sdb.newTable("census");
await census.cache(() => {
  census.loadData(
    "sda/data/98-401-X2021006_eng_CSV/98-401-X2021006_English_CSV_data_*.csv",
    {
      encoding: "cp1252",
      columns: ["GEO_LEVEL", "CHARACTERISTIC_ID", "DGUID", "C1_COUNT_TOTAL"],
      conditions: `GEO_LEVEL = 'Dissemination area'`,
    },
  );
});
await census
  .keepValues({ CHARACTERISTIC_ID: 243 })
  .log();

const names = sdb.newTable("names");
await names.cache(() => {
  names.loadData("sda/data/2021_92-151_X.csv", {
    encoding: "cp1252",
    columns: ["DADGUID_ADIDUGD", "CMANAME_RMRNOM"],
    conditions: `CMATYPE_RMRGENRE = 'B'`,
  })
    .removeDuplicates()
    .renameColumns({
      DADGUID_ADIDUGD: "DGUID",
    });
});
await names.log();

await sdb.close();
```

![Une capture d'écran de VS Code montrant les identifiants des aires de diffusion et le nom de leur région métropolitaine.](/assets/stats-can-census/names-data.png)

Vous avez peut-être remarqué que la table `names` compte environ 38 000 lignes, contre environ 57 000 pour `census`. C'est parce que les aires de diffusion n'appartiennent pas toutes à une région métropolitaine.

Il ne reste qu'à joindre la table `census` à la table `names`. La méthode `join` trouve automatiquement leur colonne commune `DGUID` et ajoute le bon nom de région métropolitaine à chaque aire de diffusion correspondante. Nos données du recensement et les noms des régions métropolitaines se trouvent maintenant dans la même table ! 🎉

```ts showLineNumbers filename="main.ts" {34-36}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB({ cacheVerbose: true });

const census = sdb.newTable("census");
await census.cache(() => {
  census.loadData(
    "sda/data/98-401-X2021006_eng_CSV/98-401-X2021006_English_CSV_data_*.csv",
    {
      encoding: "cp1252",
      columns: ["GEO_LEVEL", "CHARACTERISTIC_ID", "DGUID", "C1_COUNT_TOTAL"],
      conditions: `GEO_LEVEL = 'Dissemination area'`,
    },
  );
});
await census
  .keepValues({ CHARACTERISTIC_ID: 243 })
  .log();

const names = sdb.newTable("names");
await names.cache(() => {
  names.loadData("sda/data/2021_92-151_X.csv", {
    encoding: "cp1252",
    columns: ["DADGUID_ADIDUGD", "CMANAME_RMRNOM"],
    conditions: `CMATYPE_RMRGENRE = 'B'`,
  })
    .removeDuplicates()
    .renameColumns({
      DADGUID_ADIDUGD: "DGUID",
    });
});
await names.log();

await census
  .join(names)
  .log();

await sdb.close();
```

![Une capture d'écran de VS Code montrant les données du recensement jointes aux noms des régions métropolitaines.](/assets/stats-can-census/names-joined.png)

### Simplifier les géométries

Pour créer une carte, nous avons besoin des frontières des aires de diffusion. Nous les avons téléchargées plus tôt dans le fichier ZIP `lda_000b21a_e.zip` (et je vous ai demandé de ne pas le décompresser 😬).

### Charger les géométries

Pour charger les géométries, nous utilisons `loadGeoData` plutôt que `loadData`. Cette méthode conserve les frontières et leurs coordonnées dans une colonne spatiale `geom`. Comme d'habitude, nous utilisons `cache` pour accélérer les prochaines étapes.

N'oubliez pas de donner l'extension `.shp.zip` à votre Shapefile simplifié. Le `shp` est important pour SDA : sans lui, la librairie ne reconnaît pas le fichier comme un Shapefile et ne peut pas le charger correctement.


```ts showLineNumbers filename="main.ts" {38-42}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB({ cacheVerbose: true });

const census = sdb.newTable("census");
await census.cache(() => {
  census.loadData(
    "sda/data/98-401-X2021006_eng_CSV/98-401-X2021006_English_CSV_data_*.csv",
    {
      encoding: "cp1252",
      columns: ["GEO_LEVEL", "CHARACTERISTIC_ID", "DGUID", "C1_COUNT_TOTAL"],
      conditions: `GEO_LEVEL = 'Dissemination area'`,
    },
  );
});
await census
  .keepValues({ CHARACTERISTIC_ID: 243 })
  .log();

const names = sdb.newTable("names");
await names.cache(() => {
  names.loadData("sda/data/2021_92-151_X.csv", {
    encoding: "cp1252",
    columns: ["DADGUID_ADIDUGD", "CMANAME_RMRNOM"],
    conditions: `CMATYPE_RMRGENRE = 'B'`,
  })
    .removeDuplicates()
    .renameColumns({
      DADGUID_ADIDUGD: "DGUID",
    });
});
await names.log();

await census
  .join(names)
  .log();

const disseminationAreas = sdb.newTable("disseminationAreas");
```

Les données géospatiales se chargent sans problème. Nous voyons les 57 932 aires de diffusion sous forme de lignes, avec leurs propriétés et leurs géométries.

Cependant, la projection pose problème. Dans la colonne `geom`, nous voyons `GEOM(EPSG:3347)`. C'est la projection conique conforme de Lambert utilisée par Statistique Canada, dont les coordonnées sont mesurées en mètres. SDA peut l'utiliser, mais plusieurs méthodes, notamment celles qui dessinent les cartes, nécessitent `EPSG:4326`, une projection courante exprimée en degrés de latitude et de longitude.

Nous pouvons utiliser l'option `toEPSG4326: true` pour convertir les géométries dans le bon format.

Profitons-en pour ne conserver que les colonnes qui nous intéressent :
- `DGUID`, l'identifiant unique des aires de diffusion que nous utiliserons pour joindre les géométries aux données du recensement.
- `geom`, qui contient les géométries.

### Calculer les médianes

Calculer la médiane pour chaque région métropolitaine est facile avec la méthode `summarize`. Pour garder notre code bien organisé, créons une nouvelle fonction utilitaire nommée `addMedianVariation` dans le dossier `helpers`.

Dans `summarize`, nous définissons :

- `columns` à `C1_COUNT_TOTAL`, les valeurs de revenu à résumer.
- `by` à `CMANAME_RMRNOM`, pour obtenir un résultat par région métropolitaine.
- `stats` à `median`, la statistique à calculer.
- `outputTable` à `medians`, le nom de la table produite.

```ts showLineNumbers filename="helpers/addMedianVariation.ts"
import { SimpleTable } from "@nshiab/simple-data-analysis";

  const medians = await disseminationAreas
    .summarize({
      columns: "C1_COUNT_TOTAL",
      by: "CMANAME_RMRNOM",
      stats: "median",
      outputTable: "medians",
```

Nous allons ajouter une colonne numérique `percVar` contenant l'écart en pourcentage entre le revenu médian des ménages de chaque aire de diffusion et celui de sa région métropolitaine. Nous arrondirons le résultat à l'entier le plus proche.

```ts showLineNumbers filename="helpers/addMedianVariation.ts" {16-21}
import { SimpleTable } from "@nshiab/simple-data-analysis";

export default async function addMedianVariation(
  disseminationAreas: SimpleTable,
) {
  const medians = disseminationAreas
    .summarize({
      columns: "C1_COUNT_TOTAL",
      by: "CMANAME_RMRNOM",
      stats: "median",
      outputTable: "medians",
    });

  await disseminationAreas
    .join(medians)
    .addColumn(
      "percVar",
      "number",
      `(C1_COUNT_TOTAL - median) / median * 100`,
    )
    .round("percVar")
    .log();
}
```

```ts showLineNumbers filename="helpers/visualizeData.ts" {20-40}
import { SimpleTable } from "@nshiab/simple-data-analysis";
import { geo, plot } from "@observablehq/plot";

export default async function visualizeData(
  disseminationAreas: SimpleTable,
) {
  const allCMAs = await disseminationAreas.getUniques("CMANAME_RMRNOM");

  for (const cma of allCMAs) {
    console.log(`Processing CMA: ${cma}`);

    const tempTable = await disseminationAreas
      .clone({
        name: "tempTable",
        conditions: `CMANAME_RMRNOM = '${cma}'`,
      })
      .writeMap(
        (geoData) =>
          plot({
            title: cma,
            subtitle:
              "Variation from the median household total income at the dissemination area level.",
            caption: "2021 Census, Statistics Canada",
            projection: {
              type: "mercator",
              domain: geoData,
            },
            color: {
              legend: true,
              type: "diverging",
              domain: [-100, 100],
              ticks: 5,
              tickFormat: (d) => {
                if (d > 0) {
                  return `+${d}%`;
                }
                return `${d}%`;
              },
              label: null,
            },
            marks: [
              geo(geoData, {
                fill: "percVar",
              }),
            ],
          }),
        `./sda/output/${cma}.png`,
      );

    await tempTable.removeTable();
    break;
  }
}
```

C'est déjà beaucoup mieux ! 💅

Une dernière touche : ajoutons un contour à la région métropolitaine. Dans le nouveau code ci-dessous, nous clonons `tempTable` dans la boucle pour créer une table `outline`. La méthode `aggregateGeo("union")` fusionne les géométries des aires de diffusion en un seul polygone, ce qui laisse une ligne avec la frontière de la région métropolitaine.

Nous utilisons ensuite `insertTables` pour ajouter cette ligne à `tempTable`. L'option `unifyColumns` est nécessaire parce que `outline` ne possède qu'une colonne `geom`, tandis que `tempTable` contient aussi les colonnes du recensement. Dans `writeMap`, un deuxième appel à `geo` sélectionne l'entité dont `percVar` vaut `null`, soit notre contour, et la trace en noir avec une légère transparence.

Nous supprimons aussi la table `outline` après avoir écrit la carte, afin d'en créer une nouvelle à chaque itération de la boucle.

Si ces étapes vous semblent complexes, je vous encourage à revoir la leçon [Visualiser des données](/simple-data-analysis/dataviz) avant de continuer.

```ts showLineNumbers filename="helpers/visualizeData.ts" {18-22,52-55,61}
import { SimpleTable } from "@nshiab/simple-data-analysis";
import { geo, plot } from "@observablehq/plot";

export default async function visualizeData(
  disseminationAreas: SimpleTable,
) {
  const allCMAs = await disseminationAreas.getUniques("CMANAME_RMRNOM");

  for (const cma of allCMAs) {
    console.log(`Processing CMA: ${cma}`);

    const tempTable = await disseminationAreas
      .clone({
        name: "tempTable",
        conditions: `CMANAME_RMRNOM = '${cma}'`,
      });

    const outline = tempTable
      .clone("outline")
      .aggregateGeo("union");

    tempTable.insertTables(outline, { unifyColumns: true });

    await tempTable.writeMap(
      (geoData) =>
        plot({
          title: cma,
          subtitle:
            "Variation from the median household total income at the dissemination area level.",
          caption: "2021 Census, Statistics Canada",
          projection: {
            type: "mercator",
            domain: geoData,
          },
          color: {
            legend: true,
            type: "diverging",
            domain: [-100, 100],
            ticks: 5,
            tickFormat: (d) => {
              if (d > 0) {
                return `+${d}%`;
              }
              return `${d}%`;
            },
            label: null,
          },
          marks: [
            geo(geoData, {
              fill: "percVar",
            }),

              stroke: "black",
              strokeOpacity: 0.5,
```

Nous sommes presque prêts à retirer `break` et à créer les cartes de toutes les régions métropolitaines. Mais d'abord, nous devons nettoyer le nom de la RMR utilisé dans le chemin du fichier de sortie. ![Une capture d'écran de VS Code montrant une erreur de géométrie invalide pendant le traitement des régions métropolitaines.](/assets/stats-can-census/invalid-geometries-error.png)

Heureusement, SDA permet de corriger facilement les géométries invalides avec `fixGeo()`. Nous chargeons les frontières des aires de diffusion dans `getDisseminationAreas`. Il suffit donc d'enchaîner cette méthode après `loadGeoData()` à l'intérieur de `cache()`. SDA réparera les géométries pendant leur chargement et conservera le résultat corrigé en cache pour les prochains lancements.

```ts showLineNumbers filename="helpers/getDisseminationAreas.ts" {38}
import { SimpleDB } from "@nshiab/simple-data-analysis";

export default async function getDisseminationAreas(sdb: SimpleDB) {
  const census = sdb.newTable("census");
  await census.cache(() => {
    census.loadData(
      "sda/data/98-401-X2021006_eng_CSV/98-401-X2021006_English_CSV_data_*.csv",
      {
        encoding: "cp1252",
        columns: ["GEO_LEVEL", "CHARACTERISTIC_ID", "DGUID", "C1_COUNT_TOTAL"],
        conditions: `GEO_LEVEL = 'Dissemination area'`,
      },
    );
  });
  census.keepValues({ CHARACTERISTIC_ID: 243 });

  const names = sdb.newTable("names");
  await names.cache(() => {
    names.loadData("sda/data/2021_92-151_X.csv", {
      encoding: "cp1252",
      columns: ["DADGUID_ADIDUGD", "CMANAME_RMRNOM"],
      conditions: `CMATYPE_RMRGENRE = 'B'`,
    })
      .removeDuplicates()
      .renameColumns({
        DADGUID_ADIDUGD: "DGUID",
      });
  });
  census.join(names);

  const disseminationAreas = sdb.newTable("disseminationAreas");
  await disseminationAreas.cache(() => {
    disseminationAreas
      .loadGeoData("sda/data/lda_000b21a_e.shp.zip", {
        toEPSG4326: true,
        columns: ["DGUID", "geom"],
      })
      .fixGeo();
  });
  await disseminationAreas
    .join(census)
    .removeMissing()
    .log();

  return disseminationAreas;
}
```

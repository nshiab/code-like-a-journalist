# Variables

Commençons votre première leçon de TypeScript avec les variables ! En chemin, je vous montrerai quelques astuces et conseils pour travailler avec TypeScript, VS Code et Node.js.

Notez que je suppose que vous avez terminé la [leçon d'installation](/first-steps/setup) avant de vous lancer dans celle-ci.

<NoticeIntro lang="fr"/>

## Configuration

Créez un nouveau dossier vide sur votre ordinateur, ouvrez-le avec VS Code et créez-y un fichier nommé `main.ts`.

Tapez ce code dans `main.ts` et enregistrez le fichier :

```ts showLineNumbers filename="main.ts"
console.log("Hello!");
```

Ouvrez le terminal (`Command` + `J` sur Mac ou `Control` + `J` sur Windows) et exécutez cette commande :

```sh
node --watch main.ts
```

Cette commande exécute notre code et le relance automatiquement chaque fois que nous enregistrons une modification, pour voir les résultats au fur et à mesure que nous travaillons.

![VS Code montrant console.log("Hello!") dans main.ts et Hello! dans le terminal exécutant node --watch main.ts.](/assets/first-steps/variables/run.png)

<Callout type="info" emoji="💡">
    Vous avez peut-être remarqué que votre code s'affiche avec plusieurs couleurs. Cela s'appelle *code highlighting*. Dans le code, chaque mot a un rôle différent et se voit attribuer une couleur. Par exemple, ici `console` est un objet, et `log` est l'une de ses méthodes. De plus, en tapant, vous pouvez voir des suggestions d'auto-complétion et des infobulles. Cela s'appelle l'*IntelliSense*. C'est votre éditeur qui essaie de deviner ce que vous pourriez vouloir écrire et fournit une documentation. Pour l'instant, vous pouvez ignorer tout cela, mais nous l'utiliserons plus tard.
</Callout>

## Variables avec `const`

Ajoutons maintenant des variables à notre code.

Les variables sont comme des conteneurs. Vous pouvez y mettre des choses, et lorsque vous les référencez, Node.js regardera ce qu'il y a à l'intérieur et l'utilisera. C'est très pratique, car vous pouvez réutiliser la même variable à différents endroits dans votre code.

Remplaçons notre message de bienvenue par un calcul. Nous mettrons `2` dans la variable `a` et `4` dans `b`, puis nous stockerons leur somme dans la variable `c`. Modifiez `main.ts` avec le code ci-dessous.

Nous créons ces variables avec le mot-clé `const`, ce qui signifie que nous créons des variables constantes. Nous verrons un autre type de variable plus loin dans cette leçon.

```ts showLineNumbers filename="main.ts"
const a = 2;
const b = 4;
const c = a + b;
console.log(c);
```

<Callout type="info" emoji="💡">
    Avez-vous remarqué tous les points-virgules ? Ils marquent la fin d'une instruction que vous donnez à votre ordinateur. Votre code fonctionnera souvent même sans eux, car Node.js peut déduire où ils devraient se trouver, mais nous les inclurons dans nos exemples de code comme bonne habitude de programmation.
</Callout>

Votre ordinateur exécutera ce code de haut en bas. La ligne 1 sera exécutée, puis la ligne 2, et ainsi de suite.

Si vous enregistrez, vous verrez `6` dans le terminal. Vous venez d'effectuer un calcul avec des variables !

![VS Code montrant les variables a, b et c et le résultat 6 dans le terminal.](/assets/first-steps/variables/const-variables.png)

`c` est le résultat de la somme de `a` et `b`, donc si vous changez `a` en `3`, cela changera la valeur dans `c`. Au lieu de `6`, votre ordinateur affichera `7`. Essayez-le !

![VS Code montrant a défini à 3 et le résultat mis à jour à 7 dans le terminal.](/assets/first-steps/variables/const-variables-seven.png)

Les variables sont omniprésentes dans le code car elles permettent d'abstraire et de réutiliser votre logique.

Nous avons utilisé `a`, `b` et `c` comme noms de variables, mais vous pouvez choisir d'autres noms, comme ceux ci-dessous.

Par exemple, j'ai mis à jour notre code précédent avec des noms de variables différents. Si vous l'exécutez, le résultat sera le même dans le terminal.

```ts showLineNumbers filename="main.ts"
const banana = 3;
const super_apple = 4;
const POTATO = banana + super_apple;
console.log(POTATO);
```

![VS Code montrant les variables banana, super_apple et POTATO et le résultat 7 dans le terminal.](/assets/first-steps/variables/variable-names.png)

<Callout type="info" emoji="💡">
    Pour éviter toute confusion dans le code, il est important de nommer les variables de manière réfléchie. Lorsqu'un nom de variable est composé de plusieurs mots, nous utilisons par convention le *camel case*. Cela signifie que le premier mot est en minuscules, suivi des mots suivants avec une majuscule. Par exemple, `first name` deviendrait `firstName`. Différents langages et contextes utilisent différents styles de casse, comme le snake case en Python (`first_name`) ou le délicieux kebab case pour le développement web (`first-name`).
</Callout>

## Variables avec `let`

Il existe deux principales manières de créer des variables :

- Avec `const`, si vous avez l'intention de garder le contenu constant, comme nous l'avons fait ci-dessus. Cela devrait être votre premier choix.
- Avec `let`, si vous devez remplacer le contenu.

Voyons ce qui se passe quand nous essayons de remplacer la valeur d'une variable créée avec `const`. À la ligne 6, nous essayons de remplacer la valeur de `c` par `10`. À la ligne 7, nous essayons d'afficher sa nouvelle valeur.

```ts showLineNumbers filename="main.ts" {6-7}
const a = 3;
const b = 4;
const c = a + b;
console.log(c);

c = 10;
console.log(c);
```

Modifiez `main.ts` avec ce code et enregistrez le fichier. Voici ce que vous devriez voir :

![VS Code montrant une erreur lors de la tentative de réaffectation de c et une TypeError dans le terminal.](/assets/first-steps/variables/const-error.png)

Commençons par le terminal. Il affiche d'abord `7`, grâce à `console.log(c)` à la ligne 4. Tout fonctionne jusque-là.

À la ligne 6, `c = 10` provoque l'erreur `TypeError: Assignment to constant variable`, et Node.js arrête l'exécution du code. Remplacer la valeur d'une variable créée avec `const` est interdit. Cela aide à éviter de modifier des valeurs par accident, ce qui est utile en analyse de données.

<Callout type="info" emoji="💡">
    Lorsqu'une erreur est générée, Node.js vous indique où se trouve le code problématique. Par exemple, `.../main.ts:6:3` désigne le fichier `main.ts`, à la sixième ligne et au troisième caractère. Si vous appuyez sur `CMD` sur Mac ou `CTRL` sur PC et cliquez sur ce chemin de fichier, cela vous y mènera directement. C'est très pratique lorsque vous commencez à travailler avec beaucoup de fichiers.
</Callout>

Au fait, pendant que vous écriviez ce code, VS Code a souligné `c` en rouge. Le nom du fichier `main.ts` est aussi devenu rouge dans l'Explorer à gauche et dans le titre de l'onglet en haut. Le chiffre `1` indique que TypeScript a trouvé une erreur dans le fichier, sans avoir besoin de l'exécuter.

Survolez le `c` souligné pour voir l'explication : vous ne pouvez pas attribuer une nouvelle valeur à une constante.

Cette vérification en direct permet de repérer des erreurs pendant la saisie. Elle peut vous faire gagner beaucoup de temps, surtout lorsqu'une analyse prend des minutes ou des heures à s'exécuter, comme nous le verrons dans les prochaines leçons.

![VS Code avec des flèches pointant vers les noms de fichier main.ts en rouge et le c souligné, avec une infobulle expliquant que c est une constante.](/assets/first-steps/variables/const-error-hover.png)

Mais comment corriger cette erreur ?

Si nous voulons remplacer le contenu d'une variable, nous devons remplacer `const` par `let` lors de la création de la variable `c` à la ligne 3.

```ts showLineNumbers filename="main.ts" {3}
const a = 3;
const b = 4;
let c = a + b;
console.log(c);

c = 10;
console.log(c);
```

Maintenant, le code s'exécute sans problème ! Si vous mettez à jour votre code et l'enregistrez, vous verrez la première valeur de `c` s'afficher dans votre terminal, suivie de la deuxième valeur.

![VS Code montrant c déclaré avec let et les valeurs 7 et 10 affichées dans le terminal.](/assets/first-steps/variables/let-variables.png)

Nous pouvons également réutiliser `c` pour le remplacer... par lui-même ! Les deux dernières lignes du code ci-dessous remplacent `c` par `c` au carré (`c` multiplié par lui-même).

```ts showLineNumbers filename="main.ts" {9-10}
const a = 3;
const b = 4;
let c = a + b;
console.log(c);

c = 10;
console.log(c);

c = c * c;
console.log(c);
```

Le code ci-dessus affiche `7`, puis `10`, puis `100`.

![VS Code montrant c multiplié par lui-même et les valeurs 7, 10 et 100 dans le terminal.](/assets/first-steps/variables/squared.png)

## Variables typées

Il y a autre chose à savoir sur les variables : **le type de données est important**. C'est pourquoi cela s'appelle... TypeScript !

Par exemple, si vous survolez `c` maintenant, vous verrez qu'il a un type `number`. Cela est dû au fait que la somme de `a` et `b` est un nombre. Le type ici est **inféré**.

![VS Code montrant le type inféré number de c dans une infobulle.](/assets/first-steps/variables/type-number.png)

Maintenant, remplaçons `c` par du texte à la ligne `6`. En TypeScript, le texte est appelé un `string`, car c'est une chaîne (*string* en anglais) de caractères. Pour que votre ordinateur le reconnaisse comme du texte, il doit être entouré de guillemets.

```ts showLineNumbers filename="main.ts" {6}
const a = 3;
const b = 4;
let c = a + b;
console.log(c);

c = "Hey! What's up?";
console.log(c);

c = c * c;
console.log(c);
```

Modifiez `main.ts` avec ce code et enregistrez le fichier.

VS Code signale une nouvelle erreur de type : `main.ts` redevient rouge et une ligne rouge ondulée apparaît sous `c`.

Node.js exécute tout de même le code et affiche `7`, le message, puis `NaN`, qui signifie *not a number*, soit « pas un nombre ». Essayer de multiplier ce message par lui-même à la ligne 9 ne produit pas de nombre.

![VS Code montrant les noms de fichier main.ts en rouge, c souligné et NaN dans le terminal après la multiplication du message par lui-même.](/assets/first-steps/variables/type-error.png)

Survolez `c` pour voir l'explication : `Type 'string' is not assignable to type 'number'`. Comme `c` contenait un nombre au départ, son type est `number`. Utiliser `let` permet de changer sa valeur, mais celle-ci doit rester un nombre. C'est une règle de TypeScript.

Ces avertissements et erreurs aident à éviter des erreurs dans de longs scripts, où une valeur peut être réutilisée plus loin.

![VS Code montrant l'infobulle Type 'string' is not assignable to type 'number'.](/assets/first-steps/variables/type-error-hover.png)

<Callout type="info" emoji="💡">
    Vous avez peut-être remarqué que le terminal n'affiche aucune erreur, même si VS Code signale une erreur de type. Node.js exécute le code sans vérifier les types TypeScript ; VS Code les vérifie pendant la saisie. Dans les prochaines leçons, notre commande dans le terminal vérifiera les types avant d'exécuter le code, pour que les erreurs de type empêchent l'analyse de démarrer. Cela aide à éviter des erreurs dans nos résultats.
</Callout>

Si vous avez besoin de stocker `"Hey! What's up?"` dans une variable, la solution est simple : créez une nouvelle variable, comme ci-dessous. Ainsi, `c` reste disponible pour nos calculs.

```ts showLineNumbers filename="main.ts" {12-13}
const a = 3;
const b = 4;
let c = a + b;
console.log(c);

c = 10;
console.log(c);

c = c * c;
console.log(c);

const d = "Hey! What's up?";
console.log(d);
```

![VS Code montrant le message stocké dans une nouvelle variable d et le terminal affichant 7, 10, 100 et Hey! What's up?.](/assets/first-steps/variables/separate-string-variable.png)

## Conclusion

À ce stade, vous pourriez penser : *Pourquoi est-ce si compliqué ? Laisse-moi coder ce que je veux, stupide ordinateur !*

Mais croyez-moi : cela vous évitera de pernicieux bogues. En tant que journaliste computationnel d'expérience, j'ai appris cela à mes dépens. 😅

Utiliser `const` vous empêchera d'écraser accidentellement des variables ou des données importantes, et les types garantiront que vous ne mélangez pas `string`, `number`, `Date`, ou d'autres types de données que nous explorerons dans les prochaines leçons.

Au bout du compte, vous voulez des résultats valides. Vous voulez éviter à tout prix de publier des informations incorrectes. Alors, quand vous pesterez contre les erreurs TypeScript, prenez une grande inspiration et répétez à voix haute : *C'est pour m'aider, ce n'est pas contre moi !*

Bien que cela puisse sembler compliqué pour l'instant, après un peu de pratique, tout deviendra naturel. Faites-moi confiance. 🙂

Terminons par un récapitulatif de nos calculs, avec des commentaires expliquant chaque étape.

```ts showLineNumbers filename="main.ts"
// Nous créons des variables constantes contenant des nombres.
const a = 3;
const b = 4;

// Le type de c est inféré comme number, car a et b sont des nombres.
// Nous utilisons let pour pouvoir changer sa valeur plus tard.
let c = a + b;
console.log(c);

// c est typé comme un nombre, donc nous ne pouvons le remplacer que par des nombres.
c = 10;
console.log(c);

// Nous pouvons remplacer c en utilisant c lui-même.
c = c * c;
console.log(c);

// Pour un autre type de données, nous créons une nouvelle variable.
const d = "Hey! What's up?";
console.log(d);
```

<Callout type="info" emoji="💡">
    Pour laisser des commentaires dans votre code, utilisez `//` au début de la ligne, comme ci-dessus. Si vous souhaitez commenter plusieurs lignes, encadrez tout avec `/*` au début et `*/` à la fin. Les commentaires sont ignorés par votre ordinateur, ils sont donc un excellent moyen d'expliquer ce que fait votre code ou de désactiver temporairement certaines parties de votre code.

    Si vous ne voulez pas taper les marqueurs de commentaire à la main, placez votre curseur n'importe où sur une ligne ou sélectionnez plusieurs lignes, puis appuyez sur `CMD` + `/` sur Mac ou `CTRL` + `/` sur Windows dans VS Code. Utilisez à nouveau le même raccourci pour les décommenter.
</Callout>

## What's the question?

To avoid getting lost, let's define the question we're trying to answer:
- For each Canadian metropolitan area, which dissemination areas have household incomes above or below the median?

The metropolitan areas are defined as follows in the Census:

> A census metropolitan area (CMA) is formed by one or more adjacent municipalities centred on a population centre (known as the core). A CMA must have a total population of at least 100,000, of which 50,000 or more must live in the core.

And here's the definition of dissemination areas:

> A dissemination area (DA) is a small, relatively stable geographic unit with an average population of 400 to 700 persons. It is the smallest standard geographic area for which all census data are disseminated. DAs cover all the territory of Canada.

Let's code!

## Downloading the data

To download the Census data with the most granularity, click on this [Statistics Canada page](https://www12.statcan.gc.ca/census-recensement/2021/dp-pd/prof/details/download-telecharger.cfm?Lang=E).

Click on the first drawer *Comprehensive download file* and then on the *CSV* button for *Canada, provinces, territories, census divisions (CDs), census subdivisions (CSDs), and dissemination areas (DAs)*.

In case you can't find it, here's the [direct link](https://www12.statcan.gc.ca/census-recensement/2021/dp-pd/prof/details/download-telecharger/comp/GetFile.cfm?Lang=E&FILETYPE=CSV&GEONO=006). This will download a 2.25 GB zip file.

![A screenshot of Statistics Canada webpage to download Census data.](/assets/stats-can-census/stats-can-census-download.png)

Because we want to work on the metropolitan areas, it would be great to have the metropolitan area names for each dissemination area.

Statistics Canada provides this information in the [2021 Geographic Attribute File](https://www150.statcan.gc.ca/n1/pub/92-151-g/92-151-g2021001-eng.htm). Download it from this [direct Statistics Canada link](https://www12.statcan.gc.ca/census-recensement/2021/geo/aip-pia/attribute-attribs/files-fichiers/2021_92-151_X.zip). It is a 9.8 MB zip file named `2021_92-151_X.zip`.

![A screenshot of Statistics Canada webpage to download Census data names.](/assets/stats-can-census/stats-can-names-download.png)

And finally, since we want to create a map, we need the geospatial boundaries of the dissemination areas. You'll find them [here](https://www12.statcan.gc.ca/census-recensement/2021/geo/sip-pis/boundary-limites/index2021-eng.cfm?year=21).

Click on the drawer *Statistical boundaries* and select *Dissemination areas*. In the *Format* section, select *Shapefile*, then hit *Continue* at the bottom of the page.

In case you can't find it, here's the [direct link](https://www12.statcan.gc.ca/census-recensement/2021/geo/sip-pis/boundary-limites/files-fichiers/lda_000b21a_e.zip) to download the file. It's around 197 MB.

![A screenshot of Statistics Canada webpage to download dissemination areas boundaries.](/assets/stats-can-census/stats-can-boundaries-download.png)

Now, move all of this inside the `data` folder in your project and unzip everything except the geospatial boundaries in the file `lda_000b21a_e.zip`!

To unzip, check your folder outside of VS Code, like in Finder or File Explorer. You might need software like Winzip or 7-zip. Once unzipped, remove the two original `.zip` files from your project and download folder, and don't forget to empty your trash! 🗑️ Disk storage is precious when you work with big datasets.

## The Census data

### Loading what we need

When we unzipped the census data, we got a folder with multiple files in it. The data is in the files with the `_data_` substring.

Let's try to load the first 1,000 rows of the first file, for the Atlantic provinces. These files are very large, so we'll use the `limit` option to load just a sample while exploring them.

```ts showLineNumbers filename="main.ts"
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB();

await sdb
  .newTable("census")
  .loadData(
    "sda/data/98-401-X2021006_eng_CSV/98-401-X2021006_English_CSV_data_Atlantic.csv",
    { limit: 1000 },
  ).log();

await sdb.close();
```

Hmmm... We have a problem. This error means that the data is not using the `UTF-8` encoding, which is the standard nowadays.

![VS Code showing the Atlantic CSV in the Explorer, its path in main.ts, and a UTF-8 encoding error in the terminal.](/assets/stats-can-census/encoding-error.png)

<Callout type="info" emoji="💡">
    The Atlantic CSV has a long path. To copy it without typing it out, right-click the file in VS Code’s Explorer and select **Copy Relative Path**.
</Callout>

I asked Statistics Canada about this, and they told me they use the [`Windows-1252`](https://en.wikipedia.org/wiki/Windows-1252) encoding. Luckily, SDA has an `encoding` option. We can use `cp1252` to refer to this encoding, and SDA will automatically convert the data to `UTF-8` behind the scenes.

Update your code with the example below and save the file (`COMMAND` + `S` on Mac or `CTRL` + `S` on Windows). The first 1,000 rows should now appear.

```ts showLineNumbers filename="main.ts" {9}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB();

await sdb
  .newTable("census")
  .loadData(
    "sda/data/98-401-X2021006_eng_CSV/98-401-X2021006_English_CSV_data_Atlantic.csv",
    { limit: 1000, encoding: "cp1252" },
  ).log();

await sdb.close();
```

Amazing! It works! 🥳

![VS Code showing encoding set to cp1252 and the census table in the terminal, with 1,000 rows loaded and 10 displayed.](/assets/stats-can-census/atlantic-data.png)

<Callout type="info" emoji="💡">
    If the table layout is displayed weirdly in your terminal, it's because the width of the table is bigger than the width of your terminal. Right-click on the terminal and look for `Toggle size with content width`. There is also a handy shortcut that I use all the time to do that: `OPTION` + `Z` on Mac and `ALT` + `Z` on PC.
</Callout>

We can see a lot of columns in our data, but we only need four from the CSV file:

- `GEO_LEVEL`: The type of geographic area represented by the row.
- `CHARACTERISTIC_ID`: The Census variable represented by the row.
- `DGUID`: The unique geographic identifier we will use to join our data.
- `C1_COUNT_TOTAL`: The value of the Census variable.

We can use the `columns` option to load only these four columns.

```ts showLineNumbers filename="main.ts" {12}

const sdb = new SimpleDB();

await sdb
  .newTable("census")
  .loadData(
    "sda/data/98-401-X2021006_eng_CSV/98-401-X2021006_English_CSV_data_Atlantic.csv",
    {
      limit: 1000,
      encoding: "cp1252",
      columns: ["GEO_LEVEL", "CHARACTERISTIC_ID", "DGUID", "C1_COUNT_TOTAL"],
    },
  ).log();

await sdb.close();
```

![VS Code showing the columns option and the resulting census table with only GEO_LEVEL, CHARACTERISTIC_ID, DGUID, and C1_COUNT_TOTAL.](/assets/stats-can-census/census-columns.png)

The `GEO_LEVEL` column currently shows country-level rows. That's because the file we downloaded contains *Canada, provinces, territories, census divisions, census subdivisions, and dissemination areas*, while we only need dissemination areas.

We can use the `conditions` option to keep only dissemination area rows in our table.

```ts showLineNumbers filename="main.ts" {13}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB();

await sdb
  .newTable("census")
  .loadData(
    "sda/data/98-401-X2021006_eng_CSV/98-401-X2021006_English_CSV_data_Atlantic.csv",
    {
      limit: 1000,
      encoding: "cp1252",
      columns: ["GEO_LEVEL", "CHARACTERISTIC_ID", "DGUID", "C1_COUNT_TOTAL"],
      conditions: `GEO_LEVEL = 'Dissemination area'`,
    },
  ).log();

await sdb.close();
```

![VS Code showing the conditions option and a census table filtered to dissemination areas.](/assets/stats-can-census/census-condition.png)

We are now ready to remove the `limit` option and load all the data from the Atlantic CSV file. Before doing that, let's use the `cache` method and enable `cacheVerbose` to see more details in the terminal about how and what SDA caches.

On the first run, `cache` runs the code we pass it and saves the resulting table in a new `.sda-cache` folder. On subsequent runs, unchanged code loads the result directly from the cache instead of reading the original file again, converting its encoding, selecting its columns, and filtering its rows. This is much faster.

```ts showLineNumbers filename="main.ts" {3, 6-15}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB({ cacheVerbose: true });

const census = sdb.newTable("census");
await census.cache(() => {
  census.loadData(
    "sda/data/98-401-X2021006_eng_CSV/98-401-X2021006_English_CSV_data_Atlantic.csv",
    {
      encoding: "cp1252",
      columns: ["GEO_LEVEL", "CHARACTERISTIC_ID", "DGUID", "C1_COUNT_TOTAL"],
      conditions: `GEO_LEVEL = 'Dissemination area'`,
    },
  );
});
await census.log();

await sdb.close();
```

![VS Code showing the new .sda-cache folder and the terminal log for the first run, which computed and cached the census table.](/assets/stats-can-census/atlantic-cache-first-run.png)

Most of that time went into converting the CSV from Windows-1252 to UTF-8. Loading can be much faster when the data is already in UTF-8. On the same M4 Max, I loaded a billion rows in about eight seconds for the [One Billion Row Challenge 😱](/data-projects/one-billion-row-challenge). If you haven’t tried it yet, give it a go after this project.

### Filtering the Census variables

Let's refresh our memory. Our question is:
- For each Canadian metropolitan area, which dissemination areas have household incomes above or below the median?

To find the household total income variable, open `98-401-X2021006_English_meta.txt` in the Census data folder. This file lists all the Census variables, and it shows that the `CHARACTERISTIC_ID` for `Median total income of household in 2020 ($)` is `243`.

In the screenshot below, I used search to find it quickly (`COMMAND` + `F` on Mac or `CTRL` + `F` on Windows).

![The Census metadata file in VS Code shows characteristic ID 243 for median total household income in 2020.](/assets/stats-can-census/income-code.png)

We can use `keepValues` to select only rows where `CHARACTERISTIC_ID` is `243`.

⚠️ Make sure to add `keepValues` after the `cache` method, as shown below. If you change the code inside `cache`, SDA will run that entire block again and load the original data. Once the 152 million rows are loaded from the cache, filtering them down to around 57,000 rows is very fast with SDA, so we do not need to cache this step.

```ts showLineNumbers filename="main.ts" {16-18}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB({ cacheVerbose: true });

const census = sdb.newTable("census");
await census.cache(() => {
  census.loadData(
    "sda/data/98-401-X2021006_eng_CSV/98-401-X2021006_English_CSV_data_*.csv",
    {
      encoding: "cp1252",
      columns: ["GEO_LEVEL", "CHARACTERISTIC_ID", "DGUID", "C1_COUNT_TOTAL"],
      conditions: `GEO_LEVEL = 'Dissemination area'`,
    },
  );
});
await census
  .keepValues({ CHARACTERISTIC_ID: 243 })
  .log();

await sdb.close();
```

![VS Code shows the keepValues filter for CHARACTERISTIC_ID 243 and the resulting table with 57,936 rows.](/assets/stats-can-census/cleaning-filtering.png)

This is looking great! We have the median income for each dissemination area. Now, it would be great to add the metropolitan area names.

### The metropolitan areas

To retrieve the metropolitan area names, we'll use the [2021 Geographic Attribute File](https://www150.statcan.gc.ca/n1/pub/92-151-g/92-151-g2021001-eng.htm) we downloaded earlier, stored in `2021_92-151_X.csv`. This dataset has many columns, but I went through the documentation for you. We need only two:

- `DADGUID_ADIDUGD`, an ID that matches the dissemination area IDs in the Census data
- `CMANAME_RMRNOM`, the name of the corresponding metropolitan area

The file also uses `Windows-1252`, so we'll use the same `encoding`, `columns`, and `conditions` options as before to load only what we need. The condition keeps metropolitan areas, while `removeDuplicates` gives us unique rows for the next steps. We also use `renameColumns` so the dissemination area IDs are stored in a column named `DGUID` in the `census` table, which stores the Census data, and in the `names` table, which stores the metropolitan area names.

We will cache this work too. The first run takes a few seconds, but subsequent runs are almost instant.

```ts showLineNumbers filename="main.ts" {20-32}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB({ cacheVerbose: true });

const census = sdb.newTable("census");
await census.cache(() => {
  census.loadData(
    "sda/data/98-401-X2021006_eng_CSV/98-401-X2021006_English_CSV_data_*.csv",
    {
      encoding: "cp1252",
      columns: ["GEO_LEVEL", "CHARACTERISTIC_ID", "DGUID", "C1_COUNT_TOTAL"],
      conditions: `GEO_LEVEL = 'Dissemination area'`,
    },
  );
});
await census
  .keepValues({ CHARACTERISTIC_ID: 243 })
  .log();

const names = sdb.newTable("names");
await names.cache(() => {
  names.loadData("sda/data/2021_92-151_X.csv", {
    encoding: "cp1252",
    columns: ["DADGUID_ADIDUGD", "CMANAME_RMRNOM"],
    conditions: `CMATYPE_RMRGENRE = 'B'`,
  })
    .removeDuplicates()
    .renameColumns({
      DADGUID_ADIDUGD: "DGUID",
    });
});
await names.log();

await sdb.close();
```

![VS Code shows the names table with dissemination area IDs, metropolitan area names, and a total of 38,476 rows.](/assets/stats-can-census/names-data.png)

You might have noticed that the `names` table has around 38,000 rows, while the `census` table has around 57,000. This is because not every dissemination area belongs to a metropolitan area.

The last step is to join the `census` table with the `names` table. The `join` method automatically finds their shared `DGUID` column and adds the appropriate metropolitan area name to each matching dissemination area. Now our Census data and metropolitan area names are together in one table! 🎉

### Loading the geometries

To load the geometries, we use `loadGeoData` instead of `loadData`. This method stores the boundaries and their coordinates in a spatial `geom` column. As usual, we use `cache` to keep everything snappy going forward.

Don't forget to modify the file extension of your simplified Shapefile to `.shp.zip`. The `shp` is important for SDA. Without it, SDA doesn't recognize the file as a Shapefile and can't load it correctly.


```ts showLineNumbers filename="main.ts" {38-42}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB({ cacheVerbose: true });

const census = sdb.newTable("census");
await census.cache(() => {
  census.loadData(
    "sda/data/98-401-X2021006_eng_CSV/98-401-X2021006_English_CSV_data_*.csv",
    {
      encoding: "cp1252",
      columns: ["GEO_LEVEL", "CHARACTERISTIC_ID", "DGUID", "C1_COUNT_TOTAL"],
      conditions: `GEO_LEVEL = 'Dissemination area'`,
    },
  );
});
await census
  .keepValues({ CHARACTERISTIC_ID: 243 })
  .log();

const names = sdb.newTable("names");
await names.cache(() => {
  names.loadData("sda/data/2021_92-151_X.csv", {
    encoding: "cp1252",
    columns: ["DADGUID_ADIDUGD", "CMANAME_RMRNOM"],
    conditions: `CMATYPE_RMRGENRE = 'B'`,
  })
    .removeDuplicates()
    .renameColumns({
      DADGUID_ADIDUGD: "DGUID",
    });
});
await names.log();

await census
  .join(names)
  .log();

const disseminationAreas = sdb.newTable("disseminationAreas");
await disseminationAreas.cache(() => {
  disseminationAreas.loadGeoData("sda/data/lda_000b21a_e.shp.zip");
});
await disseminationAreas.log();
```

However, the projection is problematic. In the `geom` column, we can see `GEOM(EPSG:3347)`. We can use the option `toEPSG4326: true` to convert the geometries to the right format.

- `geom`, which stores the geometries.

## Answering the question

Now that we have the Census data and the dissemination area geometries together, we can answer our question:

- For each Canadian metropolitan area, which dissemination areas have household incomes above or below the median?

### Comparing incomes with the median

For each dissemination area, we want to know how far its median household income is above or below the median across dissemination areas in its metropolitan area. The `percentChange` method calculates that percentage difference directly. Create `addMedianVariation.ts` in the `helpers` folder.

- `"C1_COUNT_TOTAL"` contains the median household income for each dissemination area.
- `{ stat: "median", by: "CMANAME_RMRNOM" }` uses the median of those values within each metropolitan area as the reference.
- `"percVar"` names the new column that stores the result.
- `base: 100` expresses the difference as a percentage, and `decimals: 0` rounds it to the nearest whole number.

```ts showLineNumbers filename="helpers/addMedianVariation.ts"
import type { SimpleTable } from "@nshiab/simple-data-analysis";

export default async function addMedianVariation(disseminationAreas: SimpleTable) {
  await disseminationAreas
    .percentChange("C1_COUNT_TOTAL", { stat: "median", by: "CMANAME_RMRNOM" }, "percVar", {
      base: 100,
      decimals: 0,
    })
    .log();
}
```

Now we can import `addMedianVariation` in `main.ts` and call it with our `disseminationAreas` table.

One last touch: let's add an outline around the metropolitan area. In the new code below, we clone `tempTable` inside the loop to create an `outline` table. Calling `aggregateGeo("union")` merges its dissemination area geometries into one polygon, leaving one row with the metropolitan area's boundary.

We then use `insertTables` to add that row to `tempTable`. The `unifyColumns` option is needed because `outline` has only a `geom` column, while `tempTable` also has the Census columns. In `writeMap`, a second `geo` mark selects the feature whose `percVar` is `null` (our outline) and draws it with a partly transparent black stroke.

We also remove the `outline` table after writing the map, so each loop iteration can create a fresh one.

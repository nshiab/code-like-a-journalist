# Analyse de données avec la librairie Simple Data Analysis

Dans cette leçon, nous allons apprendre à utiliser la librairie en code ouvert que j'ai créée : [simple-data-analysis](https://github.com/nshiab/simple-data-analysis). Nous analyserons des données historiques de température moyenne quotidienne dans trois villes canadiennes à titre d'exemple. Notre objectif sera de répondre à cette question :

- À quelle vitesse les températures ont-elles augmenté ces dernières décennies ?

Pour ce faire, nous calculerons la température moyenne par période de 30 ans et examinerons les tendances.

Si vous avez une minute, ajoutez un ⭐ à la [page GitHub](https://github.com/nshiab/simple-data-analysis) de la librairie. C'est toujours agréable de savoir que son travail en code ouvert est apprécié. 😊

## Installation

La librairie est publiée sur [JSR](https://jsr.io/@nshiab/simple-data-analysis) et [NPM](https://www.npmjs.com/package/@nshiab/simple-data-analysis), et vous pouvez l'installer en exécutant `deno add jsr:@nshiab/simple-data-analysis`.

Mais il y a une meilleure façon. 😏

Cela indique à Deno d'exécuter l'outil [setup-data-project](https://github.com/nshiab/setup-data-project), que j'ai créé pour installer et configurer facilement tout ce dont vous avez besoin pour démarrer une nouvelle analyse de données. Lorsque le choix des librairies s'affiche, utilisez la barre d'espace pour sélectionner `simple-data-analysis`.

![Capture d'écran montrant simple-data-analysis sélectionnée dans setup-data-project.](/assets/simple-data-analysis/tabular-data/setup.png)

Après avoir sélectionné `simple-data-analysis` avec la barre d’espace, appuyez sur `Entrée`.

L’outil de configuration téléchargera, installera et créera tout ce dont nous avons besoin dans ce dossier pour le reste de la leçon.

![VS Code montrant la configuration terminée et les fichiers créés par setup-data-project.](/assets/simple-data-analysis/tabular-data/setup-complete.png)

L’outil de configuration a créé plusieurs dossiers et fichiers. Le dossier le plus important est `sda`. Vous y trouverez :

Le dossier `docs` et le fichier `AGENTS.md` sont destinés aux agents d’IA. Ils leur fournissent des instructions pour utiliser la librairie SDA et organiser votre code.

## Création d'une table

Laissez-moi vous expliquer le code actuel dans `./sda/main.ts`.

Lorsque vous utilisez SDA, vous créez une **base de données en mémoire**. C'est ce qui se passe à la ligne 3 avec `const sdb = new SimpleDB()`. Une fois nos calculs terminés, nous fermons la base de données à la ligne 10 avec `await sdb.close()`.


```ts showLineNumbers filename="main.ts" {3, 10}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB();
const table = sdb.newTable();

await table
  .loadArray([{ message: "Hello simple-data-analysis!" }])
  .log();

await sdb.close();
```

Comme dans une base de données classique, avec SimpleDB, les données sont stockées dans des **tables**. Si vous êtes plus familier avec Excel ou Google Sheets, les tables peuvent être comprises comme des onglets.

Le code de départ crée une table à la ligne 4, charge un tableau contenant un message d’exemple avec `.loadArray()` et l’affiche avec `.log()`.

```ts showLineNumbers filename="main.ts" {4, 6-8}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB();
const table = sdb.newTable();

await table
  .loadArray([{ message: "Hello simple-data-analysis!" }])
  .log();

await sdb.close();
```

C’est pourquoi la commande `deno task sda` affiche dans le terminal une table nommée `table1`, avec une colonne `message` et une seule cellule contenant `Hello simple-data-analysis!`.

![VS Code montrant le code de départ et sa table contenant un seul message dans le terminal.](/assets/simple-data-analysis/tabular-data/starter-table.png)

Remplaçons cet exemple par une table pour les températures quotidiennes. Mettez à jour `./sda/main.ts` avec le code ci-dessous.

Pour créer une table, vous pouvez utiliser la méthode `.newTable()`. Vous pouvez lui donner un nom (bien que ce soit optionnel) et stocker la table dans une variable. En général, je nomme la variable et la table de la même façon.


```ts showLineNumbers filename="main.ts" {5}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB();

const temperatures = sdb.newTable("temperatures");

await sdb.close();
```

Maintenant que nous avons une table, nous pouvons utiliser les méthodes de la table ! Sur une nouvelle ligne, tapez la variable `temperatures` (qui fait maintenant référence à la table) et ajoutez un `.` immédiatement après pour voir toutes les méthodes disponibles. Vous pouvez utiliser les flèches haut et bas de votre clavier pour consulter leur documentation et leurs exemples. Il y en a beaucoup !

Dans la capture d’écran ci-dessous, je me suis arrêté sur `loadData`, qui est la méthode que nous allons utiliser dans un instant.

![Capture d’écran montrant la documentation de VS Code pour loadData.](/assets/simple-data-analysis/tabular-data/load-data-doc.png)

## Chargement des données

J’ai téléversé les températures quotidiennes historiques de trois villes canadiennes sur GitHub. C'est un fichier CSV que [vous pouvez voir ici](https://raw.githubusercontent.com/nshiab/simple-data-analysis/refs/heads/main/test/data/files/dailyTemperatures.csv). Il provient des [Données climatiques canadiennes ajustées et homogénéisées](https://www.canada.ca/en/environment-climate-change/services/climate-change/science-research-data/climate-trends-variability/adjusted-homogenized-canadian-data.html) d'Environnement Canada.

Utilisons la méthode `loadData` pour le récupérer. Notez que cette méthode peut aussi bien récupérer des fichiers distants que lire des fichiers locaux. Elle peut charger des fichiers CSV, JSON, Excel et Parquet. Plutôt pratique !

Ce serait intéressant de voir les données une fois chargées. Nous pouvons le faire en appelant la méthode `log`.

```ts showLineNumbers filename="main.ts" {7-11}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB();

const temperatures = sdb.newTable("temperatures");

await temperatures
  .loadData(
    "https://raw.githubusercontent.com/nshiab/simple-data-analysis/refs/heads/main/test/data/files/dailyTemperatures.csv",
  )
  .log();

await sdb.close();
```

<Callout type="info" emoji="💡">
    SDA possède deux types de méthodes. Les **méthodes synchrones**, comme `loadData()`, ajoutent des instructions à une liste d’étapes à exécuter. Vous pouvez les enchaîner avec `.` pour construire votre analyse. Les **méthodes asynchrones**, comme `log()`, exécutent les étapes précédentes avant d’afficher, d’écrire ou d’envoyer les résultats.

    C’est l’un des avantages de SDA : vous pouvez écrire vos étapes de traitement dans l’ordre, ce qui rend le code facile à écrire et à suivre. Plus loin dans cette leçon, nous enchaînerons plusieurs étapes pour voir à quel point cela peut être pratique.
</Callout>

Et voici le résultat ! Nous pouvons voir que les données du fichier CSV ont été intégrées dans la table `temperatures`, qui contient désormais trois colonnes et 131 192 lignes.

![Capture d’écran montrant les données de température enregistrées dans le terminal.](/assets/simple-data-analysis/tabular-data/data-loaded.png)

## Assembler des tables

Ce serait mieux de remplacer les identifiants (`id`) par les noms des villes. Les identifiants et les noms des villes se trouvent dans un autre fichier que [j’ai également téléversé sur GitHub](https://raw.githubusercontent.com/nshiab/simple-data-analysis-core/refs/heads/main/test/data/files/cities.csv).

Allons le récupérer aussi.


```ts showLineNumbers filename="main.ts" {13, 15-19}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB();

const temperatures = sdb.newTable("temperatures");

await temperatures
  .loadData(
    "https://raw.githubusercontent.com/nshiab/simple-data-analysis/refs/heads/main/test/data/files/dailyTemperatures.csv",
  )
  .log();

const cities = sdb.newTable("cities");

await cities
  .loadData(
    "https://raw.githubusercontent.com/nshiab/simple-data-analysis-core/refs/heads/main/test/data/files/cities.csv",
  )
  .log();

await sdb.close();
```

La capture d’écran ci-dessous montre seulement la table `cities`, car il n’y a pas assez de place pour tout afficher. Dans votre terminal, le script devrait afficher d’abord la table `temperatures`, puis la table `cities`.

Comme vous pouvez le voir, la colonne `id` est présente dans les tables `cities` et `temperatures`, mais les noms des villes se trouvent uniquement dans la table `cities`. Nous aimerions intégrer ces noms dans la table `temperatures`.

![Capture d’écran montrant les noms des villes dans le terminal.](/assets/simple-data-analysis/tabular-data/cities-loaded.png)

Pour cela, nous pouvons utiliser la méthode `.join()`.

Par défaut, cette méthode recherche une colonne commune dans deux tables et associe les lignes en fonction des valeurs de cette colonne.

Ainsi, lorsque nous écrivons `temperatures.join(cities)`, nous demandons à SDA de trouver une colonne commune (qui est `id`) dans `temperatures` et `cities`, puis d'ajouter les valeurs de `cities` correspondant au même `id` aux lignes correspondantes dans `temperatures`.


```ts showLineNumbers filename="main.ts" {21-23}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB();

const temperatures = sdb.newTable("temperatures");

await temperatures
  .loadData(
    "https://raw.githubusercontent.com/nshiab/simple-data-analysis/refs/heads/main/test/data/files/dailyTemperatures.csv",
  )
  .log();

const cities = sdb.newTable("cities");

await cities
  .loadData(
    "https://raw.githubusercontent.com/nshiab/simple-data-analysis-core/refs/heads/main/test/data/files/cities.csv",
  )
  .log();

await temperatures
  .join(cities)
  .log();

await sdb.close();
```

Et maintenant, nous avons les noms des villes dans la table `temperatures` !

![Capture d’écran montrant les noms des villes dans la table temperature.](/assets/simple-data-analysis/tabular-data/join.png)

## Mise en cache

Actuellement, à chaque fois que nous enregistrons `main.ts`, les deux fichiers CSV sont téléchargés à nouveau à partir de GitHub. Cela est lent et inutile puisque les données ne changent pas.

Réutilisons les données que nous avons déjà téléchargées grâce à la méthode `.cache()`.

Nous pouvons passer une fonction à la méthode `.cache()`. La première fois qu’elle s’exécute, SDA effectue toutes les étapes qu’elle contient, y compris le téléchargement des données et les calculs, puis enregistre le résultat dans le dossier `.sda-cache`, qui est créé s’il n’existe pas déjà.

Si nous relançons le script sans modifier la fonction, SDA réutilise le résultat enregistré au lieu de télécharger les données et de refaire les calculs.

Ici, nous mettons en cache le téléchargement des données depuis GitHub pour `temperatures` et `cities`. Nous définissons aussi l’option `cacheVerbose` à `true` pour afficher davantage d’informations sur le cache dans le terminal.


```ts showLineNumbers filename="main.ts" {7-12, 16-21} /{ cacheVerbose: true }/
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB({ cacheVerbose: true });

const temperatures = sdb.newTable("temperatures");

await temperatures.cache(() => {
  temperatures
    .loadData(
      "https://raw.githubusercontent.com/nshiab/simple-data-analysis/refs/heads/main/test/data/files/dailyTemperatures.csv",
    );
});

const cities = sdb.newTable("cities");

await cities.cache(() => {
  cities
    .loadData(
      "https://raw.githubusercontent.com/nshiab/simple-data-analysis-core/refs/heads/main/test/data/files/cities.csv",
    );
});

await temperatures
  .join(cities)
  .log();

await sdb.close();
```

Voici le résultat lors de la première exécution.

Comme indiqué dans le terminal, SDA n’a rien trouvé en cache pour le code dans les deux fonctions passées à `.cache()`, donc il a tout exécuté. Cela a pris 1 sec, 459 ms avec ma connexion Internet et mon ordinateur. Le dossier `.sda-cache` a été créé, et les données y sont maintenant mises en cache.

![Capture d’écran montrant les données mises en cache.](/assets/simple-data-analysis/tabular-data/nothing-in-cache.png)

Quand j’enregistre `main.ts` à nouveau (`CMD` + `S` sur Mac et `CTRL` + `S` sur PC), le comportement change.

SDA vérifie si le code dans les deux fonctions passées à `.cache()` a été modifié. Comme il est exactement le même, SDA charge simplement les résultats de l’exécution précédente stockés dans `.sda-cache`.

Au lieu de 1 sec, 459 ms, l’exécution du script n’a pris que... 28 ms ! C'est environ 52 fois plus rapide ! 😱

Ici, la majeure partie du temps gagné provient de la récupération des données qui se fait par le Web. Mais comme nous le verrons dans d’autres leçons, vous pouvez également mettre en cache les résultats de calculs lourds qui prennent du temps à s’exécuter, ce qui peut améliorer considérablement votre productivité.

![Capture d’écran montrant les données récupérées depuis le cache.](/assets/simple-data-analysis/tabular-data/in-cache.png)

<Callout type="info" emoji="💡">
    Appelez toujours `await sdb.close()` à la fin du script. Cette méthode supprime les données en cache inutilisées ; sinon, le dossier `.sda-cache` pourrait grossir indéfiniment. Pour vider le cache manuellement, supprimez le dossier `.sda-cache` ou exécutez `deno task clean`.
</Callout>

## Explorer les données

Pour explorer les données, nous pouvons utiliser la méthode `.summarize()`. Elle agrège les données contenues dans la table. Nous commencerons par explorer la colonne `time`, avec les résultats répartis par `city`.

Comme il s'agit simplement d'une exploration rapide, nous pouvons enchaîner `.summarize()` juste après `.join()` et avant `.log()`. Avec seulement quelques lignes ajoutées à notre script, tout sera traité et affiché dans le terminal.

```ts showLineNumbers filename="main.ts" {25-28}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB({ cacheVerbose: true });

const temperatures = sdb.newTable("temperatures");

await temperatures.cache(() => {
  temperatures
    .loadData(
      "https://raw.githubusercontent.com/nshiab/simple-data-analysis/refs/heads/main/test/data/files/dailyTemperatures.csv",
    );
});

const cities = sdb.newTable("cities");

await cities.cache(() => {
  cities
    .loadData(
      "https://raw.githubusercontent.com/nshiab/simple-data-analysis-core/refs/heads/main/test/data/files/cities.csv",
    );
});

await temperatures
  .join(cities)
  .summarize({
    columns: "time",
    by: "city",
  })
  .log();

await sdb.close();
```

Les valeurs `min` et `max` montrent que nous avons plus d’un siècle de températures quotidiennes pour nos trois villes. C’est plutôt bien pour analyser les tendances !

Mais il y a un problème... La colonne `count` affiche des valeurs différentes pour chaque ville. Théoriquement, nous devrions avoir environ 44 195 jours en 121 ans. Nous en voyons moins ici, ce qui signifie que nous allons devoir gérer des données manquantes...

Au fait, avez-vous remarqué à quel point c’était rapide ? Nous avons résumé plus de 130 000 lignes en un instant. SDA est vraiiiment rapide ! ⚡

![Capture d’écran montrant les valeurs agrégées de time.](/assets/simple-data-analysis/tabular-data/time.png)

<Callout type="info" emoji="💡">
    Si l'affichage de la table semble étrange dans votre terminal, c'est parce que la largeur de la table est plus grande que celle de votre terminal. Faites un clic droit sur le terminal et cherchez `Toggle size with content width`. Il existe aussi un raccourci très pratique que j’utilise tout le temps pour cela : `OPTION` + `Z` sur Mac et `ALT` + `Z` sur PC.
</Callout>

Voyons maintenant ce que nous avons dans `t`, qui représente la *température*. Il suffit de remplacer `"time"` par `"t"` à la ligne 24.

Hmm... Non seulement nous avons des lignes manquantes dans nos données, comme nous l’avons vu juste au-dessus, mais nous avons aussi certaines lignes avec des valeurs `null`.

![Capture d’écran montrant les valeurs agrégées de t.](/assets/simple-data-analysis/tabular-data/t.png)

Occupons-nous de ce problème immédiatement en utilisant la méthode `.removeMissing()`. Elle supprime toutes les lignes contenant une valeur `null`. Vous pouvez aussi spécifier des colonnes précises si nécessaire, mais ce n'est pas utile ici.

Nous pouvons enchaîner `.removeMissing()` directement après `.loadData()`. Ici, j’ai choisi de l’ajouter à l’intérieur de la méthode `.cache()`.


```ts showLineNumbers filename="main.ts" {12}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB({ cacheVerbose: true });

const temperatures = sdb.newTable("temperatures");

await temperatures.cache(() => {
  temperatures
    .loadData(
      "https://raw.githubusercontent.com/nshiab/simple-data-analysis/refs/heads/main/test/data/files/dailyTemperatures.csv",
    )
    .removeMissing();
});

const cities = sdb.newTable("cities");

await cities.cache(() => {
  cities
    .loadData(
      "https://raw.githubusercontent.com/nshiab/simple-data-analysis-core/refs/heads/main/test/data/files/cities.csv",
    );
});

await temperatures
  .join(cities)
  .summarize({
    columns: "t",
    by: "city",
  })
  .log();

await sdb.close();
```

Et voilà ! Plus aucune température `null`.

Comme nous avons modifié le code dans la méthode `.cache()`, vous remarquerez que le message dans le terminal indique que le code est exécuté à nouveau. Les données précédemment mises en cache ont également été supprimées automatiquement. Plutôt malin, non ? 😉

![Capture d’écran montrant la méthode removeMissing en action.](/assets/simple-data-analysis/tabular-data/remove-missing.png)

## Regrouper les années en intervalles

L'une de mes ressources préférées lorsque j'analyse des données climatiques est [climatedata.ca](https://climatedata.ca/). Ils ont une excellente section expliquant pourquoi il est important d'utiliser des [moyennes sur 30 ans](https://climatedata.ca/interactive/30-years-data/) pour identifier des tendances climatiques.

C’est exactement ce que nous allons faire ici !

Tout d’abord, extrayons l’année de la colonne `time` avec la méthode `.extractDatePart()`. Cette méthode permet d’extraire facilement l’année, le mois, le numéro de semaine ou d’autres éléments d’une date à partir d’une colonne contenant des dates.

```ts showLineNumbers filename="main.ts" {26}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB({ cacheVerbose: true });

const temperatures = sdb.newTable("temperatures");

await temperatures.cache(() => {
  temperatures
    .loadData(
      "https://raw.githubusercontent.com/nshiab/simple-data-analysis/refs/heads/main/test/data/files/dailyTemperatures.csv",
    )
    .removeMissing();
});

const cities = sdb.newTable("cities");

await cities.cache(() => {
  cities
    .loadData(
      "https://raw.githubusercontent.com/nshiab/simple-data-analysis-core/refs/heads/main/test/data/files/cities.csv",
    );
});

await temperatures
  .join(cities)
  .extractDatePart("time", "year")
  .log();

await sdb.close();
```


![Capture d’écran montrant la méthode extractDatePart en action.](/assets/simple-data-analysis/tabular-data/year.png)

Maintenant, nous pouvons regrouper les années en intervalles avec la méthode `.bins()`. Comme vous commencez à le comprendre, SDA propose une méthode pour presque tout ce dont vous avez besoin lors de l'analyse de données. 😎

La méthode `.bins()` nécessite quatre arguments :

- La colonne contenant les valeurs à regrouper
- L’intervalle des groupes
- Le nom de la nouvelle colonne contenant le début de chaque intervalle
- Le nom de la nouvelle colonne contenant la fin de chaque intervalle

Ici, nous regroupons les valeurs de `year` en périodes de 30 ans et stockons leurs limites dans deux nouvelles colonnes nommées `yearStart` et `yearEnd`.

```ts showLineNumbers filename="main.ts" {27}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB({ cacheVerbose: true });

const temperatures = sdb.newTable("temperatures");

await temperatures.cache(() => {
  temperatures
    .loadData(
      "https://raw.githubusercontent.com/nshiab/simple-data-analysis/refs/heads/main/test/data/files/dailyTemperatures.csv",
    )
    .removeMissing();
});

const cities = sdb.newTable("cities");

await cities.cache(() => {
  cities
    .loadData(
      "https://raw.githubusercontent.com/nshiab/simple-data-analysis-core/refs/heads/main/test/data/files/cities.csv",
    );
});

await temperatures
  .join(cities)
  .extractDatePart("time", "year")
  .bins("year", 30, "yearStart", "yearEnd")
  .log();

await sdb.close();
```

C'est parfait !

![Capture d’écran montrant les colonnes yearStart et yearEnd créées par la méthode bins.](/assets/simple-data-analysis/tabular-data/bins.png)

Vérifions rapidement les intervalles créés. Nous sélectionnons uniquement les colonnes `yearStart` et `yearEnd` (ligne 28), supprimons les lignes en double afin que chaque intervalle n’apparaisse qu’une fois (ligne 29), puis trions le résultat pour le vérifier plus facilement (ligne 30).

Ce code sert uniquement à cette vérification rapide. Nous supprimerons donc ces trois lignes par la suite.

```ts showLineNumbers filename="main.ts" {28-30}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB({ cacheVerbose: true });

const temperatures = sdb.newTable("temperatures");

await temperatures.cache(() => {
  temperatures
    .loadData(
      "https://raw.githubusercontent.com/nshiab/simple-data-analysis/refs/heads/main/test/data/files/dailyTemperatures.csv",
    )
    .removeMissing();
});

const cities = sdb.newTable("cities");

await cities.cache(() => {
  cities
    .loadData(
      "https://raw.githubusercontent.com/nshiab/simple-data-analysis-core/refs/heads/main/test/data/files/cities.csv",
    );
});

await temperatures
  .join(cities)
  .extractDatePart("time", "year")
  .bins("year", 30, "yearStart", "yearEnd")
  .selectColumns(["yearStart", "yearEnd"])
  .removeDuplicates()
  .sort()
  .log();

await sdb.close();
```

Tout semble parfait, et les intervalles sont cohérents. L’intervalle 2020–2050 sera bien sûr incomplet, mais nous nous en occuperons plus tard.

![Capture d’écran montrant les intervalles uniques de 30 ans triés par année.](/assets/simple-data-analysis/tabular-data/bins-unique.png)

## Résumer et filtrer les données

Maintenant que nos températures quotidiennes sont bien regroupées en intervalles, nous pouvons facilement calculer la température moyenne par période de 30 ans pour chaque ville.

Utilisons à nouveau la méthode `.summarize()`. Mais cette fois, nous allons utiliser plus d'options :

- Les valeurs restent nos températures dans la colonne `t`.
- Nous regroupons les valeurs par `city` ainsi que par les colonnes `yearStart` et `yearEnd` qui définissent chaque intervalle.
- Nous voulons calculer la `mean` et un `count` des valeurs pour chaque ville et chaque intervalle.
- Nous arrondissons les valeurs à deux décimales.

De plus, la table contient maintenant 15 lignes, mais par défaut, `.log()` n'affiche que les 10 premières. Nous allons donc lui demander d'en afficher 15 pour mieux voir le résultat.


```ts showLineNumbers filename="main.ts" {28-33} /15/
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB({ cacheVerbose: true });

const temperatures = sdb.newTable("temperatures");

await temperatures.cache(() => {
  temperatures
    .loadData(
      "https://raw.githubusercontent.com/nshiab/simple-data-analysis/refs/heads/main/test/data/files/dailyTemperatures.csv",
    )
    .removeMissing();
});

const cities = sdb.newTable("cities");

await cities.cache(() => {
  cities
    .loadData(
      "https://raw.githubusercontent.com/nshiab/simple-data-analysis-core/refs/heads/main/test/data/files/cities.csv",
    );
});

await temperatures
  .join(cities)
  .extractDatePart("time", "year")
  .bins("year", 30, "yearStart", "yearEnd")
  .summarize({
    columns: "t",
    by: ["city", "yearStart", "yearEnd"],
    stats: ["count", "mean"],
    decimals: 2,
  })
  .log(15);

await sdb.close();
```

Voilà qui est intéressant... Grâce à la colonne `count`, nous pouvons clairement voir où il manque des données.

Bien sûr, les intervalles dont le `yearStart` est 2020 et le `yearEnd` est 2050 sont incomplets, mais c’est aussi le cas de l’intervalle de `MONTREAL` dont le `yearStart` est 1990 et le `yearEnd` est 2020. Théoriquement, chaque intervalle de 30 ans devrait contenir environ 10 957 jours.

![Capture d’écran montrant la méthode summary en action.](/assets/simple-data-analysis/tabular-data/summary.png)

Nous pourrions exclure les intervalles qui ont moins de 90 % du nombre de jours attendu. Notre seuil serait donc de 9 861 jours.

Pour cela, utilisons la méthode `.filter()`, qui prend une expression SQL comme condition. Comme vous pouvez le voir ci-dessous, c’est très simple.


```ts showLineNumbers filename="main.ts" {34}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB({ cacheVerbose: true });

const temperatures = sdb.newTable("temperatures");

await temperatures.cache(() => {
  temperatures
    .loadData(
      "https://raw.githubusercontent.com/nshiab/simple-data-analysis/refs/heads/main/test/data/files/dailyTemperatures.csv",
    )
    .removeMissing();
});

const cities = sdb.newTable("cities");

await cities.cache(() => {
  cities
    .loadData(
      "https://raw.githubusercontent.com/nshiab/simple-data-analysis-core/refs/heads/main/test/data/files/cities.csv",
    );
});

await temperatures
  .join(cities)
  .extractDatePart("time", "year")
  .bins("year", 30, "yearStart", "yearEnd")
  .summarize({
    columns: "t",
    by: ["city", "yearStart", "yearEnd"],
    stats: ["count", "mean"],
    decimals: 2,
  })
  .filter(`count >= 9861`)
  .log(15);

await sdb.close();
```
<Callout type="info" emoji="💡">
    La méthode `.filter()` et quelques autres méthodes de SDA attendent des expressions SQL. Ci-dessus, `count >= 9861` signifie « conserver les lignes où `count` est supérieur ou égal à 9 861 ». SQL signifie *Structured Query Language*, un langage pour travailler avec des bases de données. Avec SDA, nous n’aurons besoin que des bases, et nous les apprendrons au fur et à mesure.

    J’aime écrire les expressions SQL entre des *backticks* pour les reconnaître rapidement, mais les guillemets simples ou doubles fonctionnent aussi : ces méthodes attendent simplement une chaîne de caractères. Les *backticks* permettent aussi d’utiliser des *template literals* pour insérer des variables dans les expressions, ce qui peut être pratique, comme nous le verrons plus tard.
</Callout>

Avant le filtrage, la table contenait 15 lignes. Il n’en reste maintenant que 11.

### Visualisation avec Plot

Les visualisations dans le terminal sont assez limitées. Si vous voulez créer des graphiques plus élaborés, vous pouvez utiliser [Observable Plot](https://github.com/observablehq/plot), qui a été installé lors de la configuration avec [setup-data-project](https://github.com/nshiab/setup-data-project).

Nous ferons une leçon complète sur Plot plus tard. Cela peut sembler compliqué pour l’instant, mais une fois que vous aurez assimilé les bases, vous verrez que c'est une librairie de visualisation de données exceptionnelle.

Dans l’exemple ci-dessous, nous écrivons un graphique sous forme de fichier PNG dans notre dossier `./sda/output`.

```ts showLineNumbers filename="main.ts" {2, 34, 36-65}

import { dot, line, plot } from "@observablehq/plot";

const sdb = new SimpleDB({ cacheVerbose: true });

const temperatures = sdb.newTable("temperatures");

  temperatures
    .loadData(

    )
    .removeMissing();
});

const cities = sdb.newTable("cities");
await cities.cache(() => {
  cities
    .loadData(
      "https://raw.githubusercontent.com/nshiab/simple-data-analysis-core/refs/heads/main/test/data/files/cities.csv",
    );
});

await temperatures
  .join(cities)
  .extractDatePart("time", "year")
  .bins("year", 30, "yearStart", "yearEnd")
  .summarize({
    columns: "t",
    by: ["city", "yearStart", "yearEnd"],
    stats: ["count", "mean"],
    decimals: 2,
  })
  .filter(`count >= 9861`)
  .log("all");

await temperatures.writeChart((data) =>
  plot({
    inset: 20,
    marginLeft: 50,
    marginBottom: 40,
    grid: true,
    y: { tickFormat: (d) => `${d}°C`, label: "Temperature", ticks: 5 },
    x: {
      tickFormat: (d) => `${d}-${d + 29}`,
      ticks: [1900, 1930, 1960, 1990],

    color: { legend: true },
    marks: [
      line(data, {
        x: "yearStart",
        y: "mean",
```

Avec ce nouveau graphique, il est assez clair que les températures ont augmenté dans les trois villes analysées. Bien sûr, nous avons exclu la période complète de 30 ans la plus récente pour Montréal, car elle ne contenait pas suffisamment de données. 📈

### Corrélations et régressions linéaires

Les visualisations sont utiles, mais leur interprétation peut être subjective.

Pour analyser les tendances, vous pouvez aussi vous appuyer sur des indicateurs statistiques comme les corrélations et les régressions linéaires. Si vous souhaitez en savoir plus sur ces concepts, consultez la leçon [**Maths pour les journalistes**](/ninja-moves/math-for-journalists).

Commençons par les corrélations. Notez que j’ai supprimé le code générant le graphique.

```ts showLineNumbers filename="main.ts" {37-44}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB({ cacheVerbose: true });

const temperatures = sdb.newTable("temperatures");

await temperatures.cache(() => {
  temperatures
    .loadData(
      "https://raw.githubusercontent.com/nshiab/simple-data-analysis/refs/heads/main/test/data/files/dailyTemperatures.csv",
    )
    .removeMissing();
});

const cities = sdb.newTable("cities");

await cities.cache(() => {
  cities
    .loadData(
      "https://raw.githubusercontent.com/nshiab/simple-data-analysis-core/refs/heads/main/test/data/files/cities.csv",
    );
});

await temperatures
  .join(cities)
  .extractDatePart("time", "year")
  .bins("year", 30, "yearStart", "yearEnd")
  .summarize({
    columns: "t",
    by: ["city", "yearStart", "yearEnd"],
    stats: ["count", "mean"],
    decimals: 2,
  })
  .filter(`count >= 9861`)
  .log("all");

await temperatures
  .correlations({
    x: "yearStart",
    y: "mean",
    by: "city",
    outputTable: "correlations",
  })
  .log();

await sdb.close();
```

Comme `.summarize()`, la méthode `.correlations()` remplace les données de la table par les résultats de ses calculs. Dans le code ci-dessus, pour éviter d’écraser la table `temperatures`, nous définissons `outputTable: "correlations"`. Cela crée une nouvelle table nommée `correlations` et conserve intactes les données de `temperatures`.

Comme nous pouvons le voir, les corrélations sont proches de 1, ce qui signifie qu'il existe une forte relation entre les années et la température. Quand l'une augmente, l'autre aussi.

![Capture d’écran montrant comment calculer les corrélations.](/assets/simple-data-analysis/tabular-data/correlation.png)

Nous pouvons également calculer des régressions linéaires, qui sont plus descriptives. Ici, nous remplaçons `.correlations()` par `.linearRegressions()`, arrondissons les résultats à deux décimales et les stockons dans une nouvelle table nommée `linearRegressions`.

```ts showLineNumbers filename="main.ts" {37-45}

const sdb = new SimpleDB({ cacheVerbose: true });

const temperatures = sdb.newTable("temperatures");

await temperatures.cache(() => {
  temperatures
    .loadData(
      "https://raw.githubusercontent.com/nshiab/simple-data-analysis/refs/heads/main/test/data/files/dailyTemperatures.csv",
    )
    .removeMissing();
});

const cities = sdb.newTable("cities");

await cities.cache(() => {
  cities
    .loadData(
      "https://raw.githubusercontent.com/nshiab/simple-data-analysis-core/refs/heads/main/test/data/files/cities.csv",
    );
});

await temperatures
  .join(cities)
  .extractDatePart("time", "year")
  .bins("year", 30, "yearStart", "yearEnd")
  .summarize({

    by: ["city", "yearStart", "yearEnd"],
    stats: ["count", "mean"],
    decimals: 2,
  })
  .filter(`count >= 9861`)
  .log("all");

await temperatures
  .linearRegressions({
    x: "yearStart",
    y: "mean",
    by: "city",
    decimals: 2,
    outputTable: "linearRegressions",
  })
  .log();

await sdb.close();
```

Encore une fois, le r<sup>2</sup> est proche de 1, ce qui signifie que les deux variables sont liées. La *slope* nous indique aussi que la température a augmenté de 0,02°C par an en moyenne.

Ces trois villes canadiennes se sont réchauffées ! 🌡️🌡️🌡️

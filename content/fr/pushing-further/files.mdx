# Écrire et lire des fichiers

Lorsque vous exécutez votre code, tout est stocké dans la RAM (mémoire vive) de votre ordinateur. Ce type de mémoire est très rapide, mais si vous arrêtez votre script ou éteignez votre ordinateur, tout est perdu. 😱

Si vous voulez conserver certaines données, vous devez les écrire dans un fichier, qui sera stocké dans la mémoire permanente de votre ordinateur (disque dur). Et pour récupérer les données d’un fichier, vous devez les lire.

<NoticeIntro lang="fr"/>

## Configuration

Préparons notre environnement de travail pour cette leçon.

Créez un nouveau projet avec `npx @nshiab/setup-data-project`, en suivant la [leçon de configuration](/first-steps/setup). Pour cette leçon, ne sélectionnez aucune bibliothèque facultative. Ouvrez le dossier du projet généré dans VS Code et utilisez le fichier `sda/main.ts` pour votre code.

Ouvrez le terminal (`CMD` + `J` sur Mac ou `CTRL` + `J` sur Windows) et exécutez `npm run sda` depuis la racine du projet, le dossier contenant `package.json`.

Cette commande réexécute votre code chaque fois que vous le sauvegardez (`CMD` + `S` sur Mac ou `CTRL` + `S` sur PC). Pour l’arrêter, appuyez sur `CTRL` + `C` sur les deux systèmes.

Node.js exécute TypeScript sans vérifier les types. Utilisez `npm run all-tests` pour vérifier le projet et `npm run fix` pour appliquer la mise en forme et les corrections automatiques, comme expliqué dans la leçon de configuration.

Vous pouvez utiliser cette configuration pour tester le code fourni dans cette leçon.

## Écrire

Avec Node.js, écrire des fichiers est très facile. Importez la fonction `writeFile` du module intégré `node:fs/promises`. Vous n’avez rien à installer : ce module est fourni avec Node.js.

Pour un fichier texte, passez un chemin d’accès comme premier paramètre et du texte comme deuxième paramètre. Dans le code ci-dessous, nous voulons créer un fichier nommé `hello.txt` contenant `"Hello!"`.

Le `./` indique un chemin relatif : il pointe vers le dossier où nous exécutons le script, la racine du projet contenant `package.json`. Pour les imports, en revanche, les chemins relatifs partent du fichier qui importe, ici `sda/main.ts`.

Copiez, collez et sauvegardez ce code dans `sda/main.ts`. Nous parlerons du mot-clé `await` dans un instant.

```ts showLineNumbers filename="sda/main.ts"
import { writeFile } from "node:fs/promises";

await writeFile("./hello.txt", "Hello!");
```

Un nouveau fichier texte a été créé avec son contenu. Vous savez désormais comment stocker des données de façon permanente sur votre ordinateur !

Au fait, soyez prudent : par défaut, `writeFile` écrase les fichiers s'ils existent déjà.

## Lire

Pour lire des fichiers, importez `readFile` du même module. Passez un chemin d’accès et l’encodage `"utf8"` pour obtenir le contenu sous forme de texte. Sans cet encodage, Node.js renvoie un `Buffer`, qui représente les octets bruts.

Mettons à jour `sda/main.ts` pour lire le fichier que nous avons écrit plus tôt.

```ts showLineNumbers filename="sda/main.ts"
import { readFile } from "node:fs/promises";

const data = await readFile("./hello.txt", "utf8");
console.log(data);
```

Vous avez réussi à récupérer le contenu texte du fichier `hello.txt` !

## JSON

Écrire des données sous forme de texte est assez standard. Par exemple, les fichiers CSV sont simplement des fichiers texte avec des virgules représentant les colonnes.

Cependant, en travaillant avec TypeScript, en particulier pour le Web, vous écrirez souvent vos données sous forme de fichiers **JSON**. JSON signifie *JavaScript Object Notation*, et comme TypeScript est basé sur le JavaScript, c'est un choix naturel.

Ce format de fichier texte peut stocker des listes, des objets, du texte, des nombres et des booléens, au lieu de simples textes bruts.

Par exemple, dans le script ci-dessous, nous écrivons la liste d'objets `data` dans le fichier `data.json`.


```ts showLineNumbers filename="sda/main.ts"
import { writeFile } from "node:fs/promises";

const data = [
  { name: "Nael", age: 25 },
  { name: "John", age: 30 },
];

await writeFile(
  "data.json",
  JSON.stringify(data),
);
```
<Callout type="info" emoji="💡">
    Nous avons utilisé l'objet global `JSON`, qui est toujours disponible lorsque vous codez, et sa méthode `stringify()`. Ici, `writeFile` attend du texte plutôt qu’une liste, mais `data` est une liste d'objets. Nous utilisons donc **stringify** pour transformer `data` en texte JSON. La méthode complémentaire est `JSON.parse()`, qui rend leur forme originale à des listes, objets et valeurs qui ont été transformés en texte JSON.
</Callout>

<OutdatedScreenshot src="/assets/pushing-further/files/json-write.png" alt={"Une capture d'écran montrant VS Code écrivant un fichier JSON avec Deno."} lang="fr" />

Comme le fichier a l'extension `.json`, il est compris par VS Code et Node.js. Son contenu est affiché avec les types de données appropriés. Dans l’éditeur, les noms sont mis en évidence comme du texte et les âges comme des nombres. Si nous avions tout écrit dans un fichier `.txt`, tout apparaîtrait comme du texte brut.

De plus, vous pouvez importer un fichier JSON en ajoutant l’attribut d’importation `with { type: "json" }`. Les paramètres TypeScript du projet généré prennent en charge les imports JSON et permettent à l’éditeur d’en déduire les types. L’import ci-dessous utilise `../data.json` parce qu’il part de `sda`, puis remonte à la racine du projet.

```ts showLineNumbers filename="sda/main.ts"
import data from "../data.json" with { type: "json" };

console.log(data);
```
<OutdatedScreenshot src="/assets/pushing-further/files/json-read.png" alt={"Une capture d'écran montrant VS Code lisant un fichier JSON avec Deno."} lang="fr" />

VS Code et `npm run all-tests` peuvent vérifier les types des données importées, ce qui est formidable. Node.js ne vérifie toujours pas les types quand il exécute le code.

Si vous ajoutez un `.` après `data`, VS Code suggérera des méthodes pour les listes car il sait que les données stockées dans `data.json` sont une liste.

<OutdatedScreenshot src="/assets/pushing-further/files/json-array-methods.png" alt={"Une capture d'écran montrant VS Code suggérant des méthodes pour les tableaux."} lang="fr" />

Si vous sélectionnez le premier objet de `data` avec `[0]` et tapez un `.` pour accéder à une clé, VS Code vous proposera les clés présentes dans l'objet. Comme c'est un fichier JSON, il peut inférer les types.

<OutdatedScreenshot src="/assets/pushing-further/files/json-object-methods.png" alt={"Une capture d'écran montrant VS Code lisant un fichier JSON avec Deno."} lang="fr" />

Et si vous essayez d’accéder à des clés qui n’existent pas dans les objets, VS Code et les vérifications du projet signalent une erreur. N'est-ce pas incroyable ? 😍

<OutdatedScreenshot src="/assets/pushing-further/files/json-object-error.png" alt={"Une capture d'écran montrant VS Code lisant un fichier JSON avec Deno."} lang="fr" />

Parfois, vous ne pouvez pas ou ne voulez pas utiliser la syntaxe `import` pour un fichier JSON. Vous pouvez alors le lire avec `readFile()` et l’encodage `"utf8"`. Cependant, cette méthode renvoie une chaîne de caractères : le contenu du fichier sous forme de texte.

```ts showLineNumbers filename="sda/main.ts"
import { readFile } from "node:fs/promises";

const rawData = await readFile("./data.json", "utf8");
console.log(rawData);
```

<OutdatedScreenshot src="/assets/pushing-further/files/json-raw-data.png" alt={"VS Code affichant le contenu du fichier JSON sous forme de texte brut."} lang="fr" />

Pour transformer ce texte en tableau ou en objet, utilisez `JSON.parse()`.

```ts showLineNumbers filename="sda/main.ts" {4} /data/3
import { readFile } from "node:fs/promises";

const rawData = await readFile("./data.json", "utf8");
const data = JSON.parse(rawData);
console.log(data);
```

<OutdatedScreenshot src="/assets/pushing-further/files/json-parsed-data.png" alt={"VS Code affichant le tableau d’objets après la conversion du texte JSON."} lang="fr" />

## À propos de `await`

Il existe deux types de fonctions et de méthodes : **synchrones** et **asynchrones**.

Dans la [leçon sur les fonctions](/pushing-further/functions), nous avons écrit des fonctions synchrones. Vous n'aviez pas besoin d'ajouter `await` devant elles.

Lorsque votre ordinateur rencontre une fonction, une méthode ou une instruction **synchrone**, il **attend** que tout soit terminé avant de passer à la suivante. Cela fonctionne comme attendu : la ligne 1 de votre code est exécutée, puis la ligne 2, puis la ligne 3, et ainsi de suite.

Cependant, lorsque votre ordinateur rencontre une fonction ou une méthode **asynchrone**, il commence à l'exécuter *en arrière-plan* mais **n'attend pas** qu'elle soit terminée. Pendant que la tâche s'exécute *en arrière-plan*, il passe immédiatement à l'instruction suivante. L'*arrière-plan* est une simplification de ce qui se passe vraiment, mais vous comprenez le concept.

Puisque `writeFile` et `readFile` sont asynchrones, cela signifie que vous pouvez écrire ou lire plusieurs fichiers **concurremment**, ce qui peut considérablement accélérer le temps de traitement de votre script (si utilisé correctement 🧑‍🔬).

Cette fonctionnalité est également formidable pour le développement web. Par exemple, un site avec plusieurs images peut récupérer toutes les images en même temps au lieu de les charger une par une, ce qui améliore la vitesse et l'expérience utilisateur.

Dans notre contexte, il est plus simple d'ajouter le mot-clé `await` pour que l'ordinateur traite le code dans l'ordre affiché.

Pour identifier une fonction ou une méthode asynchrone, survolez-la. Les fonctions asynchrones retournent une promesse (`Promise`). La vérification des types peut détecter de nombreux cas où vous utilisez une `Promise` comme si elle était le résultat final, mais elle ne signale pas tous les oublis de `await`. Pensez à attendre la fin d’une opération avant d’utiliser son résultat.

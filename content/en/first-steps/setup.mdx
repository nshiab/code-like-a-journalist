## Code editor

Code is just text. You can write your code in any text editor, but it's more convenient to use a code editor that comes with many useful features.

You have many free and interesting options, but the most popular is [Visual Studio Code](https://code.visualstudio.com/), and it's the one we will use. It's an [open-source project](https://github.com/microsoft/vscode) maintained by Microsoft.

Download it from the [website](https://code.visualstudio.com/) and install it.

Once installed, open it. It should look like this. It's okay if you have different tabs open.

## Runtime

To execute our TypeScript code, we need a runtime. We will use [Node.js](https://nodejs.org/), a free, open-source runtime with a large ecosystem of tools for working with data.

For this course, install **the latest LTS version of Node.js**. LTS stands for *Long-Term Support*. The LTS version is a good choice for the tools and data libraries we will use throughout this course.

Visit the [Node.js download page](https://nodejs.org/en/download), select the latest LTS version and your operating system, and follow the installation instructions. On Windows and Mac, you can use the installer provided on that page. On Linux, follow the instructions for your distribution. The installation should include **npm**, the package manager we will use to download tools and libraries.

Quit and restart VS Code after installing Node.js. Open the terminal (`View => Terminal`, or `CMD` + `J` on Mac and `CTRL` + `J` on Windows), and run these commands one at a time:

```sh
node --version
npm --version
```

The first command should display the Node.js version you just installed. The second should display an npm version number. If either command is not found, check that installation completed, then restart VS Code again.

Other runtimes, including [Bun](https://bun.sh/), can also run TypeScript, and `setup-data-project` supports Bun too. We'll use Node.js and npm for all the examples in this course.

## Set up a project

We will use [@nshiab/setup-data-project](https://github.com/nshiab/setup-data-project), an open-source tool I created, to prepare our projects. It installs and configures TypeScript, formatting, and the tools that check our code. This lets us get straight to learning the language.

First, create a new, empty folder somewhere handy on your computer. In VS Code, click on the Explorer tab, click `Open Folder`, and select that folder. If you are asked whether you trust the authors of the files, say "Yes" for this project you just created.

![A screenshot showing how to open a new folder in VS Code.](/assets/first-steps/setup/deno-open-folder.png)

Open the terminal (`View => Terminal`, or `CMD` + `J` on Mac and `CTRL` + `J` on Windows). It should open in your new folder. Run:

```sh
npx @nshiab/setup-data-project
```

`npx` downloads and runs a tool from npm. If npm asks whether to install `@nshiab/setup-data-project`, type `y` and press Enter.

When the tool asks which libraries to install, **leave everything unselected and press Enter**. We don't need a data library to learn TypeScript fundamentals. We'll select libraries later when we start analyzing data.

Wait until setup finishes and displays `You are all set!`. It may take a few minutes to download and install the tools.

<OutdatedScreenshot src="/assets/first-steps/setup/deno-extension.png" alt={"A screenshot showing how to install Deno extension."} lang="en" />

Several files and folders will appear in the Explorer. Here are the ones you need to recognize for now:

- `sda/main.ts` is where we will write our code. `sda` is a folder, and `main.ts` is a file inside it. The `.ts` extension identifies a TypeScript file.
- `package.json` describes the project, its dependencies, and the commands we will run with npm.
- `package-lock.json` records the installed package versions so the project can be installed consistently.
- `node_modules` holds the downloaded tools and libraries. You won't need to edit it.
- `tsconfig.json`, `vite.config.ts`, and `.vscode` contain settings prepared by the tool. Keep them in place.

Don't worry if this looks like a lot. The setup tool has done the configuration for us. Most of the time, we will work in `sda/main.ts`.

## Editor settings

The project includes recommended VS Code extensions. When VS Code offers to install them, accept the recommendation for the **Vite+ extension pack**, published by **VoidZero**. You can also open the Extensions tab and search for `@recommended`, or search for `VoidZero.vite-plus-extension-pack` directly.

This pack provides the formatting and code checks configured by the project. The generated VS Code settings enable formatting when you save a file and word wrap for long lines. You don't need to configure a separate formatter.

If you previously installed the Deno extension, disable it for this workspace so it doesn't interfere with the project's TypeScript tools.

## Let's run a script

In the Explorer, expand the `sda` folder and open `main.ts`. Replace its contents with:

```ts filename="sda/main.ts"
console.log("This is going to be fun!");
```

This code tells your computer to log *This is going to be fun!* in your terminal.

Save the file by pressing `CMD` + `S` on Mac or `CTRL` + `S` on Windows. A dot in the file's tab indicates unsaved changes. Always save before expecting your changes to run.

In the terminal, from the project folder that contains `package.json`, run:

```sh
npm run sda
```

This runs the project's `sda` command, which starts Node.js and executes `sda/main.ts`. You should see *This is going to be fun!* in your terminal.

The command keeps watching your script: each time you save a change, Node.js runs it again. Try changing the message and saving! To stop the watcher, click in the terminal and press `CTRL` + `C` on Mac or Windows.

## Check and format your code

Node.js can [run TypeScript files directly](https://nodejs.org/docs/latest-v24.x/api/typescript.html) by removing their type annotations before execution. **It does not check the types.** Watching the script only reruns it; a script can run and still contain TypeScript mistakes.

The setup tool installs and configures these checks for us. VS Code can flag mistakes as we type, and this command checks the whole project:

```sh
npm run all-tests
```

It checks formatting, lint rules, and TypeScript types, then runs any automated tests in the project. We will learn about tests later. For now, read any reported errors and fix them before trusting your results. A successful check helps, but you still need to verify your data and logic!

If `npm run sda` is still watching in your terminal, use the `+` button in the terminal panel to open a second terminal for the checks, or stop the watcher with `CTRL` + `C` first.

To format the project and apply fixes the tools can make automatically, run:

```sh
npm run fix
```

This can change your files. Review the changes, then run `npm run all-tests` again. Errors in your types or logic may need a fix from you.

For each new lesson, you can keep using this project and replace the contents of `sda/main.ts`. If you prefer a separate project, create a new empty folder, open it with VS Code, and run `npx @nshiab/setup-data-project` again with no libraries selected.

## About AI

You may have noticed that we haven’t installed any AI-powered tools, such as [GitHub Copilot](https://github.com/features/copilot).

These tools are increasingly popular for coding tasks and can significantly boost productivity. However, they are not without flaws. They can introduce errors and bugs.

For experienced coders, this isn’t a big issue. When you know what you’re doing, you can easily review and refine the AI's output.

For beginners, though, it’s better to hold off. Master the basics first, and once you have a solid foundation, you’ll be in a much better position to benefit from these tools.

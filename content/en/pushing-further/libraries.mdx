# Using libraries

Millions of people around the world work with JavaScript and TypeScript. Part of the reason for their popularity is the vast ecosystem of libraries. Many developers share their code publicly, making it free for anyone to use.

In later lessons, we will use open-source libraries to analyze huge datasets and create stunning visualizations.

A note about vocabulary: *libraries* are also often called *packages* or *modules*.

<NoticeIntro />

Now, let's set up before diving into this lesson.

Open a new empty folder in VS Code and create `main.ts` inside it, as in the [setup lesson](/first-steps/setup).

Open the terminal (`CMD` + `J` on Mac or `CTRL` + `J` on Windows) and run `node --watch main.ts` from that folder. This reruns your code when you save. Stop it with `CTRL` + `C` on either system.

VS Code highlights TypeScript errors as you type and formats your code when you save.

You can use this setup to test the code provided in this lesson.

## The npm registry

Libraries are published on public registries. In this course, we’ll install them from [npm](https://www.npmjs.com/), the registry used by the npm command that comes with Node.js. Package pages include documentation, maintainers, versions, and download counts to help you choose a library.

As an example, let’s search for `d3`, a well-known library for data visualization that we will use frequently.

Go to [npmjs.com](https://www.npmjs.com/) and search for `d3`.

![A screenshot showing NPM results for d3.](/assets/pushing-further/libraries/d3-npm.png)

Select the first result: `d3` with the description **"Data-Driven Documents"** by Mike Bostock.

Here’s [the direct link](https://www.npmjs.com/package/d3), just in case.

![A screenshot showing NPM description for d3.](/assets/pushing-further/libraries/d3-description.png)

This page provides a lot of useful information:
- In the main section, we see a short description and links to documentation, examples, and more.
- On the right-hand side, there’s a link to the GitHub repository and the library’s website.
- We can see the number of weekly downloads, indicating the library’s popularity.
- The list of maintainers includes **Mike Bostock** and **Philippe Rivière**, both well-known experts in data visualization.

These details (along with the GitHub repository) help us decide whether a library is trustworthy. Always be cautious before running unknown code! 🦠

Before installing a library, let's create a `package.json` file to keep track of our project and its libraries. Stop the watcher with `CTRL` + `C`, then run these commands in the project folder:

```sh
npm init -y
npm pkg set type=module
```

`npm` comes with Node.js. The first command creates `package.json`; the second tells Node.js that our project uses `import` and `export`. If this folder already has a `package.json`, skip `npm init -y` and keep its existing contents.

Installing `d3` is very easy. Click on your terminal, stop watching your code (`CTRL` + `C`), and run these commands from the project root:

```sh
npm install d3
npm install --save-dev @types/d3
```

The first command installs the library. The second installs its TypeScript type definitions, so VS Code understands its functions. Some libraries include their own types; `d3` uses a separate `@types/d3` package.

Open `package.json`: `d3` is now listed in **dependencies**, and `@types/d3` in **devDependencies**. Dependencies are packages your code uses; development dependencies support tools such as type checking.

npm also updates `package-lock.json`, which records the exact versions installed, and puts the packages in a `node_modules` folder. Keep `package.json` and `package-lock.json` with your project. If you share the code, others can run `npm ci` to install the versions recorded in the lockfile.

<Callout type="info" emoji="💡">
    You don’t need to edit files inside `node_modules` or manage npm’s download cache yourself. npm handles installation. Use `npm install` when adding a library and import it by its package name, such as `"d3"`.

Let's reuse the [Montreal temperature CSV file](https://raw.githubusercontent.com/nshiab/data-fetch-lesson/refs/heads/main/temp.csv) from the [Fetching data lesson](/pushing-further/fetch).

If you fetch this data, you'll notice it's just text. CSV stands for **Comma-Separated Values**. You can't work with it directly. It would be much better to convert it into an array of objects.

Copy and paste the code below into `main.ts`, then run: `node --watch main.ts`

```ts showLineNumbers filename="main.ts"
const response = await fetch(
  "https://raw.githubusercontent.com/nshiab/data-fetch-lesson/refs/heads/main/temp.csv",
);

const data = await response.text();

console.log(data);
```

<OutdatedScreenshot src="/assets/pushing-further/libraries/d3-text.png" alt={"A screenshot showing CSV data in the terminal."} lang="en" />

It’s our lucky day: the `d3` function `csvParse` converts CSV data into an array of objects!

Let’s update our code to use it.

```ts showLineNumbers filename="main.ts" {1, 8, 10}
import { csvParse } from "d3";

const response = await fetch(
  "https://raw.githubusercontent.com/nshiab/data-fetch-lesson/refs/heads/main/temp.csv",
);

const data = await response.text();
const arrayOfObjects = csvParse(data);

console.log(arrayOfObjects);
```
<OutdatedScreenshot src="/assets/pushing-further/libraries/d3-parse.png" alt={"A screenshot showing CSV data converted to an array of objects in the terminal."} lang="en" />

<Callout type="info" emoji="💡">
    In the [Functions lesson](/pushing-further/functions), we saw that we can import functions with the syntax `import myFunction from "./myFunction.ts"`. Here, it's a bit different because `d3` exports more than one function, and we pick just the one(s) we want. To do this, we use curly brackets with this syntax: `import { myFunctionA, myFunctionB } from "./allMyFunctions.ts"`.
</Callout>

Congrats! You just installed `d3` from NPM and used one of its functions! 💃🕺

## Another library: csv-parse

There’s often more than one library that can solve the same problem. Let’s try [`csv-parse`](https://csv.js.org/parse/), a library dedicated to parsing CSV files. Its documentation describes the available APIs, options, examples, and a link to its source code.

Stop the running script with `CTRL` + `C`, then install it:

```sh
npm install csv-parse
```

This package includes its own TypeScript types, so no separate `@types` package is needed.

We’ll use the [synchronous API](https://csv.js.org/parse/api/sync/), which is convenient when the whole CSV fits in memory. Import `parse` from `"csv-parse/sync"`. The [`columns: true` option](https://csv.js.org/parse/options/columns/) uses the first row as property names instead of returning it as a data row.

Replace the code in `main.ts` with this, then run `node --watch main.ts` again:

```ts showLineNumbers filename="main.ts" {1, 8}
import { parse } from "csv-parse/sync";

const response = await fetch(
  "https://raw.githubusercontent.com/nshiab/data-fetch-lesson/refs/heads/main/temp.csv",
);

const data = await response.text();
const arrayOfObjects = parse(data, { columns: true });

console.log(arrayOfObjects);
```

Like `csvParse`, this turns the text into an array of objects. By default, the field values remain strings, so convert numeric fields before doing calculations.

# Variables

Let's start your first TypeScript lesson with variables! Along the way, I'll show you some tips and tricks for working with TypeScript, VS Code, and Node.js.

Note that I assume you've completed the [Setup lesson](/first-steps/setup) before diving into this one.

<NoticeIntro/>

## Setup

Create a new, empty folder on your computer, open it with VS Code, and create a file named `main.ts` inside it.

Type this code in `main.ts` and save the file:

```ts showLineNumbers filename="main.ts"
console.log("Hello!");
```

Open the terminal (`Command` + `J` on Mac or `Control` + `J` on Windows) and run this command:

```sh
node --watch main.ts
```

This runs our code and automatically runs it again each time we save a change, so we can see the results as we work.

![VS Code showing console.log("Hello!") in main.ts and Hello! in the terminal running node --watch main.ts.](/assets/first-steps/variables/run.png)

<Callout type="info" emoji="💡">
    You may have noticed that your code is written with multiple colors. This is called *code highlighting*. In code, each word has a different role and is assigned a color. For example, here `console` is an object, and `log` is one of its methods. Also, while typing, you may see auto-complete suggestions and pop-ups. This is called *IntelliSense*. It's your editor trying to guess what you might want to write and providing documentation for you. For now, you can ignore this, but we will make great use of it later.
</Callout>

## Watch mode

Let's see how watch mode helps us work.

The `node --watch main.ts` command already starts Node.js in watch mode: it automatically reruns our code anytime we save a change. This only reruns the script; it does not check TypeScript types.

If the command is still running, leave it there. Otherwise, run `node --watch main.ts` again. Now, replace your line of code with `console.log(2 + 4);` and save your file (`CMD` + `S` on Mac or `CTRL` + `S` on PC).

Node.js will rerun `main.ts` every time you save it. Very convenient!

VS Code checks TypeScript types as you type. Hover over a red squiggle to read the error message. Node.js itself runs the code without checking types.

If you want to stop watching, click in the terminal and press `CTRL` + `C` (it should be the same on Mac and PC). But we will keep it watching for the rest of the lesson.

## Variables with `const`

Now, let's add variables to our code.

Variables are like containers. You can put stuff in them, and when you reference them, Node.js will look at what's inside and use it. This is very convenient because you can reuse the same variable throughout your code.

Let's modify our code to put the first number in the variable `a` and the second number in `b`. We'll also store the result of the calculation in the variable `c`. Copy the code below and paste it into your `main.ts`.

```ts showLineNumbers filename="main.ts"
const a = 2;
const b = 4;
const c = a + b;
console.log(c);
```

<Callout type="info" emoji="💡">
    Have you noticed all the semicolons? They mark the end of statements. VS Code formats your code when you save, but get into the habit of writing them explicitly in your examples.
</Callout>

Your computer will run this code from top to bottom. Line 1 will execute, then line 2, and so on.

<OutdatedScreenshot src="/assets/first-steps/variables/const-variables.png" alt={"VS Code showing variables a, b, and c and the result 6 in the terminal."} lang="en" />

If you save, you'll notice that the result in the terminal is the same. But there is a big difference in your code: you are using variables!

`c` is the result of the sum of `a` and `b`, so if you change `a` to `3`, it will change the value in `c`. Instead of `6`, your computer will log `7`. Try it!

If Node.js is still watching in your terminal, this happens automatically when you save. If you stopped it, run this command again to have Node.js rerun your code each time you save:

```sh
node --watch main.ts
```

Variables are everywhere in code because they let you abstract and reuse your logic.

We used `a`, `b`, and `c` for the variable names, but you can use anything as long as the names don't include spaces or special characters. Remember that the language is case-sensitive.

For example, I updated our previous code with different variable names. If you run it, the result is the same in the terminal.

```ts showLineNumbers filename="main.ts"
const banana = 2;
const super_apple = 4;
const POTATO = banana + super_apple;
console.log(POTATO);
```
<Callout type="info" emoji="💡">
    To avoid confusion in the code, it's important to thoughtfully name variables. When a variable name is composed of multiple words, we use camel case by convention. This means that the first word is lowercase, followed by the next words capitalized. For example, `first name` would be `firstName`. Different languages and contexts use different casing styles, such as snake case in Python (`first_name`) or the delicious kebab case for web development (`first-name`).
</Callout>

## Variables with `let`

There are two main ways to create variables:
- With `const`, if you intend to keep the content constant, which should be your go-to.
- With `let`, if you need to overwrite the content.

Let's try to overwrite the content in our code without changing `const` to `let`.

Update your code ⚠️ **BUT DON'T SAVE IT YET** ⚠️! I want to show you something first.

```ts showLineNumbers filename="main.ts"
const a = 3;
const b = 4;
const c = a + b;
console.log(c);

// We want to put 10 in c and log it.
c = 10;
console.log(c);
```

While typing, your editor checks your code. And now we see red popping up all over the place! What's going on?

To figure it out, hover over the `c` underlined with the squiggly line.

<OutdatedScreenshot src="/assets/first-steps/variables/const-error-before-save.png" alt={"A screenshot showing VS Code showing an error."} lang="en" />

Oh! It says that we are trying to overwrite the content of a constant variable, which is forbidden. Thank you, code editor. I’m glad you caught that **before running the code**.

What you are witnessing here is an awesome feature of VS Code and TypeScript. The error was caught **before** we ran the code. When working on complex analyses that can take seconds, minutes, or sometimes hours to compute, you'll be grateful to catch errors beforehand instead of wasting time waiting for a script that will inevitably crash.

Now, let's execute this code anyway, just for the sake of curiosity. Save the file.

As expected, the code crashes, and the error is displayed in the terminal too.

<OutdatedScreenshot src="/assets/first-steps/variables/const-error.png" alt={"A screenshot showing a VS Code error in the terminal."} lang="en" />

<Callout type="info" emoji="💡">
    When throwing an error, Node.js will tell you where the problematic code is. For example, `.../main.ts:7:1` means the `main.ts` file, at the seventh line and first character. The exact line and column may vary with your code. If you press `CMD` on Mac or `CTRL` on PC and click on this file path, it will take you directly to it. This is very convenient when you start working with a lot of files.
</Callout>

But how do we fix this error?

Well, if we want to overwrite the content of a variable, we need to switch `const` to `let` when creating the `c` variable on line 3.

```ts showLineNumbers filename="main.ts"
const a = 3;
const b = 4;
let c = a + b;
console.log(c);

c = 10;
console.log(c);
```

Now it runs without any problems! If you update your code and save it, you will see the first value of `c` being logged in your terminal, followed by the second value.

We can also reuse `c` to overwrite... itself! The last two lines in the code below replace `c` with `c` squared (`c` multiplied by itself).

```ts showLineNumbers filename="main.ts"
const a = 3;
const b = 4;
let c = a + b;
console.log(c);

c = 10;
console.log(c);

c = c * c;
console.log(c);
```

The code above logs `7`, then `10`, then `100`.

<OutdatedScreenshot src="/assets/first-steps/variables/squared.png" alt={"A screenshot showing a squared result in the terminal."} lang="en" />

## Typed variables

There is something else to know about variables: **The data type matters**. This is why it's called... TypeScript!

For example, if you hover over `c` right now, you'll see that it has a type of `number`. This is because the sum of `a` and `b` is a number. The type here is **inferred**.

<OutdatedScreenshot src="/assets/first-steps/variables/type-number.png" alt={"A screenshot showing a variable of type number in VS Code."} lang="en" />

Now, let's overwrite `c` with text on line `6`. In TypeScript, text is called a `string` because it's a string of characters. For your computer to recognize something as text, it needs to be wrapped in quotes.

Update your code ⚠️ **BUT DON'T SAVE IT YET** ⚠️! Sorry, I screamed again. 😬

```ts showLineNumbers filename="main.ts"
const a = 3;
const b = 4;
let c = a + b;
console.log(c);

c = "Hey! What's up?";
console.log(c);

c = c * c;
console.log(c);
```

We have an error saying that we are trying to put text in `c` while `c` is supposed to be a number! And if you think about it, it is indeed a mistake.

If we switch `c` to text on line 6, what happens to line 9? What would be the squared value of `"Hey! What's up?"`? It makes no sense to multiply text by itself!

Once again, the editor caught the error **before running the code**. In TypeScript, **variables are typed**, which helps us write reliable and robust code.

<OutdatedScreenshot src="/assets/first-steps/variables/type-error-hover.png" alt={"A screenshot showing a type error in VS Code when hovering."} lang="en" />

**Now save the file.** VS Code still reports that a string cannot be assigned to a variable whose type is `number`.

Node.js behaves differently: it runs the code without checking the types. It logs `7`, then the text, then `NaN`, because multiplying this text by itself does not produce a number. The script does not crash. This is exactly why we use the TypeScript checker alongside Node.js: a script that runs can still produce an invalid result.

<OutdatedScreenshot src="/assets/first-steps/variables/type-error.png" alt={"A screenshot showing a type error in VS Code."} lang="en" />

## Conclusion

At this point, you might think, *Why is this so complicated? Let me code whatever I want, stupid computer!*

But trust me: this will save you from nasty bugs. As an experienced data and computational journalist, I've learned that the hard way. 😅

Using `const` will prevent you from accidentally overwriting important variables or data, and the types will ensure you are not mixing `text`, `number`, `Date`, or other data types that we will explore in the next lessons.

At the end of the day, you want valid results. You want to avoid publishing incorrect information at all costs. So, when you're swearing at TypeScript errors, take a deep breath and repeat this out loud: *It's working for me, not against me!*

While it might seem complicated right now, after a little bit of practice, it will all become natural. Trust me. 🙂

And just because I would be a very bad teacher if I let you end a lesson on an error, let's update the code one last time, with comments.

```ts showLineNumbers filename="main.ts"
// We create constant variables.
const a = 3;
const b = 4;

// We use let to overwrite c later on.
let c = a + b;
console.log(c);

// c is typed as a number, so we can only overwrite with numbers.
c = 10;
console.log(c);

// We can overwrite c by using c itself.
c = c * c;
console.log(c);
```

<Callout type="info" emoji="💡">
    To leave comments in your code, use `//` at the beginning of the line, like above. If you want to comment out multiple lines, wrap everything with `/*` at the beginning and `*/` at the end. Comments are ignored by your computer, so they are a great way to explain what your code does or to temporarily disable parts of your code.

    If you don't want to type the comment markers manually, place your cursor anywhere on a line or select several lines, then press `CMD` + `/` on Mac or `CTRL` + `/` on Windows in VS Code. Press the same shortcut again to uncomment them.
</Callout>

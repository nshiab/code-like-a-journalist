# Setup for data analysis

In the first two chapters, a folder, `main.ts`, and Node.js were enough to learn TypeScript. Data analysis projects need libraries, more folders, and a few configuration files. Let's prepare them with `@nshiab/setup-data-project`.

Make sure you've completed the [VS Code and Node.js setup](/first-steps/setup). We'll keep using the same editor and runtime.

<NoticeIntro />

## Set up a project

When you start a new project, you need to create a few folders and configuration files. To avoid doing this manually every time, I created an open-source library called [@nshiab/setup-data-project](https://github.com/nshiab/setup-data-project) that we can run to do all of this automatically. We'll use it for the data analysis lessons and projects from this chapter onward.

First, create a new, empty folder somewhere handy on your computer. In VS Code, click on the Explorer tab, click `Open Folder`, and select that folder. If you are asked whether you trust the authors of the files, say "Yes" for this project you just created.

![VS Code with arrows pointing to the Explorer tab and the Open Folder button.](/assets/first-steps/setup/vscode-open-folder.png)

Now we're ready to run the `@nshiab/setup-data-project` library in this folder. Open the terminal if it isn't already open (`View => Terminal`, or `CMD` + `J` on Mac and `CTRL` + `J` on Windows). Type the following command and press Enter:

```sh
npx @nshiab/setup-data-project
```

`npx` comes with Node.js. It will fetch, install, and run the library in the folder you created. If you're asked whether to install `@nshiab/setup-data-project`, type `y` and press Enter.

It's okay if the number after `@nshiab/setup-data-project` is different from `4.0.3` in my screenshot. It just means the library has been updated since I took it.

![The VS Code terminal asking for confirmation to install @nshiab/setup-data-project, with an arrow pointing to the prompt.](/assets/first-steps/setup/setup-data-project-install-prompt.png)

The `@nshiab/setup-data-project` library will ask which libraries you want to install. Use the space bar to select `simple-data-analysis`, then press Enter. This installs SDA and the tools we'll need for data analysis.

<OutdatedScreenshot src="/assets/simple-data-analysis/tabular-data/setup.png" alt={"Selecting simple-data-analysis in the setup tool."} lang="en" />

Wait until setup finishes and displays `You are all set!`. It may take a few seconds to download and install the tools. In the Explorer tab on the left, you'll see new files being created.

![VS Code showing the new project files in Explorer and the setup completion message You are all set! in the terminal.](/assets/first-steps/setup/setup-data-project-complete.png)

There's no magic here: the setup tool just created files in your folder. You can see them in Finder on Mac or File Explorer on Windows, too. Most are text files in different formats. VS Code gives us handy tools to edit them and run the code inside them.

After a few seconds, you should see a pop-up recommending the Oxc extension. Click `Install`. This extension will help highlight errors in our code as we type.

![VS Code recommending the Oxc extension, with arrows pointing to the pop-up and its Install button.](/assets/first-steps/setup/oxc-install-prompt.png)

<Callout type="info" emoji="💡">
    If you don't see this pop-up, fully quit VS Code. On Mac, press `Command` + `Q`, or right-click its icon in the Dock and choose `Quit`; clicking the red close button only closes the window. On Windows, use `File => Exit`. Then reopen VS Code and your project folder. The pop-up should appear after a few seconds.
</Callout>

Clicking `Install` should open the Extensions view and show the details of the Oxc extension we'll use in this course.

![VS Code showing the Oxc extension in the Extensions view and its details in an editor tab.](/assets/first-steps/setup/oxc-extension-details.png)

You are now ready to work! 🎉

If you're curious about the project files, here's a quick description of the most important ones:

- `README.md` describes what the project is about and how to run the code in it. It includes the commands for running this project.
- `AGENTS.md` contains instructions for AI agents. We won't use them in our lessons, but they're there if you use this setup for another project.
- `sda/main.ts` is the main script where we'll write our analysis. The `sda` folder also contains `helpers`, `data`, and `output` folders for our functions, input data, and results.
- `docs` contains the installed libraries' documentation.
- `package.json` lists the libraries installed in the project and useful commands we'll run regularly. We'll learn more about it in later lessons.
- `package-lock.json` is related to `package.json` and records the exact versions of the installed libraries. You don't need to worry about it for now.
- `.env` is where we'll put environment variables, such as API keys.
- `.gitignore` tells Git which files to leave out when tracking changes to your project or sharing it on platforms like GitHub. We'll talk about that later.
- `tsconfig.json` contains TypeScript options, already filled in with good defaults.
- `.oxfmtrc.json` contains formatting settings, which help keep our code neatly laid out.
- `.oxlintrc.json` contains settings for linting our code. Linting means checking code for mistakes and common problems.

Don't worry if this looks like a lot. The setup tool has done the configuration for us, and you don't need to modify these files unless you really know what you're doing.

Now close the `Extension: Oxc` tab by clicking the white cross next to its title. Then click the file icon in the top-left corner to return to the Explorer and your project files.

![VS Code with arrows pointing to the close button on the Extension: Oxc tab and the Explorer icon in the top-left corner.](/assets/first-steps/setup/return-to-explorer.png)

You should now see your project files in the Explorer again, as shown below.

![VS Code back in the Explorer view, showing the project files and the completed setup in the terminal.](/assets/first-steps/setup/explorer-ready.png)

## Run your analysis

The setup tool creates `sda/main.ts` with a short SDA example. Open it in the Explorer. From the terminal in your project folder, run:

```sh
npm run sda
```

Node.js can execute TypeScript directly, but it doesn't check types. The `sda` command adds formatting, linting (checks for common code problems), and type checking before running your analysis. If a check fails, fix the reported problem and try again. These checks help catch mistakes; you still need to check your data and results.

To rerun the analysis automatically when you save changes, use:

```sh
npm run sda:watch
```

This watches `sda` and `.env`, formats and checks the code, then runs it again when those files change. It ignores changes to `sda/output` so saving results doesn't start another run. To stop it, click in the terminal and press `Control` + `C` on Mac or Windows.

<Callout type="info" emoji="💡">
    The command for a data project is `npm run sda:watch`. It includes formatting and checks as well as automatic reruns. In the earlier TypeScript lessons, we used `node --watch main.ts` to run a standalone file.
</Callout>

## Check and format the project

To check formatting, lint rules, and TypeScript types without running the analysis, use:

```sh
npm run all-tests
```

Despite its name, this command doesn't include automated tests in a fresh project. We'll learn to add tests later.

To format files and apply automatic fixes, use:

```sh
npm run fix
```

Some problems will still need a fix from you. Read the messages, make the changes, and run the checks again.

You can keep this project for the [Tabular data lesson](/simple-data-analysis/tabular-data). For a new analysis, create a new folder and repeat this setup, selecting the libraries you need.

# The one billion row challenge 😱

Welcome to this new project where we crack open a one-billion-row CSV file. Yes, ONE BILLION!

This is a very fun challenge created by [Gunnar Morling](https://www.morling.dev/blog/one-billion-row-challenge/).

> Your mission, should you choose to accept it, is deceptively simple: write a Java program for retrieving temperature measurement values from a text file and calculating the minimum, mean, and maximum temperatures per weather station. There’s just one caveat: the file has 1,000,000,000 rows!

Instead of using a Java program, we will use TypeScript, of course, with the Simple Data Analysis library (SDA), which I created ([give it a ⭐](https://github.com/nshiab/simple-data-analysis)). This is a great opportunity to test how powerful it can be!

If you get stuck at any point in this project, it might be helpful to review the previous lessons in Chapter 3, which explain the basics of SDA:
- [Tabular data](/simple-data-analysis/tabular-data)
- [Geospatial data](/simple-data-analysis/geospatial-data)
- [Visualizing data](/simple-data-analysis/dataviz)

We will use Deno and VS Code. Check the [Setup](/first-steps/setup) lesson if needed.

Let's code!

## Setup

To set up everything we need, let's use [`@nshiab/setup-data-project`](https://jsr.io/@nshiab/setup-data-project), as in previous lessons.

Create a new folder, open it with VS Code, and run: `deno -A jsr:@nshiab/setup-data-project`

When prompted, use the space bar to select `simple-data-analysis`, then press `Enter`.

![A screenshot showing simple-data-analysis selected in setup-data-project.](/assets/simple-data-analysis/tabular-data/setup.png)

Then run `deno task sda` to watch `main.ts` and its dependencies.

This is what you should see in your `main.ts` file and terminal if everything went well.

![A screenshot showing the generated main.ts file and the successful output in the terminal.](/assets/one-billion-row-challenge/setup.png)

## The data

In the original challenge, you have to fork a GitHub repo and run a script to generate a CSV file with 1 billion rows of data. I generated it for you and uploaded a course-owned copy to Google Drive.

[Download the data from here](https://drive.google.com/file/d/1A_OCjRyHnCCMZbgT0Z5KN70pJXMA8TYD/view). It might take a few minutes since it's around 4 GB.

Then put it in your `data` folder and unzip it. The uncompressed version of the CSV file is around 13 GB.

To load the data, copy and paste this code into your `main.ts`. Depending on your computer, it might take a few seconds to a few minutes to run.

```ts showLineNumbers filename="main.ts"
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB({ logDuration: true });

sdb
  .newTable()
  .loadData("sda/data/measurements.csv")
  .log();

await sdb.close();
```
![A screenshot of VS Code after loading one billion rows of data.](/assets/one-billion-row-challenge/load-data.png)

Congratulations! You just loaded 1,000,000,000 rows of data! As you can see, it takes roughly seven seconds on my M4 Max, which is quite impressive for a CSV file of this size. 🥳

Depending on the RAM available on your computer, you might see a `.tmp` folder appearing in your project. If the data is bigger than your RAM, this folder will be used to process all of it by storing processed chunks in it.

This `.tmp` folder can become quite big. But don't worry: when you set up a project with `@nshiab/setup-data-project`, it is automatically added to `.gitignore`, so you don't accidentally commit and push it to GitHub or elsewhere.

<Callout type="info" emoji="💡">
    You can remove `.tmp` manually, although I usually don't bother. Running `deno task clean` will remove it too, but be careful: it will also delete all cached data in `.sda-cache`.
</Callout>

## The challenge

As you can see above, the data is just a list of cities with temperatures.

Now, the challenge is to compute the minimum, mean, and maximum temperatures per city. The results also need to be sorted alphabetically by city.

This is very easy with SDA. We only need to call one method, `summarize`, to perform the computations. We don't even need to sort the rows manually because `summarize` does it by default.

```ts showLineNumbers filename="main.ts" {8-12}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB({ logDuration: true });

await sdb
  .newTable()
  .loadData("sda/data/measurements.csv")
  .summarize({
    columns: "temp",
    by: "city",
    stats: ["min", "mean", "max"],
  })
  .log();

await sdb.close();
```

![A screenshot of VS Code after aggregating one billion rows of data.](/assets/one-billion-row-challenge/summarize.png)

On my machine, this runs even faster than simply loading the CSV file because the final table is much smaller than the full one-billion-row table. Everything is processed on the fly, which is quite incredible. 🚀

## But... how?

While SDA is a TypeScript library, under the hood it uses [DuckDB](https://duckdb.org/), a very fast database system written in C++. When you use methods like `loadData` or `summarize`, SDA translates everything into SQL and asks DuckDB to execute it.

To compare SDA with other popular options, including DuckDB, I ran a few benchmarks on my MacBook Pro M4 Max, as described below.

### Tabular data

For tabular data, I ran a test with the [Adjusted and Homogenized Canadian Climate Data](https://api.weather.gc.ca/collections/ahccd-annual), which contains more than 22 million rows. Among other steps, each option calculated the average temperature by station and decade. SDA was indeed extremely fast compared with the other options.

![A chart comparing the mean duration of tabular workflows with SDA, DuckDB, pandas, and the tidyverse.](/assets/one-billion-row-challenge/benchmark-tabular-duration.png)

### Geospatial data

For geospatial data, I used the dataset of all public trees in Montreal (335K). The main computation was counting the number of trees in each of the city's neighbourhoods. Once again, SDA was a very fast solution.

![A chart comparing the mean duration of geospatial workflows with SDA, DuckDB, GeoPandas, and sf.](/assets/one-billion-row-challenge/benchmark-spatial-duration.png)

The memory benchmarks tell a similar story. You can review the methodology, code, and latest results in the [Simple Data Analysis repository](https://github.com/nshiab/simple-data-analysis).

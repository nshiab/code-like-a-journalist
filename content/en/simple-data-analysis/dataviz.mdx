# Visualizing data with Simple Data Analysis and Plot

Data visualizations help you understand your data and communicate your findings. In this lesson, we'll learn how to visualize SDA tables, from simple terminal charts to customized visualizations with [Observable Plot](https://github.com/observablehq/plot).

We’ll save our charts as PNG or SVG files in this lesson. However, Plot is a library built for the web, so you can reuse the code we write here to display a chart inside an HTML element on a web page. Isn’t TypeScript amazing? 😊

We'll use data on the 2023 Canadian wildfires and explore different visualization techniques, including line charts, beeswarm charts, and maps! 🌎

This lesson assumes you’ve completed the [Setup](/simple-data-analysis/setup), [Tabular data](/simple-data-analysis/tabular-data), and [Geospatial data](/simple-data-analysis/geospatial-data) lessons.

## Creating our helper functions

To keep our code organized, let's create two functions:

- `crunchData`, where we'll fetch and clean the wildfire data.
- `visualizeData`, where we'll generate charts and maps.

Let's start with `crunchData`. Create a `crunchData.ts` file in `./sda/helpers/`. This `async` function will fetch and cache the wildfire data.

```ts showLineNumbers filename="crunchData.ts"
import type { SimpleTable } from "@nshiab/simple-data-analysis";

export default async function crunchData(fires: SimpleTable) {
  await fires.cache((table) => {
    table.loadData(
      "https://raw.githubusercontent.com/nshiab/data-fetch-lesson/refs/heads/main/reported_fires_2023.csv",
    );
  });
}
```

## Prepping the data

We have around 5,000 wildfires. Let's say that we would like to visualize how much wildfires have burnt through the year, for each province. We need the cumulative sum of the area burnt.

In `crunchData.ts`, let's sum up our fires per date and province.

```ts showLineNumbers filename="crunchData.ts" {10-14}
import type { SimpleTable } from "@nshiab/simple-data-analysis";

export default async function crunchData(fires: SimpleTable) {
  await fires.cache((table) => {
    table.loadData(
      "https://raw.githubusercontent.com/nshiab/data-fetch-lesson/refs/heads/main/reported_fires_2023.csv",
    );
  });

  fires.summarize({
    columns: "hectares",
    by: ["province", "startdate"],
    stats: "sum",
  });
}
```

Since we aggregated the data, we went from more than 5,000 rows to just over 1,000.

![VS Code showing crunchData.ts summing hectares burned by province and start date, with the resulting table in the terminal.](/assets/simple-data-analysis/dataviz/summary.png)

Use `accumulate` to calculate the cumulative area burned for each province. Set `decimals: 1` to round the results to one decimal place.

```ts showLineNumbers filename="crunchData.ts" {16-19}
import type { SimpleTable } from "@nshiab/simple-data-analysis";

export default async function crunchData(fires: SimpleTable) {
  await fires.cache((table) => {
    table.loadData(
      "https://raw.githubusercontent.com/nshiab/data-fetch-lesson/refs/heads/main/reported_fires_2023.csv",
    );
  });

  fires
    .summarize({
      columns: "hectares",
      by: ["province", "startdate"],
      stats: "sum",
    })
    .accumulate("sum", "cumulativeHectares", {
      by: "province",
      decimals: 1,
    });
}
```

![VS Code showing the accumulate call in crunchData.ts and the new cumulativeHectares column in the terminal.](/assets/simple-data-analysis/dataviz/cumulative.png)

## In the terminal

SDA has some methods to easily log charts in your terminal. It's a great way to quickly inspect your data. Let's work in `visualizeData.ts`.

In the example below, we use the `logDotChart` method with the `startdate` column for the x values and `cumulativeHectares` for the y values. We also add two options:

- We use the `province` values to create small multiples (one chart per province).
- We make all the charts share the same scales, which is convenient for comparing provinces visually.

```ts showLineNumbers filename="visualizeData.ts" {5-8}
import type { SimpleTable } from "@nshiab/simple-data-analysis";

export default async function visualizeData(fires: SimpleTable) {
  await fires.log();
  await fires.logDotChart("startdate", "cumulativeHectares", {
    smallMultiples: "province",
    fixedScales: true,
  });
}
```

![VS Code showing the logDotChart call and four terminal dot charts of cumulative hectares burned, each for a different province and using the same scales.](/assets/simple-data-analysis/dataviz/dot-charts.png)

You are not limited to dot charts. You can also use the methods `logLineChart`, `logBarChart`, and `logHistogram`.

However, while these methods are very handy, they are quite limited.

## With Plot

### Cumulative hectares burnt per province

[Plot](https://github.com/observablehq/plot) is a fantastic library for creating charts. It's based on the very famous [d3](https://github.com/d3/d3) library (and built by the same team, including [Mike Bostock](https://github.com/mbostock) and [Philippe Rivière](https://github.com/Fil)). However, it's much easier to use because many things that need to be handled manually in d3 (scales, axes, etc.) are done automatically with Plot.

SDA integrates Plot seamlessly, and `setup-data-project` installs it automatically when you select SDA.

To create a chart and save it as a file (`.png` or `.svg` if you want to rework it in Illustrator), you can use the `writeChart` method.

The `writeChart` method requires two arguments:
- A function that receives the table’s data and uses it to draw a Plot chart.
- A path for the image file that will be saved.

In `visualizeData.ts`, let's create a simple line chart showing the area burnt throughout 2023 for each province.

```ts showLineNumbers filename="visualizeData.ts" {2, 6-19}
import type { SimpleTable } from "@nshiab/simple-data-analysis";
import { line, plot } from "@observablehq/plot";

export default async function visualizeData(fires: SimpleTable) {
  await fires.log();
  await fires
    .writeChart(
      (data) =>
        plot({
          marks: [
            line(data, {
              x: "startdate",
              y: "cumulativeHectares",
              stroke: "province",
            }),
          ],
        }),
      "./sda/output/chart.png",
    );
}
```

![VS Code showing the writeChart code beside chart.png, a line chart of cumulative hectares burned by province in 2023.](/assets/simple-data-analysis/dataviz/draw-chart.png)

    As a reminder, you can right-click a file tab or a file in the Explorer on the left and select `Split Right` to view several files, including images, side by side. Since the SDA task is watching `main.ts`, every time you update and save your code, the script runs automatically and refreshes the chart. Keeping the chart open next to your code lets you see your changes right away.
</Callout>

Let me explain what's going on above:

- On line 2, we import the `line` and `plot` functions from Plot.
- On lines 6-19, we call `writeChart` on the `fires` table.
- On line 8, we use `data` as the name for the rows the arrow function receives from `fires`.
- On lines 9-17, we use `plot` to create the chart that the arrow function returns.
- On line 10, we add a `marks` array. Marks are the shapes used to represent our data in a Plot chart.
- On lines 11-15, we add a `line` mark. It uses `startdate` for the x values, `cumulativeHectares` for the y values, and `province` for the stroke color.
- On line 18, we pass the second argument to `writeChart`, which specifies where the chart should be saved.

Our chart is quite basic for now, and there are some issues, like the y-axis. Let's fix it!

```ts showLineNumbers filename="visualizeData.ts" {10-16}
import type { SimpleTable } from "@nshiab/simple-data-analysis";
import { line, plot } from "@observablehq/plot";

export default async function visualizeData(fires: SimpleTable) {
  await fires.log();
  await fires
    .writeChart(
      (data) =>
        plot({
          inset: 10,
          y: {
            grid: true,
            label: "Area burned (hectares)",
            ticks: 5,
            tickFormat: (d) => `${d / 1_000_000}M`,
          },
          marks: [
            line(data, {
              x: "startdate",
              y: "cumulativeHectares",
              stroke: "province",
            }),
          ],
        }),
      "./sda/output/chart.png",
    );
}
```

![VS Code showing the y-axis options beside the line chart, with horizontal grid lines and tick labels in millions of hectares.](/assets/simple-data-analysis/dataviz/y-axis.png)

This is better! To update the y-axis, you can pass options to `y` as an object. Here's what we are doing in the code above:

- We add grids to make the chart more readable.
- We format the top axis label to be more understandable with the unit.
- We ask Plot for about five ticks.
- We format the tick labels to show millions of hectares instead of just hectares.

I also added an `inset` of `10` to give a little more space to the top label.

Now, let's update the `x` label. There's no need to modify the x tick labels because Plot handles dates well, automatically displaying years, months, days, or even time based on the scale values and axis width.

The colors are currently assigned automatically. We can choose a different scheme and maybe add a legend.

```ts showLineNumbers filename="visualizeData.ts" {17-23}
          x: {
            label: "Date",
          },
          color: {
            legend: true,

          },

            line(data, {

    );
}
```

![VS Code showing the x-axis and color options beside the line chart, with the x-axis labeled Date and a color legend above the chart.](/assets/simple-data-analysis/dataviz/x-colors.png)

Hmmmm... The color legend doesn't work very well with so many categories. We need to change our strategy. Instead of a color legend, maybe we could add a dot and a text label at the end of each line.

Let's remove the color legend and add a `dot` mark. Since we want to add dots at the end of each line, we use the `selectLast` transform. This will select only the last data point.

Note that the order in the `marks` array is important. Marks are drawn in sequence, so if you want a shape to appear on top of another, add it later in the array.

Don't forget to remove `legend: true` from the `color` options! ⚠️

```ts showLineNumbers filename="visualizeData.ts" {29-36} /dot/1 /selectLast/1
import type { SimpleTable } from "@nshiab/simple-data-analysis";
import { dot, line, plot, selectLast } from "@observablehq/plot";

export default async function visualizeData(fires: SimpleTable) {
  await fires.log();
  await fires
    .writeChart(
      (data) =>
        plot({
          inset: 10,
          y: {
            grid: true,
            label: "Area burned (hectares)",
            ticks: 5,
            tickFormat: (d) => `${d / 1_000_000}M`,
          },
          x: {
            label: "Date",
          },
          color: {
            scheme: "tableau10",
          },
          marks: [
            line(data, {
              x: "startdate",
              y: "cumulativeHectares",
              stroke: "province",
            }),
            dot(
              data,
              selectLast({
                x: "startdate",
                y: "cumulativeHectares",
                fill: "province",
              }),
            ),
          ],
        }),
      "./sda/output/chart.png",
    );
}
```

![VS Code showing the dot mark with selectLast beside the chart, where a colored dot marks the end of each line.](/assets/simple-data-analysis/dataviz/dots.png)

And now let's add the text labels. We use `selectLast` again with some additional options:

- We apply a black `fill` with a white `stroke` to improve readability, ensuring the text remains visible even when overlapping other chart elements.
- We set `textAnchor` to `start` so the text aligns with the `dot`, but we shift it by 5 pixels with `dx` to prevent it from touching the dot.
- We use `x` and `y` to position the labels, and `z` to create one label for each province. The `text` option uses the values in the `province` column for the labels.

```ts showLineNumbers filename="visualizeData.ts" {37-49} /text/1
import type { SimpleTable } from "@nshiab/simple-data-analysis";
import { dot, line, plot, selectLast, text } from "@observablehq/plot";

export default async function visualizeData(fires: SimpleTable) {
  await fires.log();
  await fires
    .writeChart(
      (data) =>
        plot({
          inset: 10,
          y: {
            grid: true,
            label: "Area burned (hectares)",
            ticks: 5,
            tickFormat: (d) => `${d / 1_000_000}M`,
          },
          x: {
            label: "Date",
          },
          color: {
            scheme: "tableau10",
          },
          marks: [
            line(data, {
              x: "startdate",
              y: "cumulativeHectares",
              stroke: "province",
            }),
            dot(
              data,
              selectLast({
                x: "startdate",
                y: "cumulativeHectares",
                fill: "province",
              }),
            ),
            text(
              data,
              selectLast({
                text: "province",
                fill: "black",
                stroke: "white",
                textAnchor: "start",
                dx: 5,
                x: "startdate",
                y: "cumulativeHectares",
                z: "province",
              }),
            ),
          ],
        }),
      "./sda/output/chart.png",
    );
}
```

![VS Code showing the text mark beside the line chart, with province names next to the dots at the ends of the lines.](/assets/simple-data-analysis/dataviz/text-labels.png)

This is much better! But our chart needs some obvious adjustments now.

For example, the dots and labels at the ends of the lines don't align. We grouped fires by `startdate`, and the date of the last reported fire varies by province.

We also notice that not much is happening before mid-April and after October 1st.

Let's go back to `crunchData.ts` to fix that:

- On line 11, we filter the fires to keep only those with a `startdate` between April 15, 2023, and October 1, 2023.
- After calculating the cumulative values, we remove the now-unneeded `sum` column.
- Between lines 23 and 30, we use `summarize` to get each province's maximum cumulative total in the filtered period. Then we use `addColumn` to assign that value to October 1 so the lines end on the same date.
- Finally, on line 32, we insert these final values back into `fires`. Now, the data for every province has the same final date.

```ts showLineNumbers filename="crunchData.ts" {11, 21-32}
import type { SimpleTable } from "@nshiab/simple-data-analysis";

export default async function crunchData(fires: SimpleTable) {
  await fires.cache((table) => {
    table.loadData(
      "https://raw.githubusercontent.com/nshiab/data-fetch-lesson/refs/heads/main/reported_fires_2023.csv",
    );
  });

  fires
    .filter(`startdate >= '2023-04-15' && startdate <= '2023-10-01'`)
    .summarize({
      columns: "hectares",
      by: ["province", "startdate"],
      stats: "sum",
    })
    .accumulate("sum", "cumulativeHectares", {
      by: "province",
      decimals: 1,
    })
    .removeColumns("sum");

  const maxValuesPerProvince = fires
    .summarize({
      columns: "cumulativeHectares",
      by: "province",
      stats: { cumulativeHectares: "max" },
      outputTable: "maxValuesPerProvince",
    })
    .addColumn("startdate", "date", `'2023-10-01'`);

  fires.insertTables(maxValuesPerProvince);
}
```

![VS Code showing the code that assigns October 1 to each province’s final value and the chart with its dots and labels aligned on that date.](/assets/simple-data-analysis/dataviz/labels-aligned.png)

And now, our labels are properly aligned!

Let's go back to `visualizeData.ts` to fix the right margin. We can also filter out some labels to prevent overlapping text and add a caption explaining which labels are not shown.

```ts showLineNumbers filename="visualizeData.ts" {10-11, 13} /filter: (d) => d.cumulativeHectares >= 400_000/

          caption:
            "Labels for provinces with less than 400,000 hectares burned are not shown.",
          inset: 10,
          marginRight: 110,
          y: {
            grid: true,
            label: "Area burned (hectares)",
            ticks: 5,
            tickFormat: (d) => `${d / 1_000_000}M`,
          },
          x: {
            label: "Date",
          },
          color: {
            scheme: "tableau10",
          },
          marks: [
            line(data, {
              x: "startdate",
              y: "cumulativeHectares",
              stroke: "province",
            }),
            dot(
              data,
              selectLast({
                x: "startdate",
                y: "cumulativeHectares",
                fill: "province",
              }),
            ),
            text(
              data,
              selectLast({
                text: "province",
                fill: "black",
                stroke: "white",
                textAnchor: "start",

                z: "province",
```

### Wildfires beeswarm chart

Our previous chart was quite traditional, but you can also create more unconventional visualizations that push the boundaries of data storytelling.

For example, let's create a beeswarm of our fires.

We can update `crunchData.ts` to return to our raw data. However, let's keep only fires greater than 1 hectare. That leaves us with around 2,400 fires. This is quite a lot, considering we want to visualize each fire individually in this type of chart!

```ts showLineNumbers filename="crunchData.ts"
import type { SimpleTable } from "@nshiab/simple-data-analysis";

export default async function crunchData(fires: SimpleTable) {
  await fires.cache((table) => {
    table.loadData(
      "https://raw.githubusercontent.com/nshiab/data-fetch-lesson/refs/heads/main/reported_fires_2023.csv",
    );
  });
  fires.filter(`hectares > 1`);
}
```

And let's start by drawing our fires as simple dots on a y-axis.

```ts showLineNumbers filename="visualizeData.ts"
import type { SimpleTable } from "@nshiab/simple-data-analysis";
import { dot, plot } from "@observablehq/plot";

export default async function visualizeData(fires: SimpleTable) {
  await fires.log();
  await fires.writeChart(
    (data) =>
      plot({
        marks: [
          dot(data, { y: "hectares" }),
        ],
      }),
    "./sda/output/chart.png",
  );
}
```

![VS Code showing the dot mark beside a chart of wildfire sizes in hectares, with overlapping dots in a single vertical column.](/assets/simple-data-analysis/dataviz/fires-dots.png)

Right now, our fires are overlapping. The purpose of a beeswarm chart is to stack data points in a way that ensures each one remains visible.

To create a beeswarm, we can use the `dodgeX` transform with the `middle` option. Let's update our code.

Rendering this chart may take a few seconds, depending on your machine's processing power.

```ts showLineNumbers filename="visualizeData.ts" {12} /dodgeX/1
import type { SimpleTable } from "@nshiab/simple-data-analysis";
import { dodgeX, dot, plot } from "@observablehq/plot";

export default async function visualizeData(fires: SimpleTable) {
  await fires.log();
  await fires.writeChart(
    (data) =>
      plot({
        marks: [
          dot(
            data,
            dodgeX("middle", { y: "hectares" }),
          ),
        ],
      }),
    "./sda/output/chart.png",
  );
}
```

![VS Code showing the dodgeX call beside a beeswarm chart that spreads wildfire dots horizontally while keeping their height tied to hectares burned.](/assets/simple-data-analysis/dataviz/fires-dodge.png)

It looks like we have a looooot of small wildfires and a few very big ones.

A logarithmic scale could help with that! Let's change our `y` scale `type` to `log`.

![VS Code showing the log scale option beside the beeswarm chart, with y-axis labels at powers of ten.](/assets/simple-data-analysis/dataviz/log-scale.png)

This is already much better. Another improvement would be to scale the dot radius based on fire size. 

We can update the options for the `dot` function and adjust the `r` scale to ensure a minimum radius of 1 pixel and a maximum of 20 pixels.


```ts showLineNumbers filename="visualizeData.ts" {12-14} /r: "hectares"/
import type { SimpleTable } from "@nshiab/simple-data-analysis";
import { dodgeX, dot, plot } from "@observablehq/plot";

export default async function visualizeData(fires: SimpleTable) {
  await fires.log();
  await fires.writeChart(
    (data) =>
      plot({
        y: {
          type: "log",
        },
        r: {
          range: [1, 20],
        },
        marks: [
          dot(
            data,
            dodgeX("middle", { y: "hectares", r: "hectares" }),
          ),
        ],
      }),
    "./sda/output/chart.png",
  );
}
```

![VS Code showing the radius settings beside the beeswarm chart, where larger circles represent fires that burned more hectares.](/assets/simple-data-analysis/dataviz/radiuses.png)

We are getting there.

Let's fill the circles based on the cause of the fire and add a legend.

### Fires map

With SDA, you can work with both tabular and geospatial data. When wrangling geospatial data, you often want to create maps!

Let's map our fires along with the Canadian province boundaries.

First, we need to store the fire geometries in the same table as the province boundaries.

Let's reuse what we did in the previous lesson and update `crunchData.ts`. We'll modify it to take a second table, `provinces`, as a parameter. For the fires, we create point geometries from the `lat` and `lon` columns. We also add an `isFire` column set to `true`.

Then, we fetch and cache the province boundaries and add the same `isFire` column, this time set to `false`. Finally, we insert the provinces into `fires` and use the `unifyColumns` option because the two tables do not have the same columns.

```ts showLineNumbers {13, 16-21, 23} filename="crunchData.ts"
import type { SimpleTable } from "@nshiab/simple-data-analysis";

export default async function crunchData(
  fires: SimpleTable,
  provinces: SimpleTable,
) {
  await fires.cache(() => {
    fires
      .loadData(
        "https://raw.githubusercontent.com/nshiab/data-fetch-lesson/refs/heads/main/reported_fires_2023.csv",
      )
      .createPoints("lat", "lon", "geom")
      .addColumn("isFire", "boolean", `TRUE`);
  });

  await provinces.cache(() => {
    provinces.loadGeoData(
      "https://raw.githubusercontent.com/nshiab/simple-data-analysis/main/test/geodata/files/CanadianProvincesAndTerritories.json",
    )
      .addColumn("isFire", "boolean", `FALSE`);
  });

  fires.insertTables(provinces, { unifyColumns: true });
}
```

Now that we have all of the data in one table, it's easy to call just one method to draw both the fires and the provincial boundaries. Let's work on our map in `visualizeData`. Instead of using `writeChart`, we must use `writeMap`.

`writeMap` works just like `writeChart`. Its first parameter is a function that returns an Observable Plot chart, and its second parameter specifies where to write the chart.

There is one important difference. With `writeChart`, the data passed to the function was an array of objects. With `writeMap`, it is GeoJSON: a collection of features whose data is stored in each feature's `properties`. You can see this on lines 8-13, where we use `feature.properties.isFire` to separate the fires from the provinces. On lines 16 and 17, we draw them separately with Observable Plot's `geo` mark, which is designed to render geospatial features.

```ts showLineNumbers filename="visualizeData.ts" {2, 6-20}
import type { SimpleTable } from "@nshiab/simple-data-analysis";
import { geo, plot } from "@observablehq/plot";

export default async function visualizeData(fires: SimpleTable) {
  await fires.log();
  await fires
    .writeMap((geoData) => {
      const fires = geoData.features.filter(
        (feature) => feature.properties.isFire,
      );
      const provinces = geoData.features.filter(
        (feature) => !feature.properties.isFire,
      );
      return plot({
        marks: [
          geo(provinces),
          geo(fires),
        ],
      });
    }, "./sda/output/map.png");
}
```

![VS Code showing the writeMap code alongside map.png, with wildfire locations drawn as circles over Canada's provincial and territorial boundaries.](/assets/simple-data-analysis/dataviz/basic-map.png)

As you can see in the screenshot above, the `geo` mark automatically detected the point coordinates of our fires and the polygon coordinates of the Canadian province boundaries. Pretty clever! 🤓

So far, Plot has drawn longitude and latitude directly on the x and y axes. Let's set a projection better suited to a map of Canada:

- Set the `type` to `conic-conformal`.
- Use the `rotate` option to properly align Canada within the projection.
- Use the `domain` option to fit the full extent of our geospatial data within the map, taking up as much space as possible without being cut off.


Adding colors helps, but many spikes still overlap. By default, Plot fills spikes with an opacity of 0.3. Transparency can be useful for revealing marks behind one another, but here the many overlapping fills create too much visual noise.

There is one more adjustment to make now that the spikes are opaque: their drawing order. By default, Plot draws them in the order they appear in the data. Instead, we'll order them by latitude so fires with a greater latitude (further north) are drawn first and fires with a smaller latitude (further south) appear in front. This adds some perspective to the map.

We can update `crunchData` to sort the fires by latitude in descending order. Thank you to [Philippe Rivière](https://github.com/Fil) for the suggestion! 😊

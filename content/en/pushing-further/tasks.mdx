# Running tasks

Tasks are a way to avoid rewriting long commands in the terminal. They are very convenient and widely used. With npm, we call them **scripts** and define them in `package.json`.

<NoticeIntro />

Create a project with `npx @nshiab/setup-data-project`, following the [setup lesson](/first-steps/setup), with no optional libraries selected. Open the generated project folder in VS Code.

Copy and paste the following code into `sda/main.ts`. This script comes from the [Fetching data](/pushing-further/fetch) lesson. It fetches a JSON file from GitHub, parses it, and logs it.

```ts showLineNumbers filename="sda/main.ts"
const response = await fetch(
  "https://raw.githubusercontent.com/nshiab/data-fetch-lesson/refs/heads/main/temp.json",
);

const data = await response.json();

console.log(data);
```

You’ve already used `npm run sda` to execute and watch your code. Let’s see how that command works!

Open `package.json` and find the **scripts** object. Among the generated entries, you’ll see these:

```json showLineNumbers filename="package.json (scripts excerpt)"
{
  "scripts": {
    "sda": "node --env-file-if-exists=.env --watch sda/main.ts",
    "all-tests": "vp check && vp test --passWithNoTests",
    "fix": "vp check --fix"
  }
}
```

This is an excerpt: keep all the other fields and scripts in your generated file.

When you run `npm run sda` from the project root, npm finds `sda` inside `scripts` and executes its command. Node.js loads a `.env` file if one exists, runs `sda/main.ts`, and watches for changes so it can restart automatically.

The `all-tests` script runs the project’s checks and then its tests. The `fix` script applies formatting and automatic fixes. Node.js itself doesn’t check TypeScript types when executing your code; use the project checks for that.

What if you want to run the script just once? Let’s add a command called `once`. Add this entry inside the existing `scripts` object, keeping its other entries:

```json filename="package.json (new scripts entry)"
"once": "node --env-file-if-exists=.env sda/main.ts"
```

Don’t forget the comma between neighboring entries, and save the file! 🙃 If `npm run sda` is still running, stop it with `CTRL` + `C`. Then run:

```sh
npm run once
```

Your code runs once, then exits. If you later change the command stored in `once`, you’ll still use the same shortcut: `npm run once`.

<Callout type="info" emoji="💡">
    You can define as many scripts as you need. Run `npm run` without a script name to list the available ones. npm also makes installed command-line tools available to scripts, which is why the generated commands can use `vp` directly.
</Callout>

## Conclusion

Scripts are useful in all kinds of projects, whether you’re running code, scraping the web, analyzing data, or building and publishing a website. They make these commands convenient to run, and we’ll use them throughout the upcoming lessons and projects.

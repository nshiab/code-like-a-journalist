# Writing and reading files

When you run your code, everything is kept in your computer’s RAM (Random Access Memory). This type of memory is very fast, but if you stop your script or shut down your computer, everything is lost. 😱

If you want to keep some data around, you need to write it to a file, which will be stored in your computer’s permanent storage (hard drive). And to retrieve the data from a file, you need to read it.

Node.js runs TypeScript without checking its types. Use `npm run all-tests` to check the project, and `npm run fix` to apply formatting and automatic fixes, as explained in the setup lesson.

## Writing

With Node.js, writing files is very easy. Import the `writeFile` function from the built-in `node:fs/promises` module. You don’t need to install anything: this module comes with Node.js.

For text files, pass a path as the first parameter and a string as the second parameter. In the code below, we want to create a file named `hello.txt` containing `"Hello!"`.

The `./` makes this a relative path: it points to the folder where we run the script, which is the project root containing `package.json`. This is different from imports: their relative paths start from the importing file, here `sda/main.ts`.

Copy, paste, and save this code in `sda/main.ts`. We’ll talk about the `await` keyword in a minute.

```ts showLineNumbers filename="sda/main.ts"
import { writeFile } from "node:fs/promises";

await writeFile("./hello.txt", "Hello!");
```

A new text file has been created with text content in it. You now know how to permanently store data on your computer!

By the way, be careful: by default, `writeFile` overwrites files if they already exist.

## Reading

To read files, import `readFile` from the same module. Pass a file path and the encoding `"utf8"` to get the contents as a string. Without the encoding, Node.js returns a `Buffer`, which represents raw bytes.

Let’s update `sda/main.ts` to read the file we wrote earlier.

```ts showLineNumbers filename="sda/main.ts"
import { readFile } from "node:fs/promises";

const data = await readFile("./hello.txt", "utf8");
console.log(data);
```

You’ve successfully retrieved the text content from the `hello.txt` file!

## JSON

Writing data as text is pretty standard. For example, CSV files are just text files with commas representing columns.

However, when working in TypeScript, especially for the Web, you’ll often write your data as **JSON files**. JSON stands for *JavaScript Object Notation*, and since TypeScript is based on JavaScript, it’s a natural choice.

This text file format can store arrays, objects, text, numbers, and booleans, instead of just raw text.

For example, in the script below, we write the array of objects `data` to the file `data.json`.


```ts showLineNumbers filename="sda/main.ts"
import { writeFile } from "node:fs/promises";

const data = [
  { name: "Nael", age: 25 },
  { name: "John", age: 30 },
];

await writeFile(
  "data.json",
  JSON.stringify(data),
);
```
<Callout type="info" emoji="💡">
    We used the `JSON` global object, which is always available while you code, and its `stringify()` method. Here, `writeFile` needs text rather than an array, but `data` is an array of objects. So we **stringify** it to transform `data` into a JSON string. The complementary method is `JSON.parse()`, which can convert stringified arrays, objects, and values back to their original form.
</Callout>

<OutdatedScreenshot src="/assets/pushing-further/files/json-write.png" alt={"A screenshot showing VS Code writing a JSON file with Deno."} lang="en" />

Because it has the `.json` extension, the file is understood by VS Code and Node.js. Its content is displayed with the proper data types. In the editor, the names are highlighted as strings and the ages as numbers. If we wrote everything into a `.txt` file, everything would appear as plain text.

Additionally, you can import a JSON file by adding the `with { type: "json" }` import attribute. The generated project’s TypeScript settings support JSON imports and let the editor infer their types. The import below uses `../data.json` because it starts in `sda`, then goes up to the project root.

```ts showLineNumbers filename="sda/main.ts"
import data from "../data.json" with { type: "json" };

console.log(data);
```
<OutdatedScreenshot src="/assets/pushing-further/files/json-read.png" alt={"A screenshot showing VS Code reading a JSON file with Deno."} lang="en" />

VS Code and `npm run all-tests` can check the imported data’s types, which is wonderful. Node.js itself still doesn’t check types when it runs the code.

If you add a `.` after `data`, VS Code will suggest array methods because it knows the data stored in `data.json` is an array.

<OutdatedScreenshot src="/assets/pushing-further/files/json-array-methods.png" alt={"A screenshot showing VS Code suggesting array methods."} lang="en" />

If you select the first object of `data` with `[0]` and type a `.` to access a key, VS Code will suggest the keys that are in the object. Since it’s a JSON file, it can infer the types.

<OutdatedScreenshot src="/assets/pushing-further/files/json-object-methods.png" alt={"A screenshot showing VS Code reading a JSON file with Deno."} lang="en" />

And if you try to access keys that don’t exist in the objects, VS Code and the project checks flag an error. Isn’t that amazing? 😍

<OutdatedScreenshot src="/assets/pushing-further/files/json-object-error.png" alt={"A screenshot showing VS Code reading a JSON file with Deno."} lang="en" />

Sometimes, you can’t or don’t want to use the `import` syntax for a JSON file. Instead, you can read it with `readFile()` and the `"utf8"` encoding. However, this gives you a string: the contents of the file as text.

```ts showLineNumbers filename="sda/main.ts"
import { readFile } from "node:fs/promises";

const rawData = await readFile("./data.json", "utf8");
console.log(rawData);
```

<OutdatedScreenshot src="/assets/pushing-further/files/json-raw-data.png" alt={"VS Code logging the JSON file contents as raw text."} lang="en" />

To turn that text back into an array or object, use `JSON.parse()`.

```ts showLineNumbers filename="sda/main.ts" {4} /data/3
import { readFile } from "node:fs/promises";

const rawData = await readFile("./data.json", "utf8");
const data = JSON.parse(rawData);
console.log(data);
```

<OutdatedScreenshot src="/assets/pushing-further/files/json-parsed-data.png" alt={"VS Code logging the array of objects after parsing the JSON text."} lang="en" />

## About `await`

There are two types of functions and methods: **synchronous** and **asynchronous**.

In the [Functions lesson](/pushing-further/functions), we wrote synchronous functions. You didn’t need to add `await` in front of them.

When your computer encounters a **synchronous** function, method, or statement, it **waits** to finish everything required before moving to the next one. It behaves as you’d expect: line 1 of your code gets completed, then line 2, then line 3, and so on.

However, when your computer encounters an **asynchronous** function or method, it starts executing it *in the background* but **doesn’t wait** for it to finish. While the task is running *in the background*, it immediately jumps to the next instruction. The *background* is an oversimplification, but you get the idea.

Since `writeFile` and `readFile` are asynchronous, it means you can write or read multiple files **concurrently**, significantly speeding up your script’s processing time (if used correctly 🧑‍🔬).

This feature is also powerful for web development. For instance, a website with multiple images can fetch all images concurrently instead of one by one, enhancing speed and user experience.

In our context, it’s easier to add the `await` keyword so the computer processes the code in the intended order.

To identify an asynchronous function or method, hover over it. Asynchronous functions return a `Promise`. Type checking can catch many cases where you use a `Promise` as if it were the finished result, but it won’t flag every forgotten `await`. Remember to await an operation before using its result.

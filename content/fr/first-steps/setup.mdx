# Installation

Tout d'abord, installons tout ce dont nous avons besoin.

Vous pourriez avoir besoin de droits administrateur. Si vous êtes sur votre ordinateur de travail et que vous ne les avez pas, demandez l'aide de votre service informatique.

<NoticeIntro lang="fr" />

## Éditeur de code

Le code n'est que du texte. Vous pouvez écrire votre code dans n'importe quel éditeur de texte, mais il est plus pratique d'utiliser un éditeur de code qui offre de nombreuses fonctionnalités utiles.

Vous avez de nombreuses options gratuites et intéressantes, mais la plus populaire est [Visual Studio Code](https://code.visualstudio.com/), et c'est ce que nous allons utiliser. C'est un [projet en code ouvert](https://github.com/microsoft/vscode) maintenu par Microsoft.

Téléchargez-le à partir du [site web](https://code.visualstudio.com/) et installez-le.

Une fois installé, ouvrez-le. Il devrait ressembler à ceci. Ce n'est pas grave si vous avez différents onglets ouverts.  

![Une capture d'écran de l'éditeur de code Visual Studio Code.](/assets/first-steps/setup/vscode.png)

Personnellement, je trouve que l'interface est trop petite et je l'ajuste toujours pour qu'elle soit un peu plus grande lorsque je configure une nouvelle machine. Pour ce faire, cliquez sur le menu `View => Appearance => Zoom In`.

![Une capture d'écran du menu Affichage dans VS Code.](/assets/first-steps/setup/vscode-zoom.png)

## Moteur d'exécution (runtime)

Pour exécuter notre code TypeScript, nous avons besoin d'un moteur d'exécution. Nous utiliserons [Node.js](https://nodejs.org/), un moteur gratuit et en code ouvert qui dispose d'un vaste écosystème d'outils pour travailler avec les données.

Pour ce cours, installez **la dernière version LTS de Node.js**. LTS signifie *Long-Term Support*, soit soutien à long terme. La version LTS convient aux outils et aux librairies de données que nous utiliserons tout au long de ce cours.

Visitez la [page de téléchargement de Node.js](https://nodejs.org/en/download), sélectionnez la dernière version LTS et votre système d'exploitation, puis suivez les instructions d'installation. Sur Windows et Mac, vous pouvez utiliser l'installateur proposé sur cette page. Sur Linux, suivez les instructions pour votre distribution. L'installation doit inclure **npm**, le gestionnaire de paquets que nous utiliserons pour télécharger des outils et des librairies.

Quittez et redémarrez VS Code après l'installation de Node.js. Ouvrez le terminal (`View => Terminal`, ou `CMD` + `J` sur Mac et `CTRL` + `J` sur Windows), puis exécutez ces commandes une à la fois :

```sh
node --version
npm --version
```

La première commande doit afficher la version de Node.js que vous venez d’installer. La deuxième doit afficher un numéro de version de npm. Si l'une des commandes est introuvable, vérifiez que l'installation est terminée, puis redémarrez VS Code.

D'autres moteurs, dont [Bun](https://bun.sh/), peuvent aussi exécuter TypeScript, et `setup-data-project` prend aussi Bun en charge. Nous utiliserons Node.js et npm pour tous les exemples de ce cours.

## Configurer un projet

Nous utiliserons [@nshiab/setup-data-project](https://github.com/nshiab/setup-data-project), un outil en code ouvert que j'ai créé, pour préparer nos projets. Il installe et configure TypeScript, le formatage et les outils de vérification du code. Nous pouvons ainsi passer directement à l'apprentissage du langage.

Créez d'abord un nouveau dossier vide à un endroit facile d'accès sur votre ordinateur. Dans VS Code, cliquez sur l'onglet Explorer, puis sur `Open Folder`, et sélectionnez ce dossier. Si l'éditeur vous demande si vous faites confiance aux auteurs des fichiers, répondez « Oui » pour ce projet que vous venez de créer.

![Une capture d'écran montrant comment ouvrir un nouveau dossier dans VS Code.](/assets/first-steps/setup/deno-open-folder.png)

Ouvrez le terminal (`View => Terminal`, ou `CMD` + `J` sur Mac et `CTRL` + `J` sur Windows). Il devrait s'ouvrir dans votre nouveau dossier. Exécutez :

```sh
npx @nshiab/setup-data-project
```

`npx` télécharge et exécute un outil depuis npm. Si npm vous demande s'il peut installer `@nshiab/setup-data-project`, tapez `y` et appuyez sur Entrée.

Quand l'outil vous demande quelles librairies installer, **ne sélectionnez rien et appuyez sur Entrée**. Nous n'avons pas besoin d'une librairie de données pour apprendre les fondamentaux de TypeScript. Nous en sélectionnerons plus tard, lorsque nous commencerons à analyser des données.

Attendez la fin de la configuration et le message `You are all set!`. Le téléchargement et l'installation des outils peuvent prendre quelques minutes.

<OutdatedScreenshot src="/assets/first-steps/setup/deno-extension.png" alt={"Une capture d'écran montrant comment installer l'extension Deno."} lang="fr" />

Plusieurs fichiers et dossiers apparaîtront dans l'Explorer. Voici ceux à reconnaître pour l'instant :

- `sda/main.ts` est l'endroit où nous écrirons notre code. `sda` est un dossier et `main.ts` est un fichier à l'intérieur. L'extension `.ts` identifie un fichier TypeScript.
- `package.json` décrit le projet, ses dépendances et les commandes que nous exécuterons avec npm.
- `package-lock.json` conserve les versions des paquets installés pour permettre une installation cohérente du projet.
- `node_modules` contient les outils et les librairies téléchargés. Vous n'aurez pas besoin de le modifier.
- `tsconfig.json`, `vite.config.ts` et `.vscode` contiennent les paramètres préparés par l'outil. Gardez-les en place.

Ne vous inquiétez pas si cela semble beaucoup. L'outil a fait la configuration pour nous. La plupart du temps, nous travaillerons dans `sda/main.ts`.

## Paramètres de l'éditeur

Le projet inclut des recommandations d'extensions VS Code. Quand VS Code propose de les installer, acceptez la recommandation du **Vite+ extension pack**, publié par **VoidZero**. Vous pouvez aussi ouvrir l'onglet Extensions et chercher `@recommended`, ou rechercher directement `VoidZero.vite-plus-extension-pack`.

Ce groupe d'extensions fournit le formatage et les vérifications configurés par le projet. Les paramètres VS Code générés activent le formatage à la sauvegarde et le retour à la ligne pour les longues lignes. Vous n'avez pas besoin de configurer un autre formateur.

Si vous aviez installé l'extension Deno, désactivez-la pour cet espace de travail afin qu'elle n'interfère pas avec les outils TypeScript du projet.

## Exécutons un script

Dans l'Explorer, dépliez le dossier `sda` et ouvrez `main.ts`. Remplacez son contenu par :

```ts filename="sda/main.ts"
console.log("This is going to be fun!");
```

Ce code dit à votre ordinateur d'afficher *This is going to be fun!* dans votre terminal.

Enregistrez le fichier avec `CMD` + `S` sur Mac ou `CTRL` + `S` sur Windows. Un point dans l'onglet du fichier indique des modifications non enregistrées. Enregistrez toujours avant de vous attendre à voir vos changements s'exécuter.

Dans le terminal, à partir du dossier du projet qui contient `package.json`, exécutez :

```sh
npm run sda
```

Cela lance la commande `sda` du projet, qui démarre Node.js et exécute `sda/main.ts`. Vous devriez voir *This is going to be fun!* dans votre terminal.

La commande continue de surveiller votre script : chaque fois que vous enregistrez une modification, Node.js l'exécute à nouveau. Essayez de changer le message et d'enregistrer ! Pour arrêter la surveillance, cliquez dans le terminal et appuyez sur `CTRL` + `C`, sur Mac comme sur Windows.

## Vérifier et formater le code

Node.js peut [exécuter directement des fichiers TypeScript](https://nodejs.org/docs/latest-v24.x/api/typescript.html) en supprimant leurs annotations de types avant l'exécution. **Il ne vérifie pas les types.** La surveillance relance simplement le script ; un script peut s'exécuter tout en contenant des erreurs TypeScript.

L'outil de configuration installe et prépare ces vérifications pour nous. VS Code peut signaler les erreurs pendant la saisie, et cette commande vérifie le projet au complet :

```sh
npm run all-tests
```

Elle vérifie le formatage, les règles de qualité du code et les types TypeScript, puis exécute les tests automatisés du projet. Nous apprendrons à écrire des tests plus tard. Pour l'instant, lisez les erreurs signalées et corrigez-les avant de vous fier à vos résultats. Une vérification réussie est utile, mais il faut quand même vérifier vos données et votre logique !

Si `npm run sda` surveille toujours votre script dans le terminal, utilisez le bouton `+` du panneau du terminal pour en ouvrir un deuxième pour les vérifications, ou arrêtez d'abord la surveillance avec `CTRL` + `C`.

Pour formater le projet et appliquer les corrections que les outils peuvent faire automatiquement, exécutez :

```sh
npm run fix
```

Cette commande peut modifier vos fichiers. Vérifiez les changements, puis relancez `npm run all-tests`. Les erreurs dans vos types ou votre logique peuvent nécessiter une correction de votre part.

Pour chaque leçon, vous pouvez continuer à utiliser ce projet et remplacer le contenu de `sda/main.ts`. Si vous préférez un projet distinct, créez un nouveau dossier vide, ouvrez-le avec VS Code et relancez `npx @nshiab/setup-data-project` sans sélectionner de librairie.

## À propos de l'IA

Vous avez peut-être remarqué que nous n'avons pas installé d'outils basés sur l'intelligence artificielle, comme [GitHub Copilot](https://github.com/features/copilot).

Ces outils sont de plus en plus populaires pour les tâches de programmation et peuvent améliorer considérablement la productivité. Cependant, ils ne sont pas sans défauts. Ils peuvent introduire des erreurs et des bogues.

Pour les programmeurs expérimentés, ce n’est pas un gros problème. Quand vous savez ce que vous faites, vous pouvez facilement vérifier et ajuster ce que l'IA vous donne.

Pour les débutants, cependant, il est préférable de s'en passer. Prenez le temps de maîtriser les bases. Avec des fondations solides, vous pourrez alors exploiter pleinement le potentiel de ces outils.

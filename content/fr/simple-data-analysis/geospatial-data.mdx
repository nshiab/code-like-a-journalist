# Analyse géospatiale avec la bibliothèque Simple Data Analysis

Dans cette leçon, nous allons apprendre à utiliser la bibliothèque en code ouvert que j’ai créée : [simple-data-analysis](https://github.com/nshiab/simple-data-analysis). Cette bibliothèque permet de travailler à la fois avec des données tabulaires et géospatiales. Ici, nous allons analyser des feux de forêt au Canada afin de répondre à la question suivante :

- Quelle superficie les feux de forêt ont-ils brûlée dans chaque province canadienne en 2023 ?

Pour cela, nous allons convertir un fichier CSV contenant la latitude et la longitude des feux en géométries, ouvrir un fichier GeoJSON contenant les frontières provinciales et effectuer une jointure spatiale pour déterminer dans quelle province chaque feu s'est produit.

Si vous avez un moment, n’hésitez pas à ajouter un ⭐ à la [page GitHub](https://github.com/nshiab/simple-data-analysis) de la bibliothèque. C’est toujours agréable de savoir que son travail en code ouvert est apprécié. 😊

Notez que vous devriez déjà avoir terminé le **chapitre 1 : Fondamentaux de TypeScript** et le **chapitre 2 : Travailler avec TypeScript**, ainsi que la leçon précédente sur **[Les données tabulaires](/simple-data-analysis/tabular-data)** de ce chapitre.

## Téléchargement et mise en cache des données

### Feux de forêt

Commençons par récupérer les données des feux de forêt canadiens de 2023. 🔥 J’ai téléversé l’ensemble des données sur [GitHub](https://raw.githubusercontent.com/nshiab/simple-data-analysis/main/test/geodata/files/firesCanada2023.csv). Ce fichier CSV provient de Ressources naturelles Canada.

Tout d’abord, nous créons une nouvelle table et utilisons la méthode `loadData` pour charger les données. Ensuite, nous utilisons `log` pour les afficher dans le terminal.


```ts showLineNumbers filename="main.ts" {5-10}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB();

await sdb
  .newTable("fires")
  .loadData(
    "https://raw.githubusercontent.com/nshiab/simple-data-analysis/main/test/geodata/files/firesCanada2023.csv",
  )
  .log();

await sdb.close();
```

![Une capture d'écran montrant les données des feux de forêt canadiens de 2023 dans le terminal VS Code.](/assets/simple-data-analysis/geospatial-data/log-fires.png)

Comme nous pouvons le voir, il y a environ 7 000 feux de forêt. Les valeurs de latitude et de longitude sont stockées dans deux colonnes distinctes. Pour les convertir en géométries nous permettant d’utiliser des méthodes géospatiales, nous pouvons utiliser la méthode `createPoints`.

Cette méthode requiert trois arguments : le nom de la colonne contenant la latitude, le nom de la colonne contenant la longitude et le nom de la nouvelle colonne où seront stockées les géométries, que j’appelle généralement `geom`.


```ts showLineNumbers filename="main.ts" {10}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB();

await sdb
  .newTable("fires")
  .loadData(
    "https://raw.githubusercontent.com/nshiab/simple-data-analysis/main/test/geodata/files/firesCanada2023.csv",
  )
  .createPoints("lat", "lon", "geom")
  .log();

await sdb.close();
```

![Une capture d'écran montrant les feux de forêt canadiens de 2023 sous forme de géométries ponctuelles.](/assets/simple-data-analysis/geospatial-data/log-fires-points.png)

<Callout type="info" emoji="💡">
    Dans la colonne `geom`, vous pouvez voir `EPSG:4326`. Cela indique le système de coordonnées de référence, ou la projection, utilisé pour les géométries. Lorsque vos données utilisent la latitude et la longitude, c'est ce que vous voulez voir. Dans d'autres projets, nous en apprendrons davantage sur les projections et sur la façon de convertir les coordonnées géométriques d'une projection à une autre.
</Callout>

Les données semblent bonnes. Au lieu de les récupérer à chaque exécution, ce serait pratique de les stocker localement sur notre machine. Nous pouvons le faire avec la méthode `cache`.

Nous pouvons aussi activer l'option `cacheVerbose` pour afficher dans le terminal des informations supplémentaires sur le cache, comme le temps économisé grâce à son utilisation.

La première fois que vous exécutez ce code, les données seront récupérées et stockées dans un nouveau dossier appelé `.sda-cache` dans votre projet.

```ts showLineNumbers filename="main.ts" {5-6, 11-12} /{ cacheVerbose: true }/
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB({ cacheVerbose: true });

const fires = sdb.newTable("fires");
await fires.cache(() => {
  fires.loadData(
    "https://raw.githubusercontent.com/nshiab/simple-data-analysis/main/test/geodata/files/firesCanada2023.csv",
  )
    .createPoints("lat", "lon", "geom");
});
await fires.log();

await sdb.close();
```

![Une capture d'écran montrant les données des feux de forêt récupérées et stockées dans le cache.](/assets/simple-data-analysis/geospatial-data/fires-cache.png)

Mais si vous enregistrez de nouveau `main.ts` (`Command` + `S` sur macOS ou `Ctrl` + `S` sur Windows) pour relancer le script, vous verrez que l'exécution suivante charge les données directement depuis `.sda-cache` au lieu de les récupérer sur GitHub. C'est beaucoup plus rapide et cela évite d'envoyer des requêtes inutiles aux serveurs de GitHub chaque fois que le code s'exécute.

### Provinces

Nous allons maintenant nous concentrer sur la récupération des frontières des provinces canadiennes. J’ai téléversé un fichier GeoJSON sur [GitHub](https://raw.githubusercontent.com/nshiab/simple-data-analysis/main/test/geodata/files/CanadianProvincesAndTerritories.json).

GeoJSON est un format largement utilisé pour les données géospatiales. Il est pratique car il s'agit simplement d'un fichier JSON (facile à utiliser en TypeScript) structuré d’une manière spécifique. Il consiste généralement en un objet contenant un tableau de `features`. Chaque entité possède une géométrie (qui contient des coordonnées en latitude et longitude ou équivalentes) et des propriétés (qui stockent des métadonnées).

Par exemple, le fichier GeoJSON des provinces canadiennes est structuré comme ci-dessous, chaque province étant représentée par un objet `feature`. Le champ `geometry` contient les frontières de la province sous forme de `coordinates`, et le champ `properties` inclut des métadonnées telles que le nom de la province en français et en anglais (puisque le Canada est bilingue 🇨🇦).

Il existe différents types de géométries en GeoJSON, comme `Point`, `Polygon` et `MultiPolygon`.

```json
{
  "type": "FeatureCollection",
  "features": [
    {
      "type": "Feature",
      "geometry": {
        "type": "MultiPolygon",
        "coordinates": [
          [
            [
              [-55.424, 51.585],
              [-55.909, 51.629],
              ... // More coordinates
            ]
          ]
        ]
      },
      "properties": {
        "nameEnglish": "Newfoundland and Labrador",
        "nameFrench": "Terre-Neuve-et-Labrador"
      }
    },
    ... // More features
  ]
}
```

Heureusement, nous n'avons pas à manipuler ce genre d'objects avec SDA. La bibliothèque va convertir tout cela en une table de données facile à exploiter ! 😅

Pour récupérer le fichier CSV des feux de forêt, nous avons utilisé `loadData`, mais comme les données des provinces sont dans un format géospatial, nous allons utiliser `loadGeoData` à la place. D’ailleurs, cette méthode peut charger tous types de formats géospatiaux, pas seulement les GeoJSON. 🤓

Pendant que nous y sommes, mettons-les en cache, comme nous l'avons fait avec les données sur les feux.

```ts showLineNumbers filename="main.ts" {14-20}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB({ cacheVerbose: true });

const fires = sdb.newTable("fires");
await fires.cache(() => {
  fires.loadData(
    "https://raw.githubusercontent.com/nshiab/simple-data-analysis/main/test/geodata/files/firesCanada2023.csv",
  )
    .createPoints("lat", "lon", "geom");
});
await fires.log();

const provinces = sdb.newTable("provinces");
await provinces.cache(() => {
  provinces.loadGeoData(
    "https://raw.githubusercontent.com/nshiab/simple-data-analysis/main/test/geodata/files/CanadianProvincesAndTerritories.json",
  );
});
await provinces.log();

await sdb.close();
```

![Une capture d'écran montrant les données des provinces canadiennes dans le terminal VS Code.](/assets/simple-data-analysis/geospatial-data/log-provinces.png)

Comme on peut le voir dans la capture d’écran ci-dessus, chaque entité GeoJSON a été transformée en une ligne dans la table. Les coordonnées des `geometry` sont stockées par défaut dans la colonne `geom`, et toutes les propriétés ont été restructurées sous forme de colonnes. Très pratique !

Grâce à la méthode `cache`, le code sur ma machine s'exécute maintenant en seulement 31 millisecondes au lieu de 517 millisecondes. C'est beaucoup plus rapide et cela évite de solliciter les serveurs de GitHub à chaque exécution. Tout ce temps est économisé en chargeant les données depuis `.sda-cache` plutôt qu'en les récupérant sur Internet, ce qui est vraiment, vraiment, vraiment plus rapide ! Dans d'autres leçons et projets, nous mettrons également en cache les résultats de calculs lourds, ce qui est aussi très utile. ⚡

## Jointure spatiale

Maintenant que nous avons nos feux et nos provinces, nous pouvons effectuer une **jointure spatiale**. Nous allons utiliser la méthode `joinGeo` pour associer chaque feu à la province où il s'est produit.

Aux lignes 22-25, nous appelons la méthode `joinGeo` sur la table `fires`. Nous lui passons les arguments suivants :
- la table `provinces`, afin que chaque feu tente de correspondre à une province,
- la condition `"inside"` (aussi appelée prédicat), pour que chaque feu soit associé à la province dans laquelle il se trouve,
- l’option `outputTable`, qui permet de nommer la table retournée par la jointure `firesInsideProvinces`.

Enfin, nous affichons la nouvelle table à la ligne 26.

```ts showLineNumbers filename="main.ts" {22-26}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB({ cacheVerbose: true });

const fires = sdb.newTable("fires");
await fires.cache(() => {
  fires.loadData(
    "https://raw.githubusercontent.com/nshiab/simple-data-analysis/main/test/geodata/files/firesCanada2023.csv",
  )
    .createPoints("lat", "lon", "geom");
});
await fires.log();

const provinces = sdb.newTable("provinces");
await provinces.cache(() => {
  provinces.loadGeoData(
    "https://raw.githubusercontent.com/nshiab/simple-data-analysis/main/test/geodata/files/CanadianProvincesAndTerritories.json",
  );
});
await provinces.log();

await fires
  .joinGeo(provinces, "inside", {
    outputTable: "firesInsideProvinces",
  })
  .log();

await sdb.close();
```

![Une capture d'écran montrant le résultat de la jointure entre les feux et les provinces.](/assets/simple-data-analysis/geospatial-data/join.png)

<Callout type="info" emoji="💡">
    Si la mise en page de la table semble déformée dans votre terminal, c'est probablement parce que sa largeur dépasse celle de votre terminal. Faites un clic droit sur le terminal et recherchez l'option `Toggle size with content width`. Il existe aussi un raccourci pratique que j’utilise tout le temps : `OPTION` + `Z` sur Mac et `ALT` + `Z` sur PC.
</Callout>

Comme vous pouvez le voir, chaque feu est maintenant associé à une province ! Grâce à la jointure spatiale, nous savons dans quelle province chaque feu s'est produit.

La dernière colonne, `geomProvinces`, contient la géométrie de la province, qui est répétée pour chaque feu correspondant. Avec de grandes tables, ces géométries répétées peuvent rapidement augmenter le temps de traitement et l'utilisation de la mémoire. La méthode `joinGeo` fournit les options `excludeLeftGeometry` et `excludeRightGeometry`, que vous pouvez utiliser indépendamment pour omettre les géométries inutiles et garder les jointures rapides et efficaces en mémoire. Comme toujours, SDA répond à tous vos besoins d'analyse de données tabulaires et géospatiales ! 😎

## Agrégation des données

Nous pouvons maintenant répondre très facilement à notre question :

- Quelle superficie les feux de forêt ont-ils brûlée dans chaque province canadienne en 2023 ?

Nous utilisons la méthode `summarize` sur la table `firesInsideProvinces`.

Nous passons les paramètres suivants à la méthode :
- La colonne `hectares` en tant que valeurs,
- La colonne `nameEnglish` comme catégorie, afin d’obtenir des résultats pour chaque province,
- Pour `stats`, deux nouvelles colonnes : `nbFires` avec le calcul `count` et `burntArea` avec le calcul `sum`,
- L’option `decimals: 0` pour arrondir les valeurs.

```ts showLineNumbers filename="main.ts" {26-32}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB({ cacheVerbose: true });

const fires = sdb.newTable("fires");
await fires.cache(() => {
  fires.loadData(
    "https://raw.githubusercontent.com/nshiab/simple-data-analysis/main/test/geodata/files/firesCanada2023.csv",
  )
    .createPoints("lat", "lon", "geom");
});
await fires.log();

const provinces = sdb.newTable("provinces");
await provinces.cache(() => {
  provinces.loadGeoData(
    "https://raw.githubusercontent.com/nshiab/simple-data-analysis/main/test/geodata/files/CanadianProvincesAndTerritories.json",
  );
});
await provinces.log();

await fires
  .joinGeo(provinces, "inside", {
    outputTable: "firesInsideProvinces",
  })
  .summarize({
    columns: "hectares",
    by: "nameEnglish",
    stats: { nbFires: "count", burntArea: "sum" },
    decimals: 0,
  })
  .log();

await sdb.close();
```

![Une capture d'écran montrant le nombre de feux dans chaque province canadienne.](/assets/simple-data-analysis/geospatial-data/summary.png)

Nous avons maintenant le nombre de feux et la superficie totale brûlée dans chaque province. Bien sûr, il s’agit d’une approximation : certains feux ont peut-être traversé les frontières provinciales, ce que nous n’avons pas pris en compte ici.

Si nous avions les périmètres des feux sous forme de polygones, nous pourrions réaliser une analyse plus précise en utilisant la méthode [`intersection`](https://jsr.io/@nshiab/simple-data-analysis-core/doc/~/SimpleTable.prototype.intersection) pour calculer le chevauchement entre chaque feu et chaque province. Peut-être que nous aborderons cela dans une autre leçon plus tard !

Pour l'instant, trions les lignes par superficie brûlée en ordre décroissant.

Vous pouvez créer des graphiques plus élaborés dans un fichier avec [Plot](https://github.com/observablehq/plot), qui a été installée automatiquement avec SDA par `setup-data-project`, et les enregistrer avec la méthode `writeChart`.

```ts showLineNumbers filename="main.ts" {2, 34-67}
import { barX, plot, textX } from "@observablehq/plot";

const sdb = new SimpleDB({ cacheVerbose: true });

const fires = sdb.newTable("fires");
await fires.cache(() => {
  fires.loadData(
    "https://raw.githubusercontent.com/nshiab/simple-data-analysis/main/test/geodata/files/firesCanada2023.csv",
  )
    .createPoints("lat", "lon", "geom");
});
await fires.log();

const provinces = sdb.newTable("provinces");
await provinces.cache(() => {
  provinces.loadGeoData(
    "https://raw.githubusercontent.com/nshiab/simple-data-analysis/main/test/geodata/files/CanadianProvincesAndTerritories.json",
  );
});
await provinces.log();

await fires
  .joinGeo(provinces, "inside", {
    outputTable: "firesInsideProvinces",
  })
  .summarize({
    columns: "hectares",
    by: "nameEnglish",
    stats: { nbFires: "count", burntArea: "sum" },
    decimals: 0,
  })
  .sort({ burntArea: "desc" })
  .writeChart(
    (data) =>
      plot({
        title: "Burnt area by province (2023)",
        marginLeft: 170,
        grid: true,
        x: { tickFormat: (d) => `${d / 1_000_000}M`, label: "Burnt area (ha)" },
        y: { label: null },
        color: { scheme: "Reds" },
        marks: [
          barX(data, {
            x: "burntArea",
            y: "nameEnglish",
            fill: "burntArea",
            sort: { y: "-x" },
          }),
          textX(data, {
            x: "burntArea",
            y: "nameEnglish",
            textAnchor: "start",
            text: (d) =>
              d
                ? d.burntArea < 1_000_000
                  ? `${Math.round(d.burntArea / 1_000)}k`
                  : `${(d.burntArea / 1_000_000).toFixed(1)}M`
                : "",
            dx: 5,
            fill: "black",
            stroke: "white",
```

### Enregistrement d'une carte

Puisqu'il s'agit de données géospatiales, vous voudrez peut-être créer une carte. Vous pouvez le faire avec Plot et la méthode `writeMap`.

Le code ci-dessous génère une carte affichant les limites des provinces ainsi que les feux de forêt. La taille des marqueurs de feu dépend de la superficie brûlée, et leur couleur correspond à leur cause.

Encore une fois, ne vous inquiétez pas pour la syntaxe. Nous l’expliquerons en détail dans une leçon dédiée à Plot.

```ts showLineNumbers filename="main.ts" {2, 36-79}
import { SimpleDB } from "@nshiab/simple-data-analysis";
import { geo, plot } from "@observablehq/plot";

const sdb = new SimpleDB({ cacheVerbose: true });

const fires = sdb.newTable("fires");
await fires.cache(() => {
  fires.loadData(
    "https://raw.githubusercontent.com/nshiab/simple-data-analysis/main/test/geodata/files/firesCanada2023.csv",
  )
    .createPoints("lat", "lon", "geom");
});
await fires.log();

const provinces = sdb.newTable("provinces");
await provinces.cache(() => {
  provinces.loadGeoData(
    "https://raw.githubusercontent.com/nshiab/simple-data-analysis/main/test/geodata/files/CanadianProvincesAndTerritories.json",
  );
});
await provinces.log();

await fires
  .joinGeo(provinces, "inside", {
    outputTable: "firesInsideProvinces",
  })
  .summarize({
    columns: "hectares",
    by: "nameEnglish",
    stats: { nbFires: "count", burntArea: "sum" },
    decimals: 0,
  })
  .sort({ burntArea: "desc" })
  .log();

await fires
  .clone("firesAndProvinces")
  .insertTables(provinces, { unifyColumns: true })
  .replace("cause", {
    H: "Human",
    N: "Natural",
    U: "Unknown",
  })
  .writeMap(
    (geoData) => {
      const fires = geoData.features.filter((d) =>
        d.properties.hectares !== null
      );
      const provinces = geoData.features.filter((d) =>
        d.properties.hectares === null
      );

      return plot({
        projection: {
          type: "conic-conformal",
          rotate: [100, -60],
          domain: geoData,
        },
        color: {
          legend: true,
        },
        r: { range: [0.5, 25] },
        marks: [
          geo(provinces, {
            stroke: "lightgray",
            fill: "whitesmoke",
          }),
          geo(fires, {
            r: "hectares",
            fill: "cause",
            fillOpacity: 0.25,
            stroke: "cause",
            strokeOpacity: 0.5,
          }),
        ],
      });
    },
    "./sda/output/map.png",
  );

await sdb.close();
```

## Exportation des données

### Données tabulaires

Si vous souhaitez enregistrer une table, vous pouvez utiliser la méthode `writeData`. Cela vous permet d'exporter les données au format CSV, JSON ou Parquet.

Cette méthode est destinée aux données tabulaires, c'est-à-dire aux tables sans géométries. Faites défiler la page pour découvrir comment exporter des fichiers géospatiaux.

```ts showLineNumbers filename="main.ts" {22, 35}
import { SimpleDB } from "@nshiab/simple-data-analysis";

const sdb = new SimpleDB({ cacheVerbose: true });

const fires = sdb.newTable("fires");
await fires.cache(() => {
  fires.loadData(
    "https://raw.githubusercontent.com/nshiab/simple-data-analysis/main/test/geodata/files/firesCanada2023.csv",
  )
    .createPoints("lat", "lon", "geom");
});
await fires.log();

const provinces = sdb.newTable("provinces");
await provinces.cache(() => {
  provinces.loadGeoData(
    "https://raw.githubusercontent.com/nshiab/simple-data-analysis/main/test/geodata/files/CanadianProvincesAndTerritories.json",
  );
});
await provinces.log();

const firesInsideProvinces = await fires
  .joinGeo(provinces, "inside", {
    outputTable: "firesInsideProvinces",
  })
  .summarize({
    columns: "hectares",
    by: "nameEnglish",
    stats: { nbFires: "count", burntArea: "sum" },
    decimals: 0,
  })
  .sort({ burntArea: "desc" })
  .log();

await firesInsideProvinces.writeData("./sda/output/firesInsideProvinces.csv");

await sdb.close();
```

### Données géospatiales

Si nécessaire, nous pouvons également exporter nos tables contenant des géométries en utilisant `writeGeoData`. Cela nous permet de les enregistrer au format GeoJSON, GeoParquet ou Shapefile.

```ts showLineNumbers filename="main.ts" {35-36}

  provinces.loadGeoData(
```

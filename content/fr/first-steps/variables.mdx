# Variables

Commençons votre première leçon de TypeScript avec les variables ! En chemin, je vous montrerai quelques astuces et conseils pour travailler avec TypeScript, VS Code et Node.js.

Notez que je suppose que vous avez terminé la [leçon d'installation](/first-steps/setup) avant de vous lancer dans celle-ci.

<NoticeIntro lang="fr"/>

## Configuration

Créez un nouveau dossier vide sur votre ordinateur, ouvrez-le avec VS Code et créez-y un fichier nommé `main.ts`.

Tapez ce code dans `main.ts` et enregistrez le fichier :

```ts showLineNumbers filename="main.ts"
console.log("Hello!");
```

Ouvrez le terminal (`Command` + `J` sur Mac ou `Control` + `J` sur Windows) et exécutez cette commande :

```sh
node --watch main.ts
```

Cette commande exécute notre code et le relance automatiquement chaque fois que nous enregistrons une modification, pour voir les résultats au fur et à mesure que nous travaillons.

![VS Code montrant console.log("Hello!") dans main.ts et Hello! dans le terminal exécutant node --watch main.ts.](/assets/first-steps/variables/run.png)

<Callout type="info" emoji="💡">
    Vous avez peut-être remarqué que votre code s'affiche avec plusieurs couleurs. Cela s'appelle *code highlighting*. Dans le code, chaque mot a un rôle différent et se voit attribuer une couleur. Par exemple, ici `console` est un objet, et `log` est l'une de ses méthodes. De plus, en tapant, vous pouvez voir des suggestions d'auto-complétion et des infobulles. Cela s'appelle l'*IntelliSense*. C'est votre éditeur qui essaie de deviner ce que vous pourriez vouloir écrire et fournit une documentation. Pour l'instant, vous pouvez ignorer tout cela, mais nous l'utiliserons plus tard.
</Callout>

## Mode surveillance

Voyons comment la surveillance nous aide à travailler.

La commande `node --watch main.ts` démarre déjà Node.js en mode surveillance : il relance automatiquement notre code chaque fois que nous enregistrons une modification. Cela relance le script ; cela ne vérifie pas les types TypeScript.

Si la commande est toujours en cours, laissez-la tourner. Sinon, relancez `node --watch main.ts`. Maintenant, remplacez votre ligne de code par `console.log(2 + 4);` et enregistrez votre fichier (`CMD` + `S` sur Mac ou `CTRL` + `S` sur PC).

Node.js relancera `main.ts` à chaque fois que vous l'enregistrez. Très pratique !

VS Code vérifie les types TypeScript pendant la saisie. Survolez un soulignement rouge pour lire le message d'erreur. Node.js exécute le code sans vérifier les types.

Si vous voulez arrêter la surveillance, cliquez dans le terminal et appuyez sur `CTRL` + `C` (ça devrait être la même chose sur PC et sur Mac). Mais nous garderons la surveillance pour le reste de la leçon.

## Variables avec `const`

Ajoutons maintenant des variables à notre code.

Les variables sont comme des conteneurs. Vous pouvez y mettre des choses, et lorsque vous les référencez, Node.js regardera ce qu'il y a à l'intérieur et l'utilisera. C'est très pratique, car vous pouvez réutiliser la même variable à différents endroits dans votre code.

Modifions notre code pour mettre le premier nombre dans la variable `a` et le deuxième nombre dans `b`. Nous stockerons également le résultat du calcul dans la variable `c`. Copiez le code ci-dessous et collez-le dans votre fichier `main.ts`.

```ts showLineNumbers filename="main.ts"
const a = 2;
const b = 4;
const c = a + b;
console.log(c);
```

<Callout type="info" emoji="💡">
    Avez-vous remarqué tous les points-virgules ? Ils marquent la fin des instructions. Le formateur de VS Code s'occupe de la présentation du code, mais prenez l'habitude de les écrire explicitement dans vos exemples.
</Callout>

Votre ordinateur exécutera ce code de haut en bas. La ligne 1 sera exécutée, puis la ligne 2, et ainsi de suite.

<OutdatedScreenshot src="/assets/first-steps/variables/const-variables.png" alt={"VS Code montrant les variables a, b et c et le résultat 6 dans le terminal."} lang="fr" />

Si vous enregistrez, vous remarquerez que le résultat dans le terminal est le même. Mais il y a une grande différence dans votre code : vous utilisez des variables !

`c` est le résultat de la somme de `a` et `b`, donc si vous changez `a` en `3`, cela changera la valeur dans `c`. Au lieu de `6`, votre ordinateur affichera `7`. Essayez-le !

Si Node.js surveille toujours votre fichier dans le terminal, cela se fait automatiquement lorsque vous enregistrez. Si vous l'avez arrêté, relancez cette commande pour que Node.js réexécute votre code à chaque enregistrement :

```sh
node --watch main.ts
```

Les variables sont omniprésentes dans le code car elles permettent d'abstraire et de réutiliser votre logique.

Nous avons utilisé `a`, `b` et `c` comme noms de variables, mais vous pouvez utiliser n'importe quel nom tant qu'il ne contient pas d'espaces ou de caractères spéciaux. N'oubliez pas que le langage est sensible à la casse.

Par exemple, j'ai mis à jour notre code précédent avec des noms de variables différents. Si vous l'exécutez, le résultat sera le même dans le terminal.

```ts showLineNumbers filename="main.ts"
const banana = 2;
const super_apple = 4;
const POTATO = banana + super_apple;
console.log(POTATO);
```
<Callout type="info" emoji="💡">
    Pour éviter toute confusion dans le code, il est important de nommer les variables de manière réfléchie. Lorsqu'un nom de variable est composé de plusieurs mots, nous utilisons par convention le *camel case*. Cela signifie que le premier mot est en minuscules, suivi des mots suivants avec une majuscule. Par exemple, `first name` deviendrait `firstName`. Différents langages et contextes utilisent différents styles de casse, comme le snake case en Python (`first_name`) ou le délicieux kebab case pour le développement web (`first-name`).
</Callout>

## Variables avec `let`

Il existe deux principales manières de créer des variables :
- Avec `const`, si vous avez l'intention de garder le contenu constant, ce qui devrait être votre premier choix.
- Avec `let`, si vous devez remplacer le contenu.

Essayons de remplacer le contenu dans notre code sans changer `const` en `let`.

Mettez à jour votre code ⚠️ **MAIS NE L'ENREGISTREZ PAS ENCORE** ⚠️ ! Je veux d'abord vous montrer quelque chose.

```ts showLineNumbers filename="main.ts"
const a = 3;
const b = 4;
const c = a + b;
console.log(c);

// Nous voulons mettre 10 dans c et l’afficher.
c = 10;
console.log(c);
```

En tapant, votre éditeur vérifie votre code. Et maintenant, nous voyons du rouge apparaître un peu partout ! Que se passe-t-il ?

Pour le savoir, survolez le `c` souligné par une ligne ondulée.

<OutdatedScreenshot src="/assets/first-steps/variables/const-error-before-save.png" alt={"Une capture d'écran montrant une erreur dans VS Code."} lang="fr" />

Oh ! Cela indique que nous essayons de remplacer le contenu d'une variable constante, ce qui est interdit. Merci, éditeur de code. Je suis content que tu aies détecté cela **avant d'exécuter le code**.

Ce que vous voyez ici est une fonctionnalité très pratique de VS Code et TypeScript. L'erreur a été détectée **avant** que nous n'exécutions le code. Lorsque vous travaillez sur des analyses complexes qui peuvent prendre des secondes, des minutes, ou parfois des heures de calculs, vous serez reconnaissant de détecter les erreurs au préalable au lieu de perdre votre temps à attendre un script qui finira inévitablement par planter.

Maintenant, exécutons ce code, juste par curiosité. Enregistrez le fichier.

Comme prévu, le code plante, et l'erreur s'affiche également dans le terminal.

<OutdatedScreenshot src="/assets/first-steps/variables/const-error.png" alt={"Une capture d'écran montrant une erreur dans le terminal de VS Code."} lang="fr" />

<Callout type="info" emoji="💡">
    Lorsqu'une erreur est générée, Node.js vous indique où se trouve le code problématique. Par exemple, `.../main.ts:7:1` désigne le fichier `main.ts`, à la septième ligne et au premier caractère. La ligne et la colonne exactes peuvent varier selon votre code. Si vous appuyez sur `CMD` sur Mac ou `CTRL` sur PC et cliquez sur ce chemin de fichier, cela vous y mènera directement. C'est très pratique lorsque vous commencez à travailler avec beaucoup de fichiers.
</Callout>

Mais comment corriger cette erreur ?

Si nous voulons remplacer le contenu d'une variable, nous devons remplacer `const` par `let` lors de la création de la variable `c` à la ligne 3.

```ts showLineNumbers filename="main.ts"
const a = 3;
const b = 4;
let c = a + b;
console.log(c);

c = 10;
console.log(c);
```

Maintenant, le code s'exécute sans problème ! Si vous mettez à jour votre code et l'enregistrez, vous verrez la première valeur de `c` s'afficher dans votre terminal, suivie de la deuxième valeur.

Nous pouvons également réutiliser `c` pour le remplacer... par lui-même ! Les deux dernières lignes du code ci-dessous remplacent `c` par `c` au carré (`c` multiplié par lui-même).

```ts showLineNumbers filename="main.ts"
const a = 3;
const b = 4;
let c = a + b;
console.log(c);

c = 10;
console.log(c);

c = c * c;
console.log(c);
```

Le code ci-dessus affiche `7`, puis `10`, puis `100`.

<OutdatedScreenshot src="/assets/first-steps/variables/squared.png" alt={"Une capture d'écran montrant un résultat au carré dans le terminal."} lang="fr" />

## Variables typées

Il y a autre chose à savoir sur les variables : **le type de données est important**. C'est pourquoi cela s'appelle... TypeScript !

Par exemple, si vous survolez `c` maintenant, vous verrez qu'il a un type `number`. Cela est dû au fait que la somme de `a` et `b` est un nombre. Le type ici est **inféré**.

<OutdatedScreenshot src="/assets/first-steps/variables/type-number.png" alt={"Une capture d'écran montrant une variable de type number dans VS Code."} lang="fr" />

Maintenant, remplaçons `c` par du texte à la ligne `6`. En TypeScript, le texte est appelé un `string`, car c'est une chaîne (*string* en anglais) de caractères. Pour que votre ordinateur le reconnaisse comme du texte, il doit être entouré de guillemets.

Mettez à jour votre code ⚠️ **MAIS NE L'ENREGISTREZ PAS ENCORE** ⚠️ ! Désolé, j'ai encore crié. 😬

```ts showLineNumbers filename="main.ts"
const a = 3;
const b = 4;
let c = a + b;
console.log(c);

c = "Hey! What's up?";
console.log(c);

c = c * c;
console.log(c);
```

Nous avons une erreur disant que nous essayons de mettre du texte dans `c`, alors que `c` est censé être un nombre ! Et si l'on y réfléchit, c'est effectivement une erreur.

Si nous remplaçons `c` par du texte à la ligne 6, que se passe-t-il à la ligne 9 ? Quelle serait la valeur au carré de `"Hey! What's up?"` ? Cela n'a aucun sens de multiplier du texte par lui-même !

Encore une fois, l'éditeur a détecté l'erreur **avant d'exécuter le code**. En TypeScript, **les variables sont typées**, ce qui nous aide à écrire du code fiable et robuste.

<OutdatedScreenshot src="/assets/first-steps/variables/type-error-hover.png" alt={"Une capture d'écran montrant une erreur de type dans VS Code lors d'un survol."} lang="fr" />

**Enregistrez maintenant le fichier.** VS Code signale toujours qu'une chaîne de caractères ne peut pas être assignée à une variable de type `number`.

Node.js se comporte différemment : il exécute le code sans vérifier les types. Il affiche `7`, puis le texte, puis `NaN`, car multiplier ce texte par lui-même ne produit pas de nombre. Le script ne plante pas. C'est précisément pourquoi nous utilisons le vérificateur TypeScript en plus de Node.js : un script qui s'exécute peut quand même produire un résultat invalide.

<OutdatedScreenshot src="/assets/first-steps/variables/type-error.png" alt={"Une capture d'écran montrant une erreur de type dans VS Code."} lang="fr" />

## Conclusion

À ce stade, vous pourriez penser : *Pourquoi est-ce si compliqué ? Laisse-moi coder ce que je veux, stupide ordinateur !*

Mais croyez-moi : cela vous évitera de pernicieux bogues. En tant que journaliste computationnel d'expérience, j'ai appris cela à mes dépens. 😅

Utiliser `const` vous empêchera d'écraser accidentellement des variables ou des données importantes, et les types garantiront que vous ne mélangez pas `text`, `number`, `Date`, ou d'autres types de données que nous explorerons dans les prochaines leçons.

Au bout du compte, vous voulez des résultats valides. Vous voulez éviter à tout prix de publier des informations incorrectes. Alors, quand vous pesterez contre les erreurs TypeScript, prenez une grande inspiration et répétez à voix haute : *C'est pour m'aider, ce n'est pas contre moi !*

Bien que cela puisse sembler compliqué pour l'instant, après un peu de pratique, tout deviendra naturel. Faites-moi confiance. 🙂

Et comme je serais un très mauvais enseignant si je vous laissais terminer une leçon sur une erreur, mettons à jour le code une dernière fois, avec des commentaires cette fois-ci.

```ts showLineNumbers filename="main.ts"
// Nous créons des variables constantes.
const a = 3;
const b = 4;

// Nous utilisons let pour pouvoir modifier c plus tard.
let c = a + b;
console.log(c);

// c est typé comme un nombre, donc nous ne pouvons le remplacer que par des nombres.
c = 10;
console.log(c);

// Nous pouvons remplacer c en utilisant c lui-même.
c = c * c;
console.log(c);
```

<Callout type="info" emoji="💡">
    Pour laisser des commentaires dans votre code, utilisez `//` au début de la ligne, comme ci-dessus. Si vous souhaitez commenter plusieurs lignes, encadrez tout avec `/*` au début et `*/` à la fin. Les commentaires sont ignorés par votre ordinateur, ils sont donc un excellent moyen d'expliquer ce que fait votre code ou de désactiver temporairement certaines parties de votre code.

    Si vous ne voulez pas taper les marqueurs de commentaire à la main, placez votre curseur n'importe où sur une ligne ou sélectionnez plusieurs lignes, puis appuyez sur `CMD` + `/` sur Mac ou `CTRL` + `/` sur Windows dans VS Code. Utilisez à nouveau le même raccourci pour les décommenter.
</Callout>

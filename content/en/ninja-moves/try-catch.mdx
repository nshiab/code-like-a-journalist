# Handling errors with `try` and `catch`

Even well-written code can encounter errors. A file might be missing, a website might be unavailable, or data might not have the structure you expected.

By default, an error stops your script. But sometimes, you know how your code should respond. TypeScript's `try` and `catch` keywords let you **catch** an error and decide what to do next.

## Catching an error

The following code tries to read a file that doesn't exist. The path is relative to the project folder where the command runs:

```ts showLineNumbers filename="sda/main.ts"
import { readFile } from "node:fs/promises";

const text = await readFile("./article.txt", "utf8");

console.log(text);
```

When Node can't find `article.txt`, it triggers an error and stops the script.

The `"utf8"` argument asks `readFile` to return text instead of a binary buffer. `node:fs/promises` is built into Node, so there is nothing to install.

We can handle that error with `try` and `catch`:

```ts showLineNumbers filename="sda/main.ts"
import { readFile } from "node:fs/promises";

try {
  const text = await readFile("./article.txt", "utf8");
  console.log(text);
} catch (error) {
  console.log("The file could not be read.");
  console.log(error);
}
```

Node first runs the code inside the `try` block. If the code works, the `catch` block is skipped. If an error occurs, Node stops running the `try` block and moves to `catch`.

The `error` parameter contains information about what went wrong. Logging it can help you understand and fix the problem.

<Callout type="info" emoji="💡">
    Catch only errors that your code can handle meaningfully. Other errors should stop the script so you notice and fix them.
</Callout>

## Returning a fallback value

Sometimes, you only need a fallback value when an asynchronous operation fails. In this example, `stat()` returns information about a file when it exists. If the operation fails, `.catch()` returns `null`:

```ts showLineNumbers filename="sda/main.ts"
import { stat } from "node:fs/promises";

const path = "./article.txt";
const fileInfo = await stat(path).catch(() => null);

if (fileInfo) {
  console.log("The file exists!");
} else {
  console.log("The file information is unavailable.");
}
```

This shorter `.catch()` syntax is useful when you can replace an error with a simple fallback value. In this case, `null` tells the rest of our code that file information could not be read. This also catches errors other than a missing file, such as a permissions problem. Use a `try`/`catch` block and inspect the error if you need to distinguish them.

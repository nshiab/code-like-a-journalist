# Gérer les erreurs avec `try` et `catch`

Même du code bien écrit peut rencontrer des erreurs. Un fichier peut être introuvable, un site Web peut être indisponible ou des données peuvent ne pas avoir la structure attendue.

Par défaut, une erreur arrête votre script. Mais parfois, vous savez comment votre code devrait réagir. Les mots-clés `try` et `catch` de TypeScript vous permettent de **capturer** une erreur et de décider quoi faire ensuite.

<NoticeIntro lang="fr" />

## Configuration

Créez un nouveau dossier, ouvrez-le dans VS Code et utilisez la dernière version LTS de Node.js. Dans le terminal, exécutez `npx @nshiab/setup-data-project` et ne sélectionnez aucune librairie optionnelle. Vous obtenez la même structure et les mêmes outils que dans la [leçon d’installation](/first-steps/setup).

Nous écrirons notre script dans `sda/main.ts`. Exécutez `npm run sda` pour le lancer et le relancer automatiquement lorsque vous sauvegardez vos modifications. Utilisez `npm run all-tests` pour vérifier la mise en forme, les règles de lint, les types et les tests; `npm run fix` peut appliquer les corrections automatiques de mise en forme et de lint.

## Capturer une erreur

Le code suivant essaie de lire un fichier qui n'existe pas. Le chemin est relatif au dossier du projet où la commande s’exécute :

```ts showLineNumbers filename="sda/main.ts"
import { readFile } from "node:fs/promises";

const text = await readFile("./article.txt", "utf8");

console.log(text);
```

Lorsque Node ne trouve pas `article.txt`, il déclenche une erreur et arrête le script.

L’argument `"utf8"` demande à `readFile` de retourner du texte plutôt qu’un tampon binaire. Le module `node:fs/promises` est inclus dans Node : il n’y a rien à installer.

Nous pouvons gérer cette erreur avec `try` et `catch` :

```ts showLineNumbers filename="sda/main.ts"
import { readFile } from "node:fs/promises";

try {
  const text = await readFile("./article.txt", "utf8");
  console.log(text);
} catch (error) {
  console.log("Le fichier n'a pas pu être lu.");
  console.log(error);
}
```

Node exécute d'abord le code à l'intérieur du bloc `try`. Si le code fonctionne, le bloc `catch` est ignoré. Si une erreur survient, Node cesse d'exécuter le bloc `try` et passe à `catch`.

Le paramètre `error` contient de l'information sur ce qui s'est mal passé. L'afficher peut vous aider à comprendre et à corriger le problème.

<Callout type="info" emoji="💡">
    Capturez uniquement les erreurs que votre code peut gérer de manière utile. Les autres erreurs devraient arrêter le script afin que vous puissiez les remarquer et les corriger.
</Callout>

## Retourner une valeur de repli

Parfois, vous avez seulement besoin d'une valeur de repli lorsqu'une opération asynchrone échoue. Dans cet exemple, `stat()` retourne de l'information sur un fichier lorsqu'il existe. Si l’opération échoue, `.catch()` retourne `null` :

```ts showLineNumbers filename="sda/main.ts"
import { stat } from "node:fs/promises";

const path = "./article.txt";
const fileInfo = await stat(path).catch(() => null);

if (fileInfo) {
  console.log("Le fichier existe!");
} else {
  console.log("Les informations sur le fichier sont indisponibles.");
}
```

Cette syntaxe raccourcie avec `.catch()` est utile lorsque vous pouvez remplacer une erreur par une simple valeur de repli. Ici, `null` indique au reste de notre code que les informations sur le fichier n’ont pas pu être lues. Cela capture aussi d’autres erreurs, comme un problème de permissions. Utilisez un bloc `try`/`catch` et examinez l’erreur si vous devez faire la distinction.

# Writing and reading files

When you run your code, everything is kept in your computer’s RAM (Random Access Memory). This type of memory is very fast, but if you stop your script or shut down your computer, everything is lost. 😱

If you want to keep some data around, you need to write it to a file, which will be stored in your computer’s permanent storage (hard drive). And to retrieve the data from a file, you need to read it.

I assume you've completed Chapter 1 and all previous lessons in Chapter 2 before diving into this one. In particular, make sure you've followed the [Setup lesson](/first-steps/setup).

<NoticeIntro />

## Setup

Create a new, empty folder on your computer, open it with VS Code, and create a file named `main.ts` inside it.

Type this code in `main.ts` and save the file:

```ts showLineNumbers filename="main.ts"
// @ts-ignore
console.log("Hello!");
```

Open the terminal (`Command` + `J` on Mac or `Control` + `J` on Windows) and run this command:

```sh
node --watch main.ts
```

This runs our code and automatically runs it again each time we save a change, so we can see the results as we work.

![VS Code showing console.log("Hello!") in main.ts and Hello! in the terminal running node --watch main.ts.](/assets/first-steps/variables/run.png)

In the following code examples, you’ll see the keyword `await`. Don’t worry about it for now. We’ll talk about it at the end of this lesson.

## Writing

With Node.js, writing files is very easy. Import the `writeFile` function from the built-in `node:fs/promises` module. You don’t need to install anything: this module comes with Node.js.

For text files, pass a path as the first parameter and a string as the second parameter. In the code below, we want to create a file named `hello.txt` containing `"Hello!"`.

The `./` makes this a relative path: it points to the folder where we run the script, which is the project folder you opened in VS Code.

Update `main.ts` with this code and save the file.

```ts showLineNumbers filename="main.ts"
// @ts-ignore
import { writeFile } from "node:fs/promises";

await writeFile("./hello.txt", "Hello!");
```

<Callout type="info" emoji="💡">
    You might be wondering what `// @ts-ignore` is doing at the top of the file. It tells VS Code to ignore type errors on the next line. To get proper types for `writeFile`, `readFile`, and the other Node.js functions we’ll use, we need to install Node.js type definitions. We’ll do that in another lesson. For now, I just want you to focus on writing and reading files.
</Callout>

A new text file has been created with text content in it. You now know how to permanently store data on your computer!

By the way, be careful: by default, `writeFile` overwrites files if they already exist.

![VS Code showing writeFile creating hello.txt with the text Hello!.](/assets/pushing-further/files/write-hello.png)

## Reading

To read files, import `readFile` from the same module. Pass a file path and the encoding `"utf8"` to get the contents as a string. `writeFile` uses UTF-8 by default when writing text, so we use the same encoding to read it.

Let’s update `main.ts` to read the file we wrote earlier.

```ts showLineNumbers filename="main.ts"
// @ts-ignore
import { readFile } from "node:fs/promises";

const data = await readFile("./hello.txt", "utf8");
console.log(data);
```

<Callout type="info" emoji="💡">
    Computers store data as bits: zeros and ones. Humans read characters, like letters, digits, and emojis. An encoding is a set of rules for turning those characters into bits and reading them back. UTF-8 is a common encoding that supports characters from many languages.
</Callout>

You’ve successfully retrieved the text content from the `hello.txt` file!

![VS Code showing readFile reading hello.txt with UTF-8 encoding and logging Hello! in the terminal.](/assets/pushing-further/files/read-hello.png)

## JSON

Writing data as text is pretty standard. For example, CSV files are just text files with commas representing columns.

However, when working in TypeScript, especially for the Web, you’ll often write your data as **JSON files**. JSON stands for *JavaScript Object Notation*, and since TypeScript is based on JavaScript, it’s a natural choice. This text file format can store arrays, objects, text, numbers, and booleans, instead of just raw text.

For example, in the script below, we write the array of objects `data` to the file `data.json`. But first, we need to turn it into text with `JSON.stringify()` so it can be written to a text file. Remember, in code, text is usually called a **string**. We store that string in the variable `dataStringified`.


```ts showLineNumbers filename="main.ts"
// @ts-ignore
import { writeFile } from "node:fs/promises";

const data = [
  { name: "Nael", age: 25 },
  { name: "John", age: 30 },
];

const dataStringified = JSON.stringify(data);

await writeFile("data.json", dataStringified);
```
<Callout type="info" emoji="💡">
    `JSON` is a global object: it’s always available in our scripts, so we don’t need to import it.
</Callout>

![VS Code showing JSON.stringify converting data to dataStringified and writeFile saving it to data.json, with the JSON file open beside the script.](/assets/pushing-further/files/write-json.png)

Because it has the `.json` extension, the file is understood by VS Code and Node.js. Its content is displayed with the proper data types. In the editor, the names are highlighted as strings and the ages as numbers. If we wrote everything into a `.txt` file, everything would appear as plain text.

Additionally, Node.js can import a JSON file with the `with { type: "json" }` import attribute. Here, `./data.json` points to the JSON file beside `main.ts` in our project folder.

```ts showLineNumbers filename="main.ts"
import data from "./data.json" with { type: "json" };

console.log(data);
```
![VS Code showing data.json imported with the JSON import attribute and its array of objects logged in the terminal.](/assets/pushing-further/files/import-json.png)

VS Code understands the types of the data imported from our JSON file, which is wonderful! If you add a `.` after `data`, VS Code will suggest array methods because it knows that `data` is an array.

![VS Code suggesting array methods after typing a dot after data imported from data.json.](/assets/pushing-further/files/json-array-autocomplete.png)

If you select the first object of `data` with `[0]` and type a `.` to access a key, VS Code will suggest the keys that are in the object. Since it’s a JSON file, it can infer the types.

![VS Code suggesting age and name after typing data[0]., with age identified as a number.](/assets/pushing-further/files/json-property-autocomplete.png)

And if you try to access keys that don’t exist in the objects, VS Code flags an error. Isn’t that amazing? 😍

![VS Code reporting that city does not exist on the object when accessing data[0].city.](/assets/pushing-further/files/json-missing-property.png)

Sometimes, you can’t or don’t want to use the `import` syntax for a JSON file. Instead, you can read it with `readFile()` and the `"utf8"` encoding. However, this gives you a string: the contents of the file as text.

```ts showLineNumbers filename="main.ts"
// @ts-ignore
import { readFile } from "node:fs/promises";

const rawData = await readFile("./data.json", "utf8");
console.log(rawData);
```

![VS Code showing readFile reading data.json as UTF-8 text and logging rawData in the terminal.](/assets/pushing-further/files/read-json-text.png)

Just as we use `JSON.stringify()` to turn arrays and objects into JSON text, we can use `JSON.parse()` to do the opposite: turn JSON text back into JavaScript values and structures, like arrays and objects.

```ts showLineNumbers filename="main.ts" {5} /data/3
// @ts-ignore
import { readFile } from "node:fs/promises";

const rawData = await readFile("./data.json", "utf8");
const data = JSON.parse(rawData);
console.log(data);
```

![VS Code showing JSON.parse converting rawData back into an array of objects and logging it in the terminal.](/assets/pushing-further/files/parse-json-text.png)

<Callout type="info" emoji="💡">
    One drawback of reading and parsing JSON is that TypeScript no longer infers the structure of the data, so we lose automatic type checks on it. In later lessons, we’ll see how to handle this by checking the parsed values or giving the data an explicit type.
</Callout>

## Let’s talk about `await`

There are two types of functions and methods: **synchronous** and **asynchronous**.

In the [Functions lesson](/pushing-further/functions), we wrote synchronous functions. You didn’t need to add `await` in front of them.

When your computer encounters a **synchronous** function, method, or statement, it **waits** to finish everything required before moving to the next one. It behaves as you’d expect: line 1 of your code gets completed, then line 2, then line 3, and so on.

However, when your computer encounters an **asynchronous** function or method, it starts executing it *in the background* but **doesn’t wait** for it to finish. While the task is running *in the background*, it immediately jumps to the next instruction. The *background* is an oversimplification, but you get the idea.

Since `writeFile` and `readFile` are asynchronous, it means you can write or read multiple files **concurrently**, significantly speeding up your script’s processing time (if used correctly 🧑‍🔬).

This feature is also powerful for web development. For instance, a website with multiple images can fetch all images concurrently instead of one by one, enhancing speed and user experience.

In our context, it’s easier to add the `await` keyword so the computer processes the code in the intended order.

Another thing to know: asynchronous functions return a `Promise`. We’ll dive into that in the next lessons.
